## 1. scene11 ① `metal_rust` — **"파라미터 미전달/역작동" 가설은 둘 다 기각**

담당 지시는 "스케일 파라미터가 실제 `make_pbr` 호출에 전달되는지 추적, 역작동
의심"이었다. **둘 다 아니었다.** 순서대로 확정한다.

### 1-1. 전달 경로 추적 : 정상

```
PARAMS.material.scale.metal_rust = 0.25
  → setup_materials():  s = mp["scale"]
  → PBR(".../Metal", diff, nor, rough, s["metal_rust"], tint=...)
  → PBR(path,*a,**kw) = sc.make_pbr(stage, path, *a, **kw)
  → make_pbr(stage, path, diff, nor, rough, scale_m=0.25, ...)   ← 6번째 위치인자
```
`scene_common.make_pbr:346` 에서 `s = 1.0/scale_m = 4.0` 이 `texture_scale` 로 기록된다.

### 1-2. 방향 검산 : 정상(역작동 아님)

`OmniPBR.mdl` → `OmniPBR_ClearCoat.mdl:540-546`

```
base::transform_coordinate(
    transform: rotation_translation_scale(scaling: float3(texture_scale.x, texture_scale.y, 1)),
    coordinate: coordinate_projection(world, cubic))
```
좌표에 `texture_scale` 을 **곱한다** = 값이 클수록 반복↑ = 무늬 축소.
파라미터 주석도 `display_name("Texture Tiling") / "Controls the repetition"`.
즉 `scale_m`(타일 크기 m) 을 줄이면 무늬가 작아진다 — W-1 의 1.0 → 0.25 는
**의도대로의 방향**이다.

### 1-3. 렌더 픽셀 실측 : 축소가 실제로 일어났다

`look_check/scene11/{v6,v7}_rt/rt_noon_midlanding.png` 동일 좌표 패치
(x 40‥440, y 620‥900 = 참 상면 양광부)의 수평 자기상관 반폭:

| | v6(scale 1.0) | v7(scale 0.25) |
|---|---|---|
| 자기상관 반폭 | **20 px** | **10 px** |
| 패치 표준편차 | 33.2 | **34.7 (변화 없음)** |

**무늬 크기는 2× 줄었는데 명암 표준편차는 그대로다.** 여기서 진짜 원인이 드러난다.

### 1-4. 진짜 원인 : 대비 + 틴트가 만든 색분리

`assets/scene01/metal_rust_diff.jpg` (4096²) 휘도 분포 = sRGB p5 **29** / p50 56 /
p95 **130** → 선형 환산 **0.0116 ‥ 0.216 = 18.6 : 1**.
**틴트는 곱셈이라 이 비를 못 줄인다.** 게다가 채널 등화 틴트 (0.61, 0.80, 1.00) 은
*평균만* 중성화하고 화소 단위로는 오히려 색을 **갈라놓는다**:

| 분위 | R | G | B | 읽히는 색 |
|---|---|---|---|---|
| p5 (녹 짙은 화소) | 31.7 | 19.2 | 11.0 | **적갈** |
| p95 (소지 노출 화소) | 80.5 | 104.8 | 127.0 | **청백** |

판정 §6-1 의 "**백·갈 고대비 얼룩(표범/위장 무늬)**" 은 정확히 이 두 극단이다.
**스케일을 더 줄였어도 같은 판정이 나왔을 것**이고, 실제로 v7 에서 그렇게 됐다.

> 교훈(감독 §15-1 에 추가 제안) — "채널 등화 틴트"는 **평균 색만** 고치는 도구다.
> 텍스처의 명암 레인지·채도 분산이 문제일 때는 틴트로는 원리적으로 해결되지 않는다.

### 2-2. ② 원경 수목 띠 — "초록 슬래브 벽" 해소 (판정 ㉡)

원인은 형상이다. 구 `build_treeband` 는 세그(7.5 m)당
**속 찬 박스 1개(폭 4 m × 높이 4.4~4.8) + 그 위 작은 블롭 1개** 였다.
박스가 실루엣 상단을 만들고 그 상면이 평평하니 **도색 방음벽**이 된다.

| 항목 | 구 | 신 |
|---|---|---|
| 구조 | 박스가 실루엣 담당 | **박스는 덤불층(h·0.36)만** — 실루엣은 수관 블롭이 담당 |
| 세그 | 7.5 m | **5.0 m**(행당 23세그) |
| 세그당 블롭 | 1 | **3** (y 로 겹치게 배치, ±0.7 지터) |
| 블롭 높이 | 고정 | **h × 0.72~1.16** → 상단선 톱니 |
| x 지터 | ±0.8(박스만) | 블롭 **±1.2** → 전후 깊이 |
| 재질 | `leaf_a/leaf_b`(근경 진초록) | **`leaf_far_a/b/c` 신설** — 대기원근 저채도 회록 3종 순환, sRGB (76,89,70)/(66,79,61)/(86,96,79) |
| 프림 | 박스 30 + 블롭 30 | 박스 **46** + 블롭 **138** |

기하 검산(스크래치, 결정적 지터 재현):
* **부유 블롭 0** — 블롭 하단 `gz + hj·0.20` ≤ 덤불 상면 `gz + h·0.36`
  (hj ≤ 1.16 h 이므로 0.232 h < 0.36 h, 항상 성립).
* 수관 상단 z **2.51 ~ 6.82**(표준편차 0.91 m) — 구는 사실상 단일 높이의 평면.
* 블롭 x 확산 **|x| 43.4 ~ 49.5** → 식재대 바깥 경계 42.4 · 가로수 열 41.2 **무침범**.
* 수관 반경을 높이가 아니라 **띠 폭 기준**(rx = 2.0×U(0.55,0.95))으로 잡은 이유가
  이것이다 — 높이 기준으로 하면 높은 개체가 x 로 3.7 m 까지 번져 가로수를 먹는다.
* `_solid_at` 의 수목 띠 봉투도 **보수적으로 확장**(z 상한 (h+jitter)×1.21 = 7.10 ≥
  실제 최대 6.82, x ±3.2) — 차단 판정이 실제보다 작아지지 않게.

### 2-3. ③ `under_grating` 재조준 — **재실패 원인 확정 후 재조준** (판정 ㉢)

## 3. scene17 ① 갈색 매스 — **정체는 `Fill` 도 `Deck` 도 아닌 `Ramp/Apron`**

판정 §11-1 은 "재질 교체가 이 매스에 적용되지 않았거나, 매스의 정체가 `Fill` 이
아닌 석축/노면 측면"이라고 두 가설을 제시했다. **후자가 맞고, 정확히는 진입
apron 이다.** 확정 절차:

### 3-1. 역투영으로 프림 특정

`levee_walk`(eye −1.5, −14.0, 1.50 → tgt −1.3, 6.0, 0.90) 카메라로 램프 그룹 프림의
꼭짓점을 화면 좌표로 투영해 v7 렌더 위에 겹쳐 그렸다.

* `Deck` 상면/저면 모서리(초록/시안) → 프레임 **상단 아주 좁은 띠**. 매스 아님.
* `Fill` 접지선(마젠타) → 실제 렌더에서 **잔디로 렌더됨**(W-5 수정은 반영돼 있다).
* **`Apron` 강측면(적색) → 프레임의 갈색 수직벽과 정확히 일치.**

### 3-2. 원인 = rot_group 안에서의 로컬/월드 축 혼동

```
build_rot_group(ROOT/Ramp, pivot (0,4), yaw = acos(6.4/40) = 80.7931°)
BOX(grp/Apron, center=(px − 1.4/2, …), size=(1.4, 4.3, 2.8))     ← 로컬 좌표
```
`apron_back` 을 "로컬 −X = 램프 뒤 = **마루 안쪽**"이라고 가정했는데,
yaw 80.79° 에서 로컬 −X 는 월드 −X 가 아니라 **거의 월드 −Y** 다(cos 0.16).
회전 후 월드 꼭짓점은

```
(2.84, 2.12)  (−1.41, 2.81)  (3.06, 3.50)  (−1.18, 4.19)
```

**월드 x 가 +3.06 까지 사면 위로 돌아나간다.** 그 지점 사면 상면은 −1.403 인데
apron 상면은 −0.015 → **사면 위로 1.39 m 솟은 두께 2.8 m 콘크리트 블록**.
"평평한 상면 + 수직 절단면의 갈색 덩어리"라는 v6·v7 묘사와 정확히 일치한다.

### 3-3. 색의 절반은 재질

`concrete_floor_diff` 평균 sRGB **(115.7, 102.2, 77.0)** = 난색 갈토. 구 틴트
(0.80, 0.79, 0.76) 은 채널비를 그대로 두므로 렌더 결과가 sRGB **(98, 87, 69)**.
램프 노면·연석·마루 끝 연석·계단 20단이 전부 이 재질이다.
(scene06/11 에서 W-1 이 이미 같은 진단을 내렸는데 17 에는 이식되지 않았다.)

## 4. scene17 조치

### 4-1. `Ramp/Apron` **빌드 제거** (판정 ㉠)

기능적으로도 불필요하다는 것을 스모크로 확정했다:

* 진입 참이 메워야 할 단차는 **마루 끝(x 0) ↔ 램프 상류 시단(x 0.59)** 사이
  **0.152 m 문턱** 뿐이다(스모크 `[사선 램프 배치]` s0.0 절토 +0.152).
  이는 계단 riser 0.16 보다 낮은 시공 이음이라 별도 프림이 필요 없다.
* 마루 슬래브(levee x −24…0, 상면 0.000, 두께 3.6)와 자전거도로(x −3…0,
  상면 +0.004)가 마루 끝까지 이미 채우고 있다.
* 램프 노면 강측 노출은 종전대로 `Fill`(잔디) + `Batter`(잔디)가 덮는다.

`PARAMS["ramp"]["apron"]` 은 **v5.2 규약(scene05 스피커 선례)대로 이력 보존용
잔존** + `build=False` 게이트. 스모크에 구 풋프린트 재현 계산을 남겨,
누가 되살리면 즉시 드러나게 했다:

```
[진입 apron 풋프린트 — v7 판정 ⑪-1 갈색 매스]
  구(rot_group 내부, 두께 2.80): 월드 꼭짓점 [(2.84,2.12),(-1.41,2.81),(3.06,3.5),(-1.18,4.19)]
    → 월드 x 최대 +3.06 (사면 상면 -1.40) = 사면 위 +1.39 m 돌출 → 갈색 블록의 정체
  신: 빌드 생략(build=False) — 마루 끝(x 0) ~ 램프 상류 시단(x 0.59) 문턱 0.152 m
      < 계단 riser 0.16 → OK (별도 프림 불요)
  프레임 갈색 매스 잔존 가능 프림: 없음 → OK
```

### 4-2. `conc_tint` 채널 등화 (판정 ㉠ 색 성분)

`(0.80, 0.79, 0.76)` → **`(0.53, 0.66, 1.00)`**.
선형 채널평균 (0.1535, 0.1202, 0.0772) 을 최저 채널(B) 기준으로 눌러
렌더 sRGB **(98, 87, 69) → (80, 79, 78) = 중성 회색 콘크리트**.
(scene06/11 W-1 규약과 동일한 방식. 최대 채널을 1.00 으로 고정해 밝기 상승 없음.)
적용 대상: 램프 노면·연석·apron(미빌드)·마루 끝 연석·계단 20단(`hard_mtl`).
**아파트(`shell_*`)는 손대지 않았다** — 판정 ㉢ 소관이자 담당 지시 밖.

### 4-3. 배터 = "인공 계단 3단" 해소 (판정 ㉠ 후반)

판정 권고 "연속 사면(단 높이 ≤ 0.15 m)" 을 그대로 반영. **폭·낙차 총량은 불변**
이라 스모크의 매몰·풋프린트 수치가 전부 그대로다(= 회귀 0).

| 항목 | 구 | 신 |
|---|---|---|
| 단수 × 폭 × 낙차 | 3 × 0.50 × 0.42 | **9 × 0.1667 × 0.14** |
| 합계 | 폭 1.50 · 낙차 1.26 | **폭 1.50 · 낙차 1.26 (동일)** |
| 구배 | 84 % ≈ 1:1.19 | **동일** |
| 재질 | `grass`/`grass_b` **교대** | **`grass_b` 단일** — 교대가 단 경계를 줄무늬로 도드라지게 했다 |
| 풋프린트 | x ≤ 11.04 < 산책로 11.5 | **동일** |

### 4-4. 건너편 억새 "등간격 구슬 목걸이" 해소 (판정 ㉡)

구 구현은 **1열 · 균등분할 y(spacing 1.55 고정) + ±0.3 지터** 라 등간격이 남았다.

| 항목 | 구 | 신 |
|---|---|---|
| 열 | 1열 (cx 76.0 ± 0.35) | **3열** `rows=(dx, size_k, phase)` = (−1.15, 1.18, 0.00) / (0.00, 1.00, 0.37) / (+1.25, 0.82, 0.68) — 뒷열 크고 앞열 작게 = 깊이 |
| y 전진 | `length·k/n` 균등 | **랜덤 보행** `spacing × U(0.55, 1.60)` |
| 크기 지터 | ×0.8~1.2 | **×0.60~1.45** (판정 권고 대역) |
| 높이 지터 | ×0.82~1.12 | **×0.70~1.25** |
| 블롭 수 | 54 | **142** |
| 실측 간격 | 1.55 고정 | **0.87 ~ 2.48 m** (스모크가 출력·검증) |

접지 규약 유지(중심 z = z_top + hh·0.42, rz = hh·0.60 → 하단이 지면 아래 0.18 hh)
= **부유 0**. 밴드 x 확산 **73.7 ~ 78.4** ⊂ far_bank [72, 100], 아파트 최소
후퇴 x0 85.5 와 **7 m 이격** — 카메라 14컷 전부 x ≤ 14 이므로 침입 0.

## 6. 감독께 — 이번 라운드에서 나온 일반 교훈 2건

1. **"채널 등화 틴트"의 한계를 규약에 명시할 것.**
   틴트는 곱셈이라 **평균 색만** 바꾼다. 텍스처의 명암 레인지(11 `metal_rust`
   선형 18.6:1)나 채도 분산이 원인이면 틴트로는 원리적으로 못 고치고,
   오히려 극단값의 색분리를 키운다(백↔갈). 이럴 때는 OmniPBR 의
   `albedo_add / albedo_brightness / albedo_desaturation` 로 **레인지 자체**를
   압축해야 한다. `scene_common.make_pbr` 에 이 3입력을 정식으로 노출하면
   §15-2 "이끼 바위" 실패 모드(04·05·13·15)에도 그대로 쓸 수 있다 —
   씬 파일마다 `PBR_ALBEDO` 를 복제하는 것보다 낫다. **별건 승인 요청.**
2. **`build_rot_group` 하위 프림은 로컬/월드 축을 반드시 재투영해서 검산할 것.**
   17 `Apron` 은 "로컬 −X = 마루 안쪽"이라는 **주석까지 달린 오해**가 두 라운드를
   버텼다. yaw 80.79° 에서 로컬 −X 는 월드 −Y 에 가깝다. 회전 그룹 안에
   새 프림을 넣을 때는 **꼭짓점 4개를 월드로 찍어 지반고와 비교**하는 한 줄
   검산을 스모크에 넣는 것을 표준으로 제안한다(이번에 17 에 넣어 뒀다).
