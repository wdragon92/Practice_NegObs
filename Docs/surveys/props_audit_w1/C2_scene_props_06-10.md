## 1. 판정 어휘 · 근거 태그 · 측정 프로토콜

### 판정 어휘 (지시서 규정)
| 판정 | 뜻 |
|---|---|
| 유지 | 실물 근거·치수 모두 통과. 손대지 않는다 |
| 치수교정 | 형태는 맞고 숫자만 틀림. PARAMS 값 교체로 끝난다 |
| 형태재작 | 부재 구성이 실물과 다름. 빌더를 다시 쓴다 |
| 제거 | 실물 근거 없음 또는 규약 위반. 삭제한다 |
| 신규필요 | 실물에 반드시 있는데 씬에 없다 |

### 작위성 등급
| 등급 | 정의 | 판정 근거 |
|---|---|---|
| **A** | 실물 참조 없는 창작 형태, 또는 상수색 무디테일 덩어리 | 코드에 근거 주석 없음 + 렌더 `flat%` ≥ 70 |
| **B** | 실물은 존재하나 치수·부재 구성이 어긋남 | 법정/KS 치수와 대조해 오차 산출 |
| **C** | 실물에 근접. 잔여 오차만 있음 | — |

### 우선순위 = h0.3 프레임 점유율 × 작위성
`P1` ≥ 10 %×A · `P2` 3~10 %×A 또는 ≥10 %×B · `P3` 1~3 %×A 또는 3~10 %×B · `P4` 그 외.

### 측정 프로토콜
- 프림 구성·치수는 **코드 실측**(PARAMS 값 + 빌더 본문 산술). 렌더 추정 없음.
- 프레임 점유율·평탄도는 `numpy+PIL` 로 PNG 를 직접 읽어 계산.
  `flat%` = 3×3 국소표준편차 < 1/255 픽셀 비율(= 결이 전혀 없는 죽은 면).
  측정 로그 전문은 §부록 A.
- 법정 치수는 `Docs/surveys/_dimension_index.md` 를 1차 출처로 삼고, 없는 항목만 웹 조사.

### 근거 태그
`[법령]` 대한민국 법령·고시 · `[KS]` 한국산업표준 · `[지침]` 행정 지침·가이드라인 ·
`[문헌]` 학술·백과 · `[실측]` 이번 감사에서 코드/픽셀을 직접 측정 · `[추정]` 근거 미확보

## 2. 횡단 결함 — 5씬 공통 코드에서 나온 것

소품 표를 씬별로 쓰기 전에, **개별 씬 수정으로는 못 고치는 것**부터 분리한다.
아래 8건은 `scene_common.py` 한 곳을 고치면 5씬(그리고 나머지 28씬)이 같이 고쳐진다.

### X-1 [P0 · 규약 정면 위반] 나무의 62.5 %가 만개한 벚나무다

```
scene_common.py:1695
VEG_TREES = [
    ("Trees/Japanese_Cherry.usd", 4.64, 5),   # 벚나무   ← 가중치 5
    ("Trees/White_Pine.usd",      2.35, 2),
    ("Trees/Yellow_Pine.usd",    26.99, 1),
]
scene_common.py:1919   pool = [t for t in VEG_TREES for _ in range(t[2])]
```
가중치 합 8 중 벚나무 5 → **개체당 선택 확률 62.5 %** [실측].
`build_tree()` 는 좌표 해시로 이 풀에서 뽑으므로, `NEGOBS_LOOK_V1=1` 이면
**내 담당 5씬의 나무 전량**(06: 20주, 07: 15주, 09: 18주, 10: 24주)이 이 확률을 탄다.

규약은 "수종명이 아니라 **잎 텍스처 픽셀을 직접 열어 판정**"이라 했으므로 그렇게 했다:

|---|---|---|---|---|
| `Trees/materials/textures/cherryblossom.png` | (232.9, 125.9, 164.2) | **92.0 %** | 0.0 % | **만개 벚꽃** [실측] |
| `Shrub/.../rhododendron_basecolor.png` | (163.4, 107.6, 158.3) | **77.3 %** | 15.8 % | **만개 철쭉** [실측] |
| `Shrub/.../forsythiaflower_basecolor.png` | (202.8, 179.7, 54.2) | 0 % (노랑 100 %) | 0.0 % | **만개 개나리** [실측] |
| `Shrub/.../burningbush_leaf_basecolor.png` | (166.7, 117.6, 109.5) | 39.3 %(적 36.3 %) | 26.3 % | **화살나무 단풍** [실측] |
| `Shrub/.../hollyprivet_basecolor.png` | (56.9, 87.8, 25.8) | 0 % | **100 %** | 상록 — 계절 중립 ✔ |
| `Trees/materials/textures/pine_needles.png` | (117.5, 126.2, 56.6) | 0 % | 77.3 % | 침엽 — 계절 중립 ✔ |

**경험적 확증**: `look_check/scene10/veg_test/pt_noon_preset_h1.8_d10.png`
(2026-07-28 23:38 렌더) — 프레임의 **5.91 %가 벚꽃 분홍 픽셀**이고 화면 우반이 통째로
만개 벚나무다 [실측]. v8_pt/r2_on 렌더가 아직 블롭 나무인 것은 그 렌더들이 에셋 통합
이전이기 때문이고, **현행 코드로 다시 렌더하면 5씬 전부 벚꽃이 핀다.**

**코드가 스스로 밝힌 근거가 규약이 배척한 바로 그 논법이다.** `scene_common.py:1693`
주석은 "**벚나무가 한국 가로수 최다 수종 중 하나라 주력**"이라고 가중치 5 를 정당화한다.
그런데 규약은 "**수종명이 아니라 잎 텍스처 픽셀을 직접 열어 판정**"하라고 못박았다.
픽셀은 분홍 92 % — 이 에셋에는 **개엽기 녹엽 텍스처가 아예 없고 만개 화판 하나뿐**이다.
즉 쟁점은 "벚나무를 심어도 되는가"가 아니라 **"이 에셋은 4월 첫 주 외의 어떤 날짜로도
렌더할 수 없다"** 는 것이다. 수종 빈도 논거로는 이 사실을 뒤집을 수 없다.

**조치(에셋팀 인계)**
```python
VEG_TREES = [("Trees/White_Pine.usd", 2.35, 3), ("Trees/Yellow_Pine.usd", 26.99, 2)]
SHRUB_ORNAMENT = ["Shrub/Juniper.usd", "Shrub/Privet.usd", "Shrub/Boxwood.usd"]
```
(벚나무를 굳이 살리려면 **녹엽 텍스처를 별도 조달해 `cherryblossom.png` 를 교체**하는
길뿐이다. 텍스처 교체 없이 가중치만 낮추는 것은 확률만 줄일 뿐 위반은 남는다.)
`SHRUB_ORNAMENT` 는 현재 4종 중 **3종이 계절 특정**(철쭉·개나리·화살나무)이고,
정작 계절 중립인 `Privet`·`Boxwood` 가 풀에서 빠져 있다 — `SHRUB_HEDGE` 에만 들어 있다.
`build_planter()`(scene08 화단 8개소)가 이 풀을 쓴다.

### X-2 [P1] 안내 사인이 전부 "청색 도로표지 스타일" 창작판이다
