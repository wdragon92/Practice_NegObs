## §1 현행 산포 실측

### 1-a 코드가 실제로 만드는 것

`sceneC2_leaf_stairs.py:559-570` — 유일한 `scatter_debris` 호출:

```python
got = sc.scatter_debris(
    stage, f"{ROOT}/Leaves",
    x_lo, -ls["y_near"], x_hi_near, ls["y_near"], 0.0,     # x −4.20 … 6.26,  |y| ≤ 2.20
    cover=ls.get("cover", 0.55), seed=ls["seed"],
    pool=[p for p in sc.VEG_DEBRIS if "fallcluster" in p[0]],
    ground_fn=lambda x, y: surface_z(x, y) + ls["lift"],
    edge_bias=0.0, max_count=int(ls.get("max_count", 900)),
    tilt_max=10.0)
```

| 항목 | 값 | 근거 |
|---|---|---|
| `RUN = TREAD×NSTEP` | 0.34 × 14 = **4.76 m** | `[코드]` |
| 3D 산포 rect | x −4.20 … RUN+1.50 = **6.26**, \|y\| ≤ **2.20** | `[코드]` |
| 3D 산포 면적 | 10.46 × 4.40 = **46.02 m²** | `[계산]` |
| 풀 | `fallcluster1`(0.0628 m² / 9,175 tri) + `fallcluster2`(0.0242 / 2,980) | `[실측 — asset_audit §4·§4-b]` |
| `mean_cov` | 0.04350 | `[계산]` |
| n | 46.02 × (−ln 0.45) / 0.04350 = **845** | `[계산]` |
| 실추첨 | fc1 437 + fc2 408 → **5,225,315 삼각형** | `[실측 — asset_audit §4-b, 레드팀 R5 와 일치]` |
| 고유 데이터(인스턴싱 ON) | 9,175 + 2,980 = **12,155 삼각형** | `[계산]` |

역산식 `n = A·(−ln(1−cover))/mean_cov` 는 레드팀이 이미 **반증 실패** 판정한 검증된 식이다
(`redteam_verification_v1.md` §4-4). 본 보고서도 이 식만 쓴다.

### 1-b "전체 낙엽 영역 86.1 m²" 의 정체 — **텍스처 판이 아니다**

임무 배경문의 *"3D 는 근경 밴드 46.02 m² 뿐, 나머지는 텍스처"* 는 **부정확하다.**
86.11 m² 는 `x −4.20…RUN+3.00=7.76, |y| ≤ 3.60` 로, **룩v1 이 꺼졌을 때만 도는 레거시
납작 타원체 경로**의 rect 다(`sceneC2_leaf_stairs.py:576-591`). 룩v1 이 켜지면 `return` 으로
죽는다 — 즉 **현재 렌더에 86.11 m² 짜리 낙엽 면은 존재하지 않는다.**

실제 `leaf_ground` 텍스처(`M["leafbed"]`)가 붙는 프림은 **매몰 마운드 3매 + 드리프트 2매뿐**이다
(`:486-505`, `PARAMS["mound"]` / `["drift_geo"]`):

| 프림 | 평면 범위 | 평면적 |
|---|---|---|
| `LeafMound_A` | x −3.20…−0.10, \|y\| ≤ 2.40 | 14.88 m² |
| `LeafMound_B` | x −0.25…1.02, \|y\| ≤ 1.33 | 3.38 m² |
| `LeafMound_C` | x 1.02…2.38, \|y\| ≤ 0.90 | 2.45 m² |
| `LeafDrift_N/S` | x −3.40…−0.10, \|y\| 1.40…2.50 | 7.26 m² |
| **합(총/중복제거)** | | **27.97 / 21.77 m²** `[계산]` |

그리고 **이 21.77 m² 는 거의 전부가 3D 밴드(46.02 m²) 안에 있다.** 밖으로 새는 것은
마운드 A 의 \|y\| 2.20→2.40 프린지 0.20 m 와 드리프트의 2.20→2.50 프린지 0.30 m 뿐이다 `[계산]`.

⇒ **텍스처는 "원경 대역"이 아니라 "3D 아래 하지층"이다.** 하이브리드 정당화문
(*"원경은 텍스처로 두고 카메라가 낱장을 분해하는 구간만 실물로"* — 커밋 `18c8643`)은
**구현과 일치하지 않는다.** 원경에는 낙엽이 아무것도 없다(맨 흙길·잔디). 이것이 §2-c 의
`d10` 실패로 직결된다.

## §3 전역화 예산 재산정

### 3-a 풀 선택 — "낱장을 섞어 개당 비용을 낮춘다"는 **틀렸다**

`asset_audit_v1.md` §4-b 가 남긴 선택지 (b) 를 검증했다. **고정 피복률**에서 총 삼각형은
`A·(−ln(1−cover)) × (tri/cov)` 이므로, 지배 인자는 **에셋별 "피복 1 m² 당 삼각형"** 이다:

| 에셋 | 유효피복 m² | 삼각형 | **삼각형 / 피복 m²** |
|---|---|---|---|
| `fallcluster1` | 0.0628 | 9,175 | 146,100 |
| `fallcluster2` | 0.0242 | 2,980 | **123,140** |
| `maplefall1` | 0.0051 | 631 | 123,725 |
| `oakfall1` | 0.0030 | 496 | 165,333 |
| `oakfall2` | 0.0038 | 582 | 153,158 |

`[실측 — asset_audit §4·§4-b, oakfall2 는 R8 정정본]`

전역 86.11 m² · cover 0.55 에서:

| 풀 | n | 논리 삼각형 |
|---|---|---|
| fallcluster 2종 | 1,581 | **9.61 M** |
| 5종 전체 | 3,476 | **9.64 M** |
| 낱장 3종만 | 17,335 | **9.88 M** |

⇒ 개수는 11배 차이나는데 **삼각형은 ±3 % 안에서 같다**. 낱장을 섞으면 개당 비용은 내려가지만
개수가 정확히 그만큼 올라간다. **선택지 (b) 는 예산 절감 수단이 아니다** — 폐기한다.
남는 것은 (a) `cover` 하향과 (c) 인스턴싱뿐이고, (c) 는 이미 복구됐다.
**최적 풀은 `fallcluster` 2종 유지**(개수 최소 = TLAS·빌드 시간 최소). 필요하면
`fallcluster2` 단독이 −12 % 로 가장 싸지만(8.47 M) 개수가 2,838로 늘어 실익이 없다 `[계산]`.

### GRAZE v2 신판 예상 — **전역화는 GRAZE 를 개선한다. 현행이 위험하다.**

GRAZE v2 로 `balust → leaf3d` 를 재실행했다 `[실측]`.
v2 는 카메라 기하로 **낙차 에지 대역 E**(지면거리 0.7·d ~ 2.2·d 투영 행)를 특정하고,
`spec = max|Δ|_E − max|Δ|_N`(에지 국소도)와 `agree`(변화의 열 부호 일치율,
0.5 = 등방 클러터 / 1.0 = 화면 전폭 선)로 판정한다.
발동 조건 `spec > 8.0 AND agree ≥ 0.70`, `spec > 20.0` 이면 FAIL (`:720-726`).

| 컷 | E 대역(행/540) | 낙차 예상 행 | **spec** | dE | dN | **agree** | 판정 |
|---|---|---|---|---|---|---|---|
| `h0.3_d2` | 169.6~312.0 | 248.7 | 5.27 | 11.18 | 5.91 | 0.594 | 미발동 |
| `h0.3_d5` | 130.6~211.8 | 174.3 | **−11.19** | 4.18 | 15.37 | 0.596 | 미발동 (변화가 전량 근경 = v2 가 잡아낸 v1 오탐) |
| **`h0.3_d10`** | 124.4~177.4 | 149.0 | **24.79** | **25.04** | **0.25** | **0.6990** | **미발동 — FAIL 임계를 `agree` 0.0011 차로 비껴감** |

`[실측 — regression_check v2 --json]`

> **`h0.3_d10` 이 위험하다.** `agree = 0.6990 = 671/960 열`. **열 하나만 더 일치하면
> 672/960 = 0.700 = 임계 도달**이고, `spec 24.79` 는 이미 FAIL 임계 20.0 을 넘겼다.
> 즉 현행 하이브리드는 판정 1순위 컷에서 **GRAZE FAIL 을 1/960 마진으로 면하고 있다.**

원인은 기하로 특정된다. 최대 변화 행 `gz_row = 167` 은 §3-b 에서 계산한
**3D 밴드 시단(x = −4.20)의 투영 행 y = 0.310 → 167/540** 과 일치한다 `[계산·실측 일치]`.
그리고 진짜 낙차 행은 149 다 — **18행(프레임 높이의 3.4 %) 차이**.

⇒ **현행 하이브리드의 "낙엽 밭 경계"가 낙차 에지 대역 한복판에 가짜 수평선을 만들고 있다.**
`dN = 0.25`(근경 무변화) · `dE = 25.04`(에지대역만 변함)는 "화면을 가로지르는 선이 에지
대역에 국소 발생"이라는, v2 가 **낙차 노출을 검출하려고 설계한 바로 그 서명**이다.
낙엽이 스스로 낙차 단서를 위조하고 있는 셈이다.

**전역화 후 예상** `[추정 — 같은 산포의 실측 대역으로 외삽]`:

- 밴드 시단이 `x = −10.60`(d10 eye 뒤)으로 이동 → **프레임 안에 낙엽 밭 경계가 없다.**
  E 대역 변화는 등방 낙엽 클러터만 남는다.
- `agree`: 같은 산포가 경계 없이 깔린 대역의 실측치는 **0.594 / 0.596**(`d2`·`d5`).
  d10 도 **0.55 ~ 0.62** 로 내려갈 것 → 임계 0.70 에서 멀어진다.
- `spec`: 근경 N 대역도 같은 낙엽으로 바뀌므로 `dN` 이 0.25 → dE 급으로 올라
  `spec = dE − dN` 이 **0 부근으로 붕괴** → 임계 8.0 미만.
- ⇒ **`h0.3_d10` GRAZE v2 : PASS 유지 + 마진 대폭 확보.** 현행의 1/960 위험이 사라진다.

재캘리브레이션 담당에게 전달할 것:

1. **v2 는 잘 작동한다** — 본 A/B 에서 GRAZE 발동 0건, 남은 FAIL/WARN 은 전부
   `FRAME`·`OCCL`(근경 재질 전면 교체의 당연한 결과)이다. 임계를 더 손댈 이유가 없다.
2. 다만 `d10 spec 24.79 / agree 0.6990` 은 **임계 바로 아래에 걸린 실사례**다.
   코드 주석의 대조군 157컷 통계(`:191-194`, spec p90 0.2~9.8 · **max 24.8**)와
   소수 첫째 자리까지 같다 — **이 컷이 그 max 일 가능성**이 있다 `[추정]`.
   그렇다면 대조군 상단에 "낙엽 밭 경계"라는 **인공 수평선**이 섞인 것이므로,
   전역화 후 값으로 갱신해야 한다. 근거 문서 `Docs/reports/graze_recalibration_v1.md`
   는 코드가 참조하지만 **아직 파일이 없다** — 대조군 구성표 공개를 요청한다.
3. 전역화 자체의 은닉 여부 판정 정본은 GRAZE 가 아니라 **`leaf_cover` ON/OFF 대응쌍**이다
   (`SCENE_CONFIG["leaf_cover"]`, `:324` "OFF 시 계단·난간 트랜스폼 완전 불변").
4. `FRAME`·`OCCL` 은 전역화에서 **더 크게** 흔들린다(근경 전체가 흙→낙엽). `d5` 는 845개만으로
   이미 블록이동 45 % FAIL 이었다 `[실측]`. 전역화 렌더를 새 before 로 **re-baseline** 할 것.
