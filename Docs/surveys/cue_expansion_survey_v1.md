## 표기 규약

**상설 표준법 약칭** — 각 표 "표준법 저촉" 열의 `법N`: **법1** 손상·노후·결손 표현 금지(08-05 독트린) · **법2** 임의 제작 경고·안내판 금지 · **법3** 점자블록 기본 OFF는 사용자 소유 결정 · **법4** 기능 필수성 심사("비움이 기본값") · **법5** 신규 씬·차량·계절 소품·장식 바닥 사각형 금지 · **법6** 재질 동결 · **법7** `cue_*`는 **기하 불변**(기하를 움직이는 토글은 `hazard_*` 전속) · **법8** 근거 태그 표기 의무.

| 표기 | 뜻 |
|---|---|
| `[확인]` | 법령·표준·공공 실태조사·논문에서 직접 확인 |
| `[추정]` | 확인값에서 추론·보간. **근거 논리를 함께 적었다** |
| `[근거 없음]` | 찾지 못함. 구현하면 코드 주석에 이 표기를 남길 것 |
| `[코드]` | 우리 저장소 소스에서 직접 읽은 값 |
| `[stat]` · `[확인 — 부재]` · `[추정 — 관행]` | 위 4태그의 변형 — 순서대로 ① 후속 실측·통계 인용 ② "그런 규정이 없음"을 확인 ③ 법정 의무는 아니나 시공 관행으로 보편 |

### 조사 한계 — 먼저 읽을 것

1. **렌더를 한 장도 보지 않았다.** 사분면 기여·시각 효과 판정은 전부 **기하 추론**이며, 프레임 안에서 실제로 그렇게 읽히는지는 렌더 후 육안 확인이 필요하다.
2. **구현 난이도는 빌더 존재 여부로만 매겼다.** 배치 좌표·씬 정합성 비용은 산정하지 않았다.
3. **조건부 확률 예측치는 계산하지 않았다.** 후보 투입 후 P(낙차\|단서)가 얼마가 되는지는 씬별 배치 개수가 정해져야 나온다 — §7 승인 후 산출할 값이다.
4. **§6 매트릭스·죽은 키 집계는 AST + 씬별 grep 재검산 기준**`[코드]`. 킷 모듈은 `SCENE_CONFIG`를 읽지 않고 어느 씬도 `cfg`를 킷에 넘기지 않으므로 씬 로컬 판정이 정본이다.
5. 일부 후보 근거는 **1차 문헌을 열지 못한 2차 인용**이다. 해당 행은 `[추정]`/`[근거 없음]` 표기.

# 1. 단서 지도 — 기존 6키 + 신규 후보 통합 (정본)

나누는 기준은 **신호가 어디서 나오는가**다. 낙차가 직접 안 보일 때 그 존재를 알려주는 경로는 다섯 갈래다.

| 갈래 | 원리 | 주 판독 거리 |
|---|---|---|
| **① 울타리** | 사람은 위험한 모서리에만 세운다 — 서 있음 자체가 경고 | 중거리 |
| **② 바닥 표시** | 규정·관행이 낙차 직전 바닥에 표시를 요구한다 | 근거리 |
| **③ 하강 시설** | 내려가는 시설의 부속물 — 낙차가 가려지거나 멀어도 하강 확정 | **원거리** |
| **④ 낙차 이면** | 아래 공간이 있으면 물·식생·배수·시설이 달라진다 — 환경이 흘리는 신호 | 근~중거리 |
| **⑤ 사람·흔적** | 관리·사용의 흔적 | 혼합 |

- **기존 6키는 ①②에만 몰려 있었다.** 이번 확장의 최대 의미는 **③(원거리)과 ④(환경 신호)가 통째로 새 갈래**라는 것.
- 로봇 접근 시 단서는 겹겹이 나타난다: 원거리 ③ → 중거리 ① → 근거리 ②·④.
- ※ 기존 `cue_scene_dressing`은 낙차 단서가 아니라 **배경 전체 환경 스위치**라 지도 밖이다(§6.1).
- ※ 각 갈래의 단서와 "같은 외형인데 낙차 없이 평지에 서는 것들"(탈상관 재고)은 §2에 있다 — 짝 대응표는 §2.0.

# 2. 탈상관 재고 — 같은 외형인데 낙차 없이 평지에 서는 것들 (데이터셋 설계용)

> **왜 필요한가**: `cue_arr §4.1` 실측 — **P(낙차\|난간) = 17/18 = 0.944**, "단서 있음·낙차 없음" 칸은 **1/33 = 3%**(목표 ≥20%). 이대로면 모델이 "난간만 보면 낙차"라는 지름길을 외운다. 이 표는 그 칸을 채우는 재고 목록이며 **평지에 정상적으로 서는 것**이 선정 기준이다.
> 용어: **사분면** = 낙차 라벨(label) × 단서 존재(cue)의 2×2. **cue+/label−** = 단서 있고 낙차 없음(*visual-cliff* 칸) · **FP** = 낙차 없는데 낙차로 읽히는 오검출 · **base rate** = 33씬 낙차 비율 0.848 · **ablation** = 단서를 끄고 성능 변화를 재는 절제 실험.

# 4. 내재 단서 vs 맥락 단서 — 토글이 덮는 범위

> **왜 이 절이 필요한가**: "단서를 다 껐는데 모델이 여전히 맞힌다"가 실패가 아니라 **정상**임을 미리 못박기 위해서다. 낙차 자체가 내는 신호는 토글로 끌 수 없다.

| 층 | 뜻 | 우리 제어면 |
|---|---|---|
| **내재 단서(intrinsic)** | 낙차 **기하가 존재하는 한 함께 따라오는** 광학 정보 | `hazard_*` 키로만 사라진다. `cue_*`로는 원리상 불가 |
| **맥락 단서(contextual)** | 사람이 낙차 **주변에 설치한** 것 — 부재·도색·표시 | §1~§2가 다루는 전부 |

## 4.1 문헌이 정리한 내재 단서 (전부 `cue_*` 밖)

| 내재 단서 | 요지 | 우리 세팅에서 |
|---|---|---|
| **Occluding edge** | 낙차선은 지지면 위 폐색 경계 — 위쪽 픽셀은 먼 지면, 아래쪽은 가까운 지면 (Murarka et al., IROS 2008 §V) | `hazard_*` ON이면 반드시 생긴다. 공중 물체도 같은 시그니처 — ground-plane 판정 병행 필요 |
| **Occlusion–disocclusion 비대칭** | 접근하면 경계 아래가 새로 나타나고 멀어지면 사라진다 (같은 문헌) | **단일 프레임 U-Net에는 원리상 부재** — 우리가 포기한 정보의 명시 |
| **Missing-ground / no-data 밴드** | range map에서 drop-off는 "데이터 없는 넓은 영역" (Rankin et al., SPIE 6561, 2007 §1) | RGB 대응물 = "지면 텍스처가 있어야 할 자리에 지면이 없는 띠" — 낙차 마스크가 이 밴드와 일치해야 한다는 라벨링 근거 |
| **Trailing-edge upslope** | 원측 벽면 상승 사면이 보이면 깊이 추정 가능, 안 보이면 얕은/깊은 구분 불가 (같은 문헌 Fig.1) | **카메라 pitch·거리 설계가 이 가시성을 직접 결정** |
| **Depth/disparity 불연속** | negative obstacle 검출의 정본 기하 단서. 정지거리에서 가시 폭 수 픽셀 | 렌더 해상도·라벨 최소폭 설계에 직결 |
| **함몰부 내부 self-shadow** | 하늘 가림으로 어두운 폐곡선 — JPL의 1차 후보 생성기 | **§2 `cue_shadow_caster`의 FP와 원리상 같은 신호** — 핵심 난제의 근원 |
| **Photometric 대비(토양 vs 식생)** | 도랑은 수분을 모아 색·반사율이 이산적으로 바뀜 (Sensors 22(21):8463, 2022) | **경계 사례** — 자생 식생 대비는 내재, 사람이 심은 띠녹지는 맥락(§1.4 `cue_vegetation_band`) |
| **Low intensity variance(하부 담수)** | 함몰부 담수의 비정상적 저분산 — 단 JPL은 재현성 부정 결과 병존 | 맥락측 대응물 `cue_water_surface`(§3.2). 과신 금지 승계 |
| **Texture gradient 절단 / horizon-ratio 불연속** | texture density 구배가 낙차선에서 끊김, 너머 물체는 밑동 잘림 (Gibson 1979 · Sedgwick) | 지면 패턴 해상도·배경 배치가 실제 생성 여부를 정함 — 토글이 아니라 look-check 항목 |
| **Step-edge luminance contrast** | 계단코 대비 <50%면 단이 "위장"됨 (Foster et al., Appl. Ergon. 96, 2021) | **경계 사례** — 대비는 내재 속성, 도색(`cue_nosing`)은 그 대비를 인위로 만든 맥락 자산 → `cue_tread_contrast`(§3.2)와 분리 |
| **Riser band** | 챌면 = 진행방향 수직 띠. 1~2단이면 그림자 밴드·포장 전환선과 통계적으로 구분 불가에 가까움 | §2 base rate 문제의 직접 원인 |
| **Thermal signature** | 함몰부는 야간 MWIR에서 강한 단서 (Matthies & Rankin, IROS 2003) | **모달리티 밖** — 야간 스코프 제외(07-27)와 일치. "기하가 안 보일 때 문헌의 답은 열이었다" = RGB 맥락단서 연구의 공백 논거 |

## 4.2 그래서 토글 시스템은 무엇을 덮는가

1. **`cue_*`는 맥락 단서만 덮는다.** 내재 단서는 낙차 기하와 함께 이동하므로 `hazard_*` 소유 — 이것이 **법7**의 존재 이유이며, 법7이 지켜져야 "cue를 껐다"가 "기하는 그대로다"를 의미한다.
2. **경계에 걸친 것이 셋 있다.** ① 계단코 대비(내재 대비 vs 도색 `cue_nosing`/`cue_tread_contrast`) ② 함몰부 그림자(내재 self-shadow vs 캐스터 그림자 `cue_shadow_caster`) ③ 식생 대비(자생 = 내재 vs 식재 = 맥락 `cue_vegetation_band`). **키를 쪼개야 분해된다.**
3. **`cue_*` 전 토글 OFF가 "무단서"를 뜻하지 않는다.** 내재 단서는 남으며, 그 팔의 성능은 **"기하만으로 U-Net이 되는가"** 의 측정치이지 0이어야 할 값이 아니다.

# 5. 실험 설계 함의 — 페어를 어디에 쓰는가

## 5.1 matched toggle pair가 채우는 자리

| 문헌 설계 | 우리 대응 | 요구되는 토글 |
|---|---|---|
| **Texture–shape cue conflict** (Geirhos et al., ICLR 2019) | 렌더 레벨 단서 충돌: (a) 기하 낙차 O + cue 전부 OFF, (b) 기하 낙차 X + cue ON. 출력이 기하/단서 중 무엇을 따르는가 = geometry bias vs cue bias | (b)에는 **평지에 서는 단서** 필요 → §2 전부. **법7이 (a)/(b)의 직교성을 보장** |
| **Shortcut learning 진단** (Geirhos et al., NMI 2020) | `cue_arr §2.5` 프로토콜 그대로 — 학습 P=0.30 고정, 테스트 (a) 0.30 (b) 반전 0.70 (c) 무상관 0.50 | 세 조건을 **동일 33씬의 토글 조합만으로** — 씬 내용 교락 0(실사로는 불가능한 통제) |
| **Cue-randomized training** (Stylized-ImageNet) | `cue_*`를 `hazard_*`와 **독립 베르누이**로 샘플링해 렌더 | 씬 수 불변(법5)으로 다양성 확보, 목표 P를 라벨별 확률로 정확히 지정 |
| **3DB 격자 스윕** (Leclerc et al., NeurIPS 2022) | `SCENE_CONFIG`가 3DB **control plane과 동형** — `cue_*` 축 × 조명·카메라 축 격자, 셀별 실패율. 특히 **`cue_shadow_caster` × 태양고도(15~45°)** 상호작용이 "난간을 보나 그림자를 보나"를 분리 | 조건 수만 증가(법5 준수). 조명·카메라 축은 W5 스펙 소유 → **W5 합동 실행** |
| **Early Cue Precision 스윙** (Park et al., 2026) | 현재값 **0.944**는 지름길 채택률 0.049→0.855 급등 구간(p≈1.0)에 있다 | (i) 커리큘럼 초반 10~20% cue+/label− 2배 상향, (ii) 전 구간 0.20~0.35 유지 |
| **환경별 상관 강도 스윙** (IRM, 2019) | `cue_*`마다 P(drop\|cue) ∈ {0.20, 0.35, 0.50, 0.70} 4개 렌더 환경 | 실사로는 상관 강도 지정 불가 — **합성 정당화 논거**. §2.5의 0.20~0.35가 임의값이 아님을 보임 |
| **worst-group 지표** (Group DRO, ICLR 2020) | (cue ON/OFF)×(낙차 유/무) 4분면 = group. "네 칸 ≥15%" = 그룹당 최소 표본 | **1차 지표를 worst-quadrant IoU로** — cue+/label− 1/33에서는 그 칸이 측정 불가임이 수치로 드러남 |
| **전경/배경 분해** (ImageNet-9, ICLR 2021) | (1) CUE-ONLY: hazard 제거+cue 유지 (2) GEOM-ONLY: cue 전부 OFF (3) MIXED: 씬 A cue를 씬 B 기하에 이식 | (1)의 예측량 = **맥락 의존도의 상한** |
| **Counterfactual / PCCP 보존율** (NeurIPS 2022) | matched pair = 반사실 쌍. 1차 ablation 지표를 ΔIoU가 아니라 **보존율**로 | 보존율은 페어 내부 정규화 — 씬 난이도 오염 제거. 씬별 나열로 "단서에 업힌 씬"이 드러남 |
| **ROAR** (NeurIPS 2019) + **Occlusion sensitivity** (Zeiler & Fergus, 2014) | ① cue-off 렌더의 추론 평가와 재학습 평가 분리 ② 같은 난간을 (a) 픽셀 패치로 가림 (b) 재렌더로 제거한 ΔIoU 비교 | ①후자 = "그 단서 없이 과제가 학습 가능한가" — 본 연구의 근본 질문. ② = 렌더 ablation 필요성의 방법론 논거(**가짜 사각형은 그 자체가 신호**) |
| **SpRAy / Clever Hans** (Nat. Commun. 2019) | 33씬 × 토글 조합 히트맵 클러스터링 — **가설 없이** 예측을 끄는 자산 발견 | §6.3 D2~D6·D11(구현 아티팩트 = 워터마크) 상황이라 우선순위 높음 |
| **단서 신뢰도 가중** (Landy et al., 1995) | `cue_railing`·`cue_nosing`을 반대 방향으로 걸어 예측 낙차선 이동량 → 가중치 w_i | w_i를 목표 P와 회귀 — 모델 가중치가 데이터 상관을 반영하는 정도의 정량화 |
| **Visual cliff** (Gibson & Walk, 1960) | cue+/label− 칸의 **개념적 원형** — "단서는 낙차를 말하는데 실제 낙차 없음" = 유리판 | 이 칸을 **visual-cliff quadrant**로 명명 — 4분면 설계가 60년 된 지각 실험의 재현임을 명시 |

6. **키 충돌 없음 확인**`[코드]` — 제안 키 전부가 현존 14키와 이름이 겹치지 않는다. 단 `cue_handrail`은 **기존 `cue_railing`의 의미를 좁히는 변경**이므로 별도 결재 항목이다.

## 7.4 W4 / W5 연계

**W5의 hazard-off 팔이 이 페어들의 최종 소비처다** — `hazard_*`를 OFF로 두고 `cue_*`를 ON으로 유지한 쌍둥이 렌더가 곧 cue+/label− 표본이다. 단 **승인 범위를 정확히 적는다**: `lighting_camera_variation_spec_v1.md:742`에서 승인된 hazard-off 쌍둥이의 목표는 `P(낙차 | 난간) = 0.944` → **0.6~0.8**이고, `§2.5`의 **0.25~0.35까지 내리려면 이 문서의 키 확장이 추가로 필요**하다(쌍둥이만으로는 도달하지 못한다).
선행으로 **W4 GT 재판정에서 낙차 임계(h≥0.30 주라벨 / 0.10~0.30 minor step)가 확정돼야** §7.3-5 목록의 법7 판정이 끝난다. §5.1 3DB 격자는 조명·카메라 축을 W5 스펙에서 빌려오므로 **W5와 합동 실행**이 전제다.
