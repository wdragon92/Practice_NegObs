## §2 팀 간 상충 4건 — 해소

### 상충 1 (핵심): 센서 후처리가 해법인가?
- **B·G팀**: 센서/이미지형성 시뮬이 최고 ROI 저비용 개입 (Carlson 2018 +4.3~7.3 AP)
- **E팀 통제실험**: JPEG 아님(q95 재인코딩 시 지표 불변). **센서 그레인도 아님** — 실사 노이즈
  플로어를 맞추려면 중간회색 **16.7% 그레인**(비물리적)이 필요하고 그때조차 고주파는 **5.5분의 1만** 회복.
  **실사 사진의 가장 평탄한 1% 타일조차 우리 렌더보다 24.9배 더 변동** — 실사엔 평탄면이 없다.

**해소**: 두 주장은 서로 다른 것을 말한다.
- 센서 시뮬 = **도메인 지문 제거**(sim 특유의 무노이즈·완벽노출 통계). 필요하고 싸다. 유지.
- 그러나 **고주파 결손의 원인은 표면 미세구조 전면 부재**이며 후처리로는 못 닫는다.
- → **"센서 시뮬은 필요조건이지 충분조건이 아니다."** 둘 다 하되 역할을 혼동하지 말 것.
- 부수 결론: **PT spp 인상은 무의미**(측정값이 이미 spp=512 PT).

### 상충 2: 배치 랜덤화(SDR) vs 관심객체 정확도
- **B팀**: SDR이 ROI 2순위 (KITTI AP +20.6/+26.8/+28.2)
- **A팀**: SDR은 우리에게 적용 불가 — 우리 관심 신호는 맥락 그 자체라 프리미티브 대체 = 학습 신호 삭제

**해소**: 상충 아님. SDR 원논문이 **"관심 객체는 정확히 모델링, 배경만 랜덤화"**다.
우리 관심 객체 = 난간·볼라드·연석·계단 노징·수관. → **이것들은 사실적으로, 배치·조명·배경은 랜덤화.**
GuideTWSI 레시피("배경은 사서 쓰고 관심 객체만 규격대로 직접 제작")와 정확히 일치.

### 상충 3: 감독 초기 추정 철회
감독이 "OptiX denoiser + DLSS가 고주파를 지우는 것 아닌가"를 혐의점으로 제시했고
**추정이며 A/B 검증 필요**로 표기했다. **E팀 통제실험이 이를 반증했다** — 원인은 후처리가 아니라
표면 미세구조 부재다. 추정을 철회한다. (denoiser/DLSS 자체 검증은 여전히 가치 있으나 우선순위 하)

## §3 가장 위험한 것은 미학이 아니다 — 지름길 학습과 주장 무결성

### 3.1 "고수준 단서라 충실도 요구가 낮다"는 논거는 성립하지 않는다
B팀이 이를 지지하는 논문을 **찾지 못했고**, 반대 근거가 강했다:
- van Dijk & de Croon (ICCV'19): 모든 단안 깊이망이 **겉보기 크기를 무시하고 이미지 내 수직 위치**를 씀
- Islam et al. (ICLR'20): **제로 패딩이 CNN에 절대 위치를 인코딩** → 패딩 conv를 쌓는 U-Net 직격
- Early Cue Precision (arXiv:2606.30344, 감독이 인용 직접 확인): 단서-라벨 상관 p=1.0이면
  지름길 채택률 **0.049 → 0.855**. 저자 결론 "단서 탈상관이 아키텍처나 입력 열화보다 중요"

### 3.2 우리가 만든 지름길 (B팀 13개 중 최상급, 감독 코드 확인 표시)
| # | 지름길 | 확인 |
|---|---|---|
| S1 | **카메라가 h{0.3,0.9,1.8} x d{2,5,10} 9개 이산조합·피치 -10도 고정** → "이미지 y좌표 = 낙차" | **감독 확인** (scene_common.py:1183, 전 씬 공통) |
| S2 | 수면이 roughness 0.08 거울면 → "이 RGB = 낙차" | 감독 정정: albedo (0.05,0.10,0.11) 저채도. 원인은 **하늘 반사** → 처방은 파문 노멀·탁도·부유물 |
| S3 | 재질 팔레트 ↔ 클래스 1:1 | C팀 확인 |
| S6 | 설비-낙차 결정론적 상관 p=1.0 | batch1 hard-negative 12씬 존재하나 **비율 설계 근거 없음** |
| S8 | 정오 맑음 단일조건·태양방위 고정 | **C팀 확인** (21씬 파라미터 문자 단위 동일) |
| S13 | **동적 개체 0건** | **A·B·C 3팀 독립 확인** |

### 3.3 S13은 성능이 아니라 논문 주장의 결함이다
맥락단서 4계열 중 **3번 스케일 앵커**가 "사람 상반신·차 지붕이 눈높이 이하"를 명시한다.
학습 데이터에 사람·차량이 0건이면 **그 주장은 데이터로 뒷받침되지 않는다.**
A팀 판정: 렌더 품질이 아니라 데이터셋 설계 결함이며 리젝 사유.

### 결정 2: 사람·차량 도입 범위
단서 3번이 성립하려면 필수. 범위 선택 필요 — 전 씬 / 관련 씬만 / 차량만.

## §6 실행 계획 (우선순위 = 임팩트/비용, 팀 권고 통합)

### T0 — 검증 스파이크 (착수 전 반나절, 실패 시 계획이 바뀜)
1. **`round_edges_radius` 육안 검증** — F팀 최고 ROI인데 두 팀 다 미검증. 1프림 A/B 렌더
2. `subdivisionScheme=catmullClark` + crease가 RTX Hydra에 반영되는지 (D팀 [미검증])
3. `NegObsGround.mdl`을 본편 1씬에 바인딩 → flat%/고주파 개선폭 측정

### T1 — 씬 파일 무수정, scene_common.py/MDL 층위만 (1주)
회귀 위험 최소(v5 21/21 합격 상태 보존). 전 씬 재렌더는 **3씬 게이트 통과 후**(GPU 1대).
1. **`NegObsGround.mdl` 프로덕션 이식** — 이미 검증된 자산. 최우선
2. **가짜 베벨** (T0-1 성공 시 make_pbr 인자 1개로 33씬 전 모서리)
3. **`detail_normalmap_texture` + `detail_bump_factor`** — 근접뷰 텍셀 뭉개짐 즉시 개선 [로컬검증됨]
4. **헥스 타일링 MDL** (약 40줄, gamma=7 beta=0.6 r=0.7 + 타일 랜덤회전)
5. **접지 AO·오염 링** — 월드 Z 그라디언트. G팀 우선순위 1위, 비용 자명
6. **절차 웨더링 마스크** (약 30줄): 상향면 먼지 normal.z>0.6, 스플래시존 30~50 cm, 하향 줄무늬
7. **상수색 재질에 텍스처 강제** — flat% 직격
8. **잎 노멀 트랜스퍼** (약 10줄 MDL, normalize(P - cluster_center)) — 구 수관 유지한 채 음영 개선
9. **채도 캘리브레이션** (현 0.298 → 목표 0.15~0.22)
10. **창 리세스 버그 수정** — window["inset"]이 정의만 되고 안 읽힘(scene_common.py:891).
    현재 창이 파사드 밖으로 20 mm 돌출. 10개 씬이 inset을 넘기는데 전부 무시됨. 비용 거의 0
- **목표 수치**: flat% 8% 미만, slope -2.0~-2.2, sat 0.15~0.22

### T2 — 지오메트리·다양성 층위 (1개월)

### 9.4 감독 정정 — 점자블록은 "텍스처 수준 차이"가 아니다

앞서 감독 보고에서 이 항목을 G팀 근거(특허 유래)로 전했다. 법령 원문이 더 정확하며, 특히
**한국 vs 서구는 텍스처가 아니라 모듈·색·돌기수가 전부 다르다**:

| | 한국 점형 | 영미 blister |
|---|---|---|
| 색 | **노란색** | **적색/버프색** |
| 모듈 | **300×300 mm** | **400×400 mm** |
| 돌기 | **36개 6×6 정렬격자, 6±1 mm** | **약 64개 오프셋격자 66.5 mm 피치, 6 mm** |

서구 에셋을 그대로 쓰면 **네트워크에 틀린 사전지식을 가르친다.** 그리고 이 노란 대역은
법에 의해 **계단 머리·연석 경사로·승강장 연단·볼라드 전면** — 즉 우리가 회귀하려는 낙차 위치에
**정확히 공존**한다. 미관 문제가 아니라 **이 도메인에서 비가시 낙차의 가장 강한 RGB 단서**다.

`opacityThreshold` 기본값이 **0.0** 이라 설정하지 않으면 **잎이 전부 불투명 판때기**가 된다.
나무 임포트 시 이것부터 확인할 것. (G팀의 알파 밉맵 커버리지 보존 이슈와는 별개 문제)

### 10.3 PT 워밍업이 약 70배 낭비되고 있다 [D팀 실측]
`/rtx/pathtracing/spp` 기본값이 **1** 이라 우리는 512spp를 **512프레임에 걸쳐** 누적 중이다
(`scene01:1211-1212` + 워밍업 `pt_spp+60` = **572회 루프**).
`spp=16, totalSpp=64, rt_subframes=8` 이면 **8프레임**에 수렴.

| 모드 | D팀 실측 | 2만 장 환산 |
|---|---|---|
| PT 512spp (현재) | **13.99 s/컷** | **70시간** |
| RT (워밍업 90) | **1.12 s/컷** | 6시간 |
| RT (워밍업 32로 축소) | 약 0.4 s/컷 | **1.3~2.5시간** |

- NVIDIA 공식 벤치: **annotator를 전부 켜면 처리량 40배 붕괴**(GPU와 무관).
  → RGB + depth + semantic + camera_params **4개만** 켤 것.
- **RT로 데이터를 뽑아도 된다** — 단 GI 강화 + RT↔PT 정합성 실험 + PT 5~10% 홀드아웃 3조건 충족 시.

### 10.4 GT 낙차 맵은 렌더러로 만들 수 없다 — 설계 전제 수정
**비가시 낙차는 정의상 어떤 렌더 pass에도 나타나지 않는다.** depth·semantic·normal 전부 무력.
게다가 **4.5의 직교(orthographic) 카메라는 조용히 틀린 값을 낸다**(D팀 확인)
→ **탑다운 직교 높이맵 계획은 폐기.**
대안: **PhysX 레이캐스트로 2.5D 높이장을 만들고 픽셀 역투영**으로 GT 생성.
(T3 항목 20의 구현 방식이 이걸로 확정된다)

### 10.5 감독 앞선 보고 정정 — 재질 투영 방식
감독이 사용자에게 "OmniPBR **월드 트라이플래너** 투영"이라고 보고했으나,
D팀 로컬검증 결과 `project_uvw`는 **트라이플래너가 아니라 큐빅(cubic) 투영**이다.
→ **경사면에서 이음매가 생기는 원인**이며, 우리 `scene07`이 자체 주석으로 이미 진단해 둔 문제와 일치한다.
(`texture_scale`은 항상 적용된다는 점도 함께 정정.)
이는 §1의 `NegObsGround.mdl`(진짜 소프트 트라이플래너 + 45도 보조기저)이 왜 결정적인지를 설명한다.

### 10.8 기타 확인 사항
- `ensure_noon_lookfix()` numpy HDRI 수술이 **불필요했을 가능성** — 정식 해법은
  `/rtx/domeLight/upperLowerStrategy=0`. 나아가 위경도·절기·시각 구동 **물리 하늘**(구름 6종·대기포그)이
  로컬과 S3 양쪽에 존재 → T2의 "조명 다변화"를 자체 구현할 필요가 줄어든다.

  → §6의 T0 스파이크에 병합할 것.
