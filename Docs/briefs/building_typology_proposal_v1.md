### 1.2 원인 4중 구조

1. **유형 스위치가 거의 선언되지 않는다.** dict 79동 중 `bd["kind"]`를 명시한 것은 s01 10동뿐
   `[measured]`. 나머지는 `infer_kind()` `building_kit.py:566-633` 가 층수·층고·깊이로 추정한다.
   그 추정은 «층수 ≤ 8 → office» `:631-632` 이므로 **3~5층 한국 가로 건물이 전부 office 로 떨어진다**
   (s11 6동 전량, s16 D동, s01 8동). office 는 커튼월 + 포디움 후퇴 유형이다.
2. **거리가 유형을 덮어쓴다.** `plan_building` `:833-835` 는 `tier=="silhouette"` 이거나
   `in_frame False` 면 `kind="backdrop"` 로 강등한다. 이건 프림 예산으로는 옳지만
   **"근접인데 프레임 밖"** 케이스(s16 가로벽 12동, s02 10동, s20 4동, s21 3동)에서
   *보행자가 스치듯 보는 벽*을 3프림 상자로 만든다. s16 코드가 이 모순을 이미 자백해 두었다 —
   `scene16_canopy_shadow.py:394-407` *"Policy (2) is written for a building the camera faces,
   not for a wall it travels along."*
3. **재질 롤이 3개뿐이다.** 레거시 24 call site 전부 `(shell, glass, parapet)` 만 넘긴다 `[measured]`.
   `Mtls` `:533-542` 의 fallback 사슬 때문에 **기단 화강석·금속·간판·소방 데칼이 전부 파라펫
   재질로 칠해진다.** `w3r_building_ab_v1.md:543-544` 가 이미 *"Passing a `sign` and a `stone`
   material is not optional in practice"* 로 못 박았으나 미이행. **선례는 1건 존재** —
   s18 만 `bk.Mtls(shell, glass, parapet, stone=M["coping"], metal=M["pole"])`
   `scene18_wavy_artstair.py:1507-1510` 로 5롤을 넘긴다. 확장의 형식은 이미 씬 하나가 증명했다.
4. **유형 대신 파라미터로 때운 흔적이 코드에 남아 있다.** s06 `window_by` `:566-573`, s11
   `window_by` `:477-484` 는 **동별로 창 폭·높이·`col_step`·`margin` 을 따로 준다** `[measured]`.
   같은 유형의 건물 6동이 서로 다른 창 규격을 갖는 실경은 없다. 이것은 "격자가 타일처럼 반복돼
   보인다"는 증상을 격자 파라미터를 흔들어 덮으려 한 것이고, 유형(=베이 리듬)을 도입하면
   불필요해진다.

## 3. 씬별 설계 제안

각 절 형식: **컨텍스트 → 추천 유형(+대안) → 매스·비례 → 입면 문법 → 재질군 → 킷 갭 → 판정축 안전성.**
수치는 씬 좌표계(m). `d_true`·`z_ceil`·`tier`·`in_frame` 은 이 세션에서
`bk.plan_building(eyes=bk.judged_eyes(gy))` 로 재계산한 `[measured]` 값이다.
