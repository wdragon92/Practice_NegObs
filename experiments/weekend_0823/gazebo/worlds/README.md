# gz_drop* — Gazebo Classic drop-off 씬 사양 (WEEKEND_BRIEF_0823 §6.7-c)

4개 월드. 전부 `../make_worlds.py`가 생성한다 — **`.world`를 손으로 고치지 말고 생성기를 고칠 것.**

```
gz_drop1.world        내려가는 계단 (4단 × 0.18 m = 0.72 m 낙차) → 우묵한 피트
gz_drop1_ctrl.world   그 트윈 대조군 — 계단·피트 제거, 장식(dressing) 전부 동일
gz_drop2.world        플랫폼 단차 (수직 0.80 m), 난간은 +Y 한쪽에만
gz_drop2_ctrl.world   그 트윈 대조군 — 아래층을 지면 높이로 올림, 장식 동일
```

`gz sdf -k` 정적 검사 4/4 통과. SDF 1.6 / Gazebo Classic 11.10.2.
**`<include>`·`model://`·메시 0건** — 인라인 box/cylinder + 스톡 `Gazebo/*` 머티리얼뿐.
이유: `bumperbot_description/launch/gazebo.launch.py`가 `GAZEBO_MODEL_PATH`를 **덮어쓴다**.
부작용으로 저들 런치 없이도(`ros2 launch gazebo_ros gazebo.launch.py world:=...`) 그대로 열린다.

## 1. 좌표 규약

- **+X = 진행/시선 방향.** lip(낙차 시작 모서리) = **`x = 12.0 m`**, 데크 윗면 = `z = 0`.
- 코퍼스는 lip을 `x = 0`에 두고 눈을 `x = -d`에 둔다(`scene_common.grid_views`).
  여기서는 씬 전체를 **+12 m 평행이동**했다. 이유 하나뿐: `gazebo.launch.py`의
  `spawn_entity.py`가 로봇을 **`(0, 0, 0.15)`에 하드코딩**해 스폰한다. 12 m 밀어 두면
  로봇은 가장 먼 카메라(`x = 2.0`)보다 **2 m 뒤**에 서므로 어떤 프레임에도 안 들어온다.
- 따라서 어떤 뷰든 **표준거리 d = 12.0 − (카메라 x)**.

## 3. gz_drop1 — 내려가는 계단

```
              railing(양쪽, y=±1.30)            far wall
   ────────────────────────────┐  ▁▁▁            │
   deck z=0                    │▁▁    ▔▔▔▔▔▔▔▔▔▔▔│  deck z=0
   ══════════════[warn strip]══╪══ steps ══════════════════
                            x=12.0        pit floor z=−0.72
                             lip      x=12.9 … 20.0
```

| 요소 | 값 |
|---|---|
| 낙차 | **0.72 m** = 4 riser × 0.18 m (요구 ≥ 0.6 m 충족) |
| tread | 0.30 m, 계단 폭 2.20 m (`|y| ≤ 1.10`) |
| 계단 x | 12.00 → 12.90 (tread 3장), 4번째 riser가 곧장 피트 바닥으로 |
| 피트 | `x ∈ [12.90, 20.0]`, `|y| ≤ 1.10`, 바닥 `z = −0.72`, 끝벽 `x = 20.0` |
| 데크 | `x ∈ [−16, 120]`, `|y| ≤ 8`, 두께 1.5 m (피트 옆벽이 곧 데크 측면) |
| 난간 | 양쪽 `y = ±1.30`, 기둥 x = 8·9·10·11·12, **발은 전부 데크 `z=0`**, 상단봉 1.05 m / 중간봉 0.55 m, 반지름 0.035/0.030 |
| 경고블록 | lip에 밀착 `x ∈ [11.70, 12.00]`, `|y| ≤ 1.10`. `Gazebo/Yellow` 6 mm 슬래브 + `Gazebo/ZincYellow` 돌기 51개(0.05 m 각, 3열 × 17행, 피치 0.125 m) |
| 측벽 | `y = ±3.5`, 높이 2.5 m, 데크 구간(`x ≤ 12`)에만 — 원근/지평선 기준 |
| 지면 끝 | `x = 120 m` — h0.3/d10에서 시선이 lip 24 m 너머에서야 아래층에 닿으므로, 짧은 앞치마를 두면 **지면이 있어야 할 자리에 하늘**이 찍힌다. 그건 단서가 아니라 아티팩트다 |

**단서 목록**: 난간(양쪽) · 경고블록 · 계단 코 그림자 · 측벽 원근선.

## 4. gz_drop2 — 플랫폼 단차, 난간 한쪽만

```
   railing(+Y 쪽만) ──────────┐ 
                             └┐ (lip 위 짧은 return, y=+1.30 → +0.35)
   ───────────────────────────┤
   deck z=0                   │  아래층 z=−0.80  →  x=120 까지
   ───────────────────────────┘
   −Y 쪽 lip은 완전히 무방비 (y = −8 … +0.35)
                            x=12.0
```

| 요소 | 값 |
|---|---|
| 낙차 | **0.80 m**, 전폭(`|y| ≤ 8`) 수직 단차, 계단 없음 |
| 난간 | **`+Y` 한쪽만** — `y = +1.30`에서 `x = 8 → 12` 주행 방향 런, + lip 위 짧은 return `x = 11.95`, `y = +1.30 → +0.35` |
| 무방비 구간 | lip의 `y = −8 … +0.35` 전부. 카메라 정면(`y=0`)은 **무방비 쪽**이다 |
| 경고블록 | **없음** (의도적) |
| 측벽 | drop1과 동일 |

**설계 의도**: drop1과 **단서 재고(cue inventory)가 다르다** — drop1은 난간+경고블록,
drop2는 난간 반쪽만. 같은 위험 깊이대에서 단서 밀도를 두 단계로 준 셈이라
"모델이 기하를 보는가, 단서를 보는가"를 두 씬 사이에서도 대조할 수 있다.
`+Y`쪽 난간이 프레임 오른쪽에만 나타나므로 **좌우 비대칭 응답**(섹터 A~E 편향)도 볼 수 있다.

## 5. 트윈 규약 준수

프로젝트 규약(`METRICS.md:237` — *same camera pose, same lighting, same seed; the only
difference is the hazard geometry*)과 08-23 신off 세대(위험만 제거, **장식 보존**,
`nightrun_0820/ctrl_dressing/README.md`)를 그대로 지켰다.

- `wall_py` 모델 이후 **꼬리 전체(측벽 + 난간 + 경고블록 + 카메라 9대)가 두 팔에서 바이트 동일**
  — 검산 완료.
- `gz_drop2` ↔ `gz_drop2_ctrl`의 diff는 **주석 한 줄 + `lower_floor` pose 한 줄**이 전부:
  `<pose>66 0 -1.1 …</pose>` → `<pose>66 0 -0.3 …</pose>`.
- `gz_drop1` ↔ `gz_drop1_ctrl`은 지면 분해가 다르다(구멍을 뚫으려면 데크를 쪼개야 한다):
  `deck_left/right/near/far + tread1..3 + pit_floor` → `deck` 하나. **윗면 z=0은 동일**하고
  장식·카메라·조명은 바이트 동일.
- **난간 기둥 발을 전부 데크(`z=0`) 위에 세운 것**이 이 규약을 지키기 위한 핵심 설계다.
  계단 위를 타고 내려가는 경사 난간을 달았다면, 계단이 사라질 때 기둥이 공중에 뜨거나
  움직여야 해서 트윈이 깨진다. 그래서 난간은 **접근로 가드**로만 두고 lip에서 끊었다
  — 끊기는 난간 자체가 강한 맥락 단서이기도 하다.
- 따라서 두 대조군은 **"단서는 있는데 위험은 없는" FA(오경보) 프로브**로 바로 쓸 수 있다.
  순수 기하 대조군이 필요하면 `make_worlds.py`에서 dressing 블록을 빼고 재생성할 것.

## 6. 프리셋별 V/E/H 성격 (예측 — 실측 아님)

정의(`OVERNIGHT_BRIEF_0819_v3.md` 부록 A3): **V** = 위험 **내부면** 픽셀 가시 ·
**E** = 내부면 비가시 + **개구 경계(림)**만 가시 · **H** = 위험 기여 픽셀 전무, 맥락 단서만.
판정은 계층적 V → E → H. 운영 임계값 `TAU_INT_DEF = 50 px`, `TAU_EDGE_DEF = 0.05`
(`labeling/labeler.py:66-68`).

기하 계산: 눈 `(−d, h)`과 lip `(0,0)`을 잇는 시선은 lip 너머 `x`에서 깊이 `x·h/d`에 있다.
따라서 깊이 `D`의 내부 바닥은 **`x_vis = D·d/h`** 부터 보이기 시작한다.

### gz_drop1 (D = 0.72, 피트 바닥 lip+0.90…8.00, 끝벽 lip+8.00)

| view | h/d | x_vis (lip 너머 m) | 피트 바닥 보임 | 끝벽 노출 높이 | 끝벽 픽셀 추정 | 예상 티어 |
|---|---|---|---|---|---|---|
| `extra_h0.3_d1.2` | 0.250 | 2.88 | 2.88–8.00 | 0.72 m(전부) | ~59,000 | **V** (강) |
| `preset_h0.3_d2`  | 0.150 | 4.80 | 4.80–8.00 | 0.72 m | ~50,000 | **V** (강) |
| `preset_h0.3_d5`  | 0.060 | 12.00 | 안 보임 | 0.48 m | ~19,700 | **V** (끝벽만) |
| `preset_h0.3_d10` | 0.030 | 24.00 | 안 보임 | 0.24 m | ~5,100 | **V** (얇은 띠) |
| `preset_h0.9_d2`  | 0.450 | 1.60 | 1.60–8.00 | 0.72 m | ~50,000 | **V** (최강) |
| `preset_h0.9_d5`  | 0.180 | 4.00 | 4.00–8.00 | 0.72 m | ~29,600 | **V** |
| `preset_h0.9_d10` | 0.090 | 8.00 | 경계 | 0.72 m | ~15,400 | **V** |

계단 tread 3장은 어느 프리셋에서도 시선 아래에 잠긴다(가장 깊은 tread3도 `x_vis`보다 앞).
즉 **보이는 것은 계단면이 아니라 피트 바닥과 끝벽**이다 — h0.3 grazing의 전형.

|---|---|---|---|
| `extra_h0.3_d1.2` | 0.250 | 3.20 | **V** |
| `preset_h0.3_d2`  | 0.150 | 5.33 | **V** |

| `preset_h0.9_d2`  | 0.450 | 1.78 | **V** (강) |
| `preset_h0.9_d5`  | 0.180 | 4.44 | **V** |

### 정직한 한계 — **이 4개 월드는 E도 H도 안정적으로 만들지 못한다**

낙차가 0.72–0.80 m인데 눈높이가 0.3–0.9 m면 **그림자대(shadow zone)가 짧다.**
어느 프리셋이든 내부면 픽셀이 τ_int = 50을 훌쩍 넘는다 → 전부 **V**.
이건 설계 실수가 아니라 기하의 결론이고, 다음 증분의 조건을 정확히 알려 준다:

- **E를 만들려면**: 폭 `W`인 **좁은 트렌치**(먼 쪽 lip도 `z=0`). 노출되는 먼 벽 높이가
  `W·h/d`이므로, `W·h/d`가 서브픽셀이 되도록 `W`를 잡는다. h0.3/d10(`h/d=0.03`)이면
  `W ≈ 1 m`에서 먼 벽이 ~5 px 높이 → E. → `gz_drop3` (폭 0.8–1.2 m 균열/트렌치) 제안.
- **H를 만들려면**: lip 앞에 **차폐물**(생울타리·파라펫·주차 차량 박스)을 세워 위험 픽셀을
  0으로 만들고 맥락 단서만 남긴다. **H가 이 연구의 핵심 대상**이므로 우선순위가 높다.

두 증분 모두 `make_worlds.py`에 월드 하나씩 추가하면 되고, 트윈 규약은 그대로 지켜진다
(차폐물은 dressing, 트렌치는 hazard).
