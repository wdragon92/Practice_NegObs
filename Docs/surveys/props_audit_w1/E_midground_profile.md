## 0. 결론 3줄 (먼저 읽을 것)

1. **중경 지면은 채워도 소용없다.** h0.3에서 5~20 m 대역의 *지면*은 프레임 세로의
   **7.1 %(1080 px 중 76 px)** 뿐이다 `[실측]`. 근경(0.56~5 m)이 67.7 %다.
   중경 충전은 **수직 요소 전용 작업**이다 — 줄눈·패치·데칼을 중경에 넣는 것은 예산 낭비다.
2. **낙차 씬의 중경은 "비어 있는" 게 아니라 "차폐선 아래"다.** 근경 연단을 스치는
   시선 아래는 무엇을 놓아도 안 보인다. 씬별 **인지 최소높이**를 계산했다
   (09 = 4.3~5.2 m, 14 = 5.1~6.0 m, 19 = 6.7~7.9 m, 03 = 2.3~3.2 m, 18 = 1.8~2.6 m).
   지금 그 씬들에 깔린 벤치(0.45)·볼라드(0.90)·관목(0.7)은 **전부 이 문턱 아래**다.
3. **차단 요인 1건 — 활엽 가로수 에셋이 없다.** 유일한 활엽수
   `Trees/Japanese_Cherry.usd` 의 잎 텍스처 `cherryblossom.png` 는 평균 RGB
   **(0.913, 0.494, 0.644)**, 분홍 픽셀 **93 %** `[실측]` = **벚꽃 확정, 규약 위반**.
   나머지 2종은 침엽수다. 가로수 열 처방은 **에셋 조달 전에는 실행 불가**(§8).

### 1.4 중경 배치 유효 판정식 (코드에 그대로 옮길 것) `[추정 — 위 모델의 도출]`

요소 중심 (x, y), 상단 z_top 이 `preset_h0.3_d` 컷에서 **유효**하려면 셋 다 만족:

```
① 화각      |atan((y − gy) / (x + d))| < 30.0°
② 차폐선    z_top > z_ray(x),  z_ray(x) = z_e + (z_e − 0.3)/(x_e + d) · (x − x_e)
             (x_e, z_e) = 근경 연단(낙차 시작점). 평지면 z_ray ≡ 0.3 → z_top > 0.3
③ 각크기    프레임 세로 점유 ≥ 3 % (=32 px). 그 미만은 안티에일리어싱에 묻힌다.
```

③은 실무적으로 **"D m 거리에서 높이 ≥ 0.10·D m"** 로 근사된다(오차 5 % 이내).
→ **12 m 지점의 요소는 최소 1.2 m, 20 m 지점은 최소 2.0 m 여야 화면에 남는다.**

- Wikimedia Commons 의 한국 가로 경관 파일은 표본이 얕고(검색 8건 중 다수가 1945년
  역사사진·테헤란 사진 등 무관 파일) **현행 가로 상태의 유형별 n≥15 표본을 구성할 수 없었다** `[실측: Commons search API 결과]`.
- Mapillary 는 API 토큰 필요 — 이 환경에서 미보유.

대체 근거로 **(a) 재고 통계 → 선밀도·출현률 환산**(§3.1 가로수 13.9 %,
§3.5 승차대 68.3 %)과 **(b) 배치를 사실상 결정하는 법령 간격 규정**(4~8 m, 1.5 m,
20~25 m 등)을 썼다. 이는 사진 카운트보다 **절차적 배치 코드에 더 직결되는 형태**지만,
"유형별 출현 여부"의 표본 검증은 **미완**이다. → §9 후속 작업으로 이관.

## 5. 실루엣 해체 — 스카이라인 다층화 사양

### 5.1 문제의 정확한 정의

h0.3에서 **지평선은 항상 247 px(위에서 22.9 %)의 수평 직선**이다 `[실측]`.
이 선을 **끊는 것은 z_top > 0.3 m 인 지물뿐**(평지) 또는 **z_top > z_ray(x)**(낙차 씬).
scene09가 "무대 배경막"으로 읽히는 이유는 **그 조건을 만족하는 지물이 57~72 m 에 있는
생울타리 3장과 건물 2동뿐**이어서, 스카이라인 전체가 **한 거리대**에서 나오기 때문이다
(runmax 302 = 폭의 15.7 %가 헤지 상단 한 직선) `[실측]`.

### 5.2 해체 규칙 (S1~S4)

**S1 — 3거리대 규칙 (필수)**
스카이라인을 구성하는 지물이 **5~10 m / 10~20 m / 20~60 m** 세 대역에서 각 1개 이상 나올 것.
어느 한 대역이 스카이라인 열의 **60 % 초과 점유 금지**.
→ 검산: `skyline.py` 의 열별 최초 비하늘 행을 대역별로 라벨링(프림 거리 기준).

**S2 — runmax ≤ 320 px** `[추정 — §1.6 도출]`
현재 초과: 18(844) · 12(664) · 19(452) · 14(405) · D3(337).

**S3 — 수직 리듬 비등간격**
가로수 종간 4~8 m 는 **범위**다 `[법령]`. 등간격 배치는 CG 서명이므로
`det_rng` 로 4~8 사이 지터를 준다(기존 전역 규약 3 「격자 금지」와 정합).

**S4 — 대기원근 금지 (음성 결과 재확인)**
서울 실측 b_ext = 2.97e−4(청명) ~ 7.91e−4 m⁻¹(스모그) `[논문: Visibility study in Seoul,
1993, Atmospheric Environment]`. Koschmieder 로 90 m 원경 대비 손실 **2.6~7 %**.
→ **원경 헤이즈·페이드·색보정 도입 금지.** 원경이 흐리면 원인은 대기가 아니라
**디테일 부족**이며, 처방은 S1(거리대 추가)이지 안개가 아니다.
