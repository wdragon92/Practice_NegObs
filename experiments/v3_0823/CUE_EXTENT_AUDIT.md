## 승용 요약 (다섯 문장)

1. **as-built v3 코퍼스에서 "위험 있는 프레임이 단서 픽셀을 더 많이 갖는" 상관은 실재하고 크다** —
   프레임 수준 점이연 **r_pb = 0.4135**(위험 평균 **20.97 %** vs 무위험 **6.60 %**, Cliff δ 0.636)로,
   씬 안에서 위험 라벨만 섞은 귀무 3,000회의 **q99 = 0.1009**을 네 배 넘어선다.
2. **그러나 그 상관의 대부분(0.4135 → 0.1495, 64 %)은 씬 설계가 아니라 2×2의 빈 칸 때문이다** —
   현재 무위험 프레임은 사실상 전부 **D팔(위험·단서 동시 OFF)**이고, **C팔(위험 無·단서 有)이 아직
   안 찍혔다**. 신규 씬 프로브에서 실측한 **κ = 1.0022**(C팔 단서 면적 ÷ A팔 단서 면적 = 1.00)로
   그 칸을 채워 투영하면 r_pb는 **0.1495**로 내려간다.
3. **2×2가 완비된 신규 씬(H1·H2·H3·H6·H7·L1·N9·N11)에서는 상관이 이미 통과다** — r_pb = **−0.112**
   (귀무 q99 = 0.1795), 그리고 **A팔과 C팔의 씬별 단서 면적이 소수점까지 일치**한다
   (예: H1 20.19 % / 20.22 %, N11 30.08 % / 30.17 %). 즉 **신규 씬 설계 자체는 밀도 대칭을 지켰다.**
4. **남는 잔차(0.1495, 여전히 문턱 초과)의 정체는 두 가지로 좁혀졌다** — ⓐ **팔 수 불균형 7씬**
   (scene03·04·10은 A팔만 있고 B팔이 0, scene06·08은 그 반대) ⓑ **씬 출신별 밀도 격차** —
   정본 33씬 A팔 평균 **27.06 %** 대 신규 H씬 A팔 **10.40 %**(비 2.60배, δ 0.655). 상관 제조 1·2위는
   `sceneC4`(Δ−0.042)·`sceneC1`(Δ−0.036)이다.
5. **문턱은 손으로 정하지 않았다** — 씬 내 셔플 귀무의 **q99 = 0.1009**을 "계통적으로 높다"의 판정선으로,
   **\|Cliff δ\| ≥ 0.147**(Romano small)을 실질성 하한으로 제안한다(§8, 등재는 **제안만** 하고 적용하지 않았다).
   **T키(`cue_material_break`)는 면적 계기가 원리적으로 볼 수 없다**(재질 재바인딩 = 프림 불변) —
   존재 \|r\| 쪽 값(W1-B2 0.0692)이 유일한 근거다.

## §0. 무엇을 어떻게 쟀나

### 0.1 계기

컷별 ID 마스크 사이드카 `.idseg.npz`(`instance_id_segmentation`)가 **프림 경로를 그대로 돌려준다**
(P-5 세그 스모크 실증 · `W1B2_SEGFILL_REPORT §2.2`). 프레임마다 프림 경로별 픽셀 수를 세고,
프림을 단서 키에 귀속시켜 합산한다. 면적 단위는 **프레임 대비 %**(1 프레임 = 1920×1080 = 2,073,600 px).

| 지표 | 정의 |
|---|---|
| `cue_area_total` | 단서로 귀속된 프림의 픽셀 합 ÷ 2,073,600 × 100 |
| `cue_area[key]` | 같은 것을 키별로 |
| `cue_obj_count` | 보이는 단서 **개체** 수. 개체 = 씬 하위 최상위 컴포넌트(`Rail_0`·`Planter_C`), 단 신규 씬처럼 cue **네임스페이스**를 쓰는 경우 한 단 더 내려간다(`Dress/Bench_0`) |
| `cue_group_count` | 개체명 끝의 인덱스를 떼어 묶은 **설치군** 수(`Reed_2_35`→`Reed_2`→`Reed`) |

> **개수 지표의 한계를 먼저 적는다.** 정본 33씬은 설치물을 씬 루트에 직접 놓고, 신규 씬은 cue
> 네임스페이스 아래 모은다. 네임스페이스 보정을 넣었지만 두 세대의 "개체" 입자 크기는 완전히
> 같지 않다. **면적이 주지표이고 개수는 병기 지표다.**

### 0.2 프림 → 단서 키 귀속 — 네 겹, 프림 단위로 출처를 남긴다

| 겹 | 근거 | 강도 |
|---|---|---|
| ① `declared` | 신규 8씬의 **`GATED_ZONES`** 표 `(tag, cue_key, …)` — 렌더 **전**에 선언되고 씬 자신의 `datum_selfcheck()`가 기계 검사한다 | 최강 |
| ② `empirical:armdiff` | **팔 차분** `visible(A,i) \ visible(B,i)`. 같은 씬·시드·밴드·조건·포즈에서 B는 프림을 **지우는 일만** 하고, 제거는 가림을 풀 뿐 만들지 않으므로 그 차집합은 **정확히** 그 프레임에서 B레버가 지운 단서 프림이다 | 측정 |
| ③ `lexical:prims2` | `code/prims2.json`(CUE_COVERAGE 부속) — 가드 본문 + 호출된 `build_*` 본문의 프림 경로 | 추정 |
| ④ `lexical:global` | 33씬 명명 관례 토큰 사전 | 추정 |

**강등 두 규칙(③④에만 적용 · ①②는 면제)** — 추정층의 과잉 매칭을 기계로 잘라낸다.

| 규칙 | 논리 | 실측 |
|---|---|---|
| **D팔 생존** | 전 cue OFF + 위험 OFF인 D팔에도 보이면, 어떤 cue 토글도 만들지 않는 프림이다 | **63건** 강등 (예: `scene01/Band_4` = 프레임의 20.4 %인 지면 밴드) |
| **레버 모순** | B레버가 키 k를 껐는데 그 컴포넌트가 **B팔에 그대로 보이면** k가 만든 프림이 아니다 | **27건** 강등 (예: `scene20/Diag/*` = 대각 계단 = 위험 기하인데 `prims2`가 장식 가드 본문에서 잘못 주워 왔다 — 프레임의 33 %) |

**계기 검산(홀드아웃)**: ②를 **떼어낸** 렉시컬 단독 귀속기로 팔 차분 **528쌍**을 다시 재면
픽셀 recall **0.9899**. 즉 렉시컬 추측만으로도 99 %는 잡지만, 나머지 1 %(sceneD2 0.775 ·
sceneD3 0.952)를 위해 경험층이 필요했다. 경험층이 등록한 프림 **2,689개** 중 키가 안 갈린 것은
**13개**(`Ux` 버킷, 전 코퍼스 면적 기여 0.04 %)뿐이다.

### 0.3 면적-불가시 키 — **T는 이 계기로 잴 수 없다**

`cue_material_break`는 32씬 중 **24씬에서 프림을 만들거나 지우지 않고 재질 바인딩만** 바꾼다
(`CUE_COVERAGE §0-3` 헤드라인 5). ID 마스크는 **기하·카메라만의 함수**이고 조명·재질에 불변이다
(`W1B2_SEGFILL_REPORT §2.2 ③` — 프림 경로 정규화 후 15/15 완전 동일). 따라서 **T의 면적 r은
정의상 0이며 그것은 "통과"가 아니라 "측정 불가"다.** 존재 \|r\| 쪽 실측(W1-B2 **0.0692**)이
T에 대한 유일한 근거로 남는다. §4.9-3의 "상수 키 별도 표기"와 같은 자리에 **면적-불가시 키**로 적는다.

## §6. 규정 감사 트랙(REG_AUDIT)과의 상호작용

`REG_AUDIT.md` · `CUE_REGULATION_BASIS.md`가 **본 감사 집필 중(00:27–00:31)** 착지했다. 세 지점에서

### AC-CUEX-2 — 통계

```
주지표 : r_pb(hazard, cue_area_total %)  — 존재 |r| 의 연속판(0/1 × 연속의 피어슨)
병기   : ① 주변분포(팔×위험 분할 포함) ② 키별 r ③ 상수 키 ④ **면적-불가시 키**
         ⑤ Cliff δ (분포무관 · 면적 분포가 심하게 치우쳐 있다)
         ⑥ cue_obj_count · cue_group_count (개수판)
금지   : r 단독 인쇄. T키를 "면적 r = 0 이므로 통과"로 읽는 것.
귀속   : declared > empirical(팔 차분) > lexical. 강등 2규칙(D팔 생존·레버 모순) 필수.
         **홀드아웃 검산(렉시컬 단독 recall)을 매 회 인쇄** — 현재 0.9899 / 528쌍.
```

### AC-CUEX-3 — 문턱 (**"계통적으로 높다"의 정의**)

```
VG-cuex :  |r_pb| ≤ 0.1009   AND   ( |r_pb| ≤ 0.1009  OR  |Cliff δ| < 0.147 )
```

| 항목 | 값 | 유도 근거 (자의 아님) |
|---|---:|---|
| 주문턱 | **0.1009** | **씬 내 셔플 귀무 3,000회의 q99.** 씬 구성·카메라 밴드·팔 구성이 만드는 구조는 유지한 채 위험–면적 결속만 끊은 분포다. q50 = 0.0608 · q95 = 0.0881 · max = 0.1167 |
| (참고) 자유 셔플 문턱 | 0.0578 | 씬 구조까지 지운 귀무의 q99. **더 엄격하나 씬 효과를 지름길로 오인**하므로 주문턱으로 쓰지 않는다 |
| 실질성 하한 | **\|δ\| ≥ 0.147** | Romano(2006) small-effect 경계. r이 문턱을 넘어도 δ가 이 아래면 *"보이지만 작다"*로 분류 |
| 현재 판정 | **0.4135 ❌** (δ 0.636) | as-built. C 투영 후 **0.1495 ❌**(여전히 초과) · P2 **0.112 ✅** |

**왜 q99인가**: q95(0.0881)는 20회 중 1회 오경보를 허용한다. 키별까지 6–13회 판정하므로 다중
비교에서 오경보가 쌓인다. q99는 3,000표본에서 상위 30번째 값이라 추정 안정성도 확보된다
(max 0.1167과의 거리 0.016).

**왜 씬 내 셔플인가**: 자유 셔플은 "정본 33씬이 신규 씬보다 단서가 많다" 같은 **씬 구성 효과**까지
지름길로 세어 문턱을 비현실적으로 낮춘다(0.0578). 씬 내 셔플은 그 구조를 남기므로, 문턱 초과 =
**"씬 구성으로 설명되지 않는 계통적 초과"**로 읽을 수 있다.

## §10. 한계 (한 번만 적는다)

1. **T키는 잴 수 없다.** 면적 계기의 구조적 사각지대다(§0.3). "T 면적 r = 0"을 통과로 읽으면 안 된다.
2. **C팔 수치는 정본 33씬에 대해 투영이다.** κ = 1.0022는 신규 씬 8개에서 잰 값이고, 정본 33씬의
   C팔(`keep_dressing` 이식 15건 포함)이 같은 κ를 가질지는 **W1-C가 착지해야 안다**.
3. **P2는 규정 감사 전 상태다**(§6 ③). `*reg_*` 확정 라운드 + 라벨이 착지하면 §3이 바뀐다.
4. **개수 지표는 명명 관례에 민감하다**(§0.1). 면적이 주지표다.
5. **`Gk`·`Ux` 버킷은 미분해다.** `Gk`(GKit 지면 패턴)는 `Manhole/Gully/Joint`로 갈리는 부분만 갈랐고
   나머지는 한 버킷이다. `Ux`는 팔 차분이 단서로 확정했으나 키가 안 갈린 13프림(면적 0.04 %)이다.
6. **H6·H7은 A팔뿐**이라 (A,C) 대칭을 못 쟀고, 씬 유형별 이상치 판정의 표본이 작다(H(new) 5씬).
7. **본 감사는 `.idseg.npz`가 정본 프레임에 대응한다는 W1B2 §2.2의 "기하 대응" 판정을 승계한다.**
   그 판정 기준 자체(상신 B2-1)가 아직 결재 전이다.
