# gz_drop* — Gazebo Classic drop-off 씬 사양 (WEEKEND_BRIEF_0823 §6.7-c, D37 증분 포함)

8개 월드 (하자드 4 + 트윈 대조군 4). 전부 `../make_worlds.py`가 생성한다 —
**`.world`를 손으로 고치지 말고 생성기를 고칠 것.**

```
gz_drop1.world  gz_drop1_ctrl.world   계단 4단 × 0.18 = 0.72 m 낙차 → 우묵한 피트      [V 티어]
gz_drop2.world  gz_drop2_ctrl.world   플랫폼 단차 0.80 m, 난간은 +Y 한쪽에만            [V 티어]
gz_drop3.world  gz_drop3_ctrl.world   0.72 m 피트를 0.61 m 화단벽으로 가림 (D37①)      [H 티어]
gz_drop4.world  gz_drop4_ctrl.world   0.25 × 1.00 m 개방 트렌치, 0.70 m 깊이 (D37②)    [E 티어 (원거리)]
```

`gz sdf -k` 정적 검사 8/8 통과. SDF 1.6 / Gazebo Classic 11.10.2.
**`<include>`·`model://`·메시 0건** — 인라인 box/cylinder + 스톡 `Gazebo/*` 머티리얼뿐.
이유: `bumperbot_description/launch/gazebo.launch.py`가 `GAZEBO_MODEL_PATH`를 **덮어쓴다**.
부작용으로 저들 런치 없이도(`ros2 launch gazebo_ros gazebo.launch.py world:=...`) 그대로 열린다.

## 1. 좌표 규약

- **+X = 진행/시선 방향.** lip(낙차 시작 모서리) = **`x = 12.0 m`**, 데크 윗면 = `z = 0`.
- 코퍼스는 lip을 `x = 0`에 두고 눈을 `x = -d`에 둔다(`scene_common.grid_views`).
  여기서는 씬 전체를 **+12 m 평행이동**했다. 이유 하나뿐: `gazebo.launch.py`의
  `spawn_entity.py`가 로봇을 **`(0, 0, 0.15)`에 하드코딩**해 스폰한다. 12 m 밀어 두면
  로봇은 가장 먼 카메라(`x = 2.0`)보다 **2 m 뒤**에 서므로 어떤 프레임에도 안 들어온다.
- 따라서 어떤 뷰든 **표준거리 d = 12.0 − (카메라 x)**.
- 8개 월드가 **같은 좌표계·같은 카메라**를 쓴다. 월드 간 비교가 곧 기하 비교다.

## 5. gz_drop3 — 가려진 피트 [H] `(D37①)`

```
        rail(양쪽) ──────────┐        planter 0.61 m
   ─────────────────────────┐│  ███                     
   deck z=0                 ││  ███   (뒤는 안 보인다)   deck z=0
   ═══════[warn strip]══════╪╪══███══╤═══════════════════
                        11.30  11.60  12.0        15.0
                                      lip   pit z=−0.72
```

| 요소 | 값 |
|---|---|
| 낙차 | **0.72 m** — 피트 `x ∈ [12.0, 15.0]`, `|y| ≤ 0.90`, 바닥 `z = −0.72` |
| **가림막(화단벽)** | `x ∈ [11.60, 12.00]` (두께 0.40), `|y| ≤ 1.10`, 벽돌 몸통 0.55 m + 식재 캡 0.06 m = **실루엣 높이 0.61 m**. 먼 면이 lip과 **정확히 flush** |
| 난간 | 양쪽 `y = ±1.30`, `x = 8 → 12`에서 **lip에서 끊긴다** — 화단벽 옆/위로 보인다 |
| 경고블록 | **화단벽 앞** `x ∈ [11.30, 11.60]` — 카메라 쪽이라 모든 프리셋에서 보인다 |
| 피트 길이 | **3.0 m로 짧게** — 끝벽이 h0.9 시선의 그림자 안에 머물러야 한다 (§8.2 유도) |

**왜 0.61 m인가** (두 조건의 교집합):
1. `h0.3`(눈 0.30 < 0.61) → 눈이 벽 **아래**. 실루엣은 **가까운 위 모서리**(11.60, 0.61),
   시선 기울기 `(0.61−0.30)/a > 0` → **올라간다** → `z ≤ 0`인 것은 그 뒤로 영원히 안 보인다.
2. `h0.9`(눈 0.90 > 0.61) → 눈이 벽 **위**. 실루엣은 **먼 위 모서리**(12.00, 0.61),
   기울기 `(0.61−0.90)/a < 0` → 내려간다. 피트 끝벽(x=15)에 닿기 전에 `z=0`을 못 지나야 한다
   → 가장 빡빡한 `h0.9_d2`에서도 여유 **+0.175 m (≈ 60 px)** 확보.

**단서**: 경고블록(항상 보임) · 화단벽 자체(모서리 보호물) · **lip에서 끊기는 난간**.
PS §6-3 "추론 가능한 가림" 요건 — 위험은 안 보이지만 **추론할 근거는 프레임 안에 있다**.

```
   ─────────────────────────────┐ ┌────────────────────
   deck z=0    [warn strip]     │ │   deck z=0  → x=120
   ═════════════════════════════╧═╧════════════════════
                    11.40‥11.70  12.0 12.25
                                  trench z=−0.70
```

| 요소 | 값 |
|---|---|
| 개구 | **0.25 m (X 방향) × 1.00 m (횡방향)**, 깊이 **0.70 m**, `x ∈ [12.00, 12.25]`, `|y| ≤ 0.50` |
| 정체 | 보도 슬래브 사이 벌어진 신축이음 / 빠진 그레이팅 한 줄 — 전형적 wheel-trap |
| 난간 | 양쪽 `y = ±1.30`, `x = 8 → 12` (drop1과 동일) |
| 경고블록 | `x ∈ [11.40, 11.70]` — **lip에서 0.30 m 물러나 있다** |

**경고블록을 물린 이유(중요)**: 6 mm 두께라도 lip 위에 **올려두면** 스침 시선의
실루엣이 lip이 아니라 슬래브 위 모서리가 되어 노출 밴드가 약 **5배 줄어든다**.
그러면 이 월드의 E는 트렌치 기하가 아니라 **점자블록 두께의 산물**이 된다. 0.30 m
물려서 슬래브 그림자가 lip에 닿지 않게 했다(그림자 끝 ≈ x 11.90 < 12.00).

## 7. 트윈 규약 준수 (8개 월드 전부)

프로젝트 규약(`METRICS.md:237` — *same camera pose, same lighting, same seed; the only
difference is the hazard geometry*)과 신off 세대(위험만 제거, **장식 보존**,
`nightrun_0820/ctrl_dressing/README.md`)를 그대로 지켰다.

- 4쌍 모두 **`wall_py` 모델 이후 꼬리 전체(측벽 + 장식 + 카메라 9대)가 바이트 동일** — 검산 완료.
- `gz_drop2` ↔ ctrl의 diff는 **주석 한 줄 + `lower_floor` pose 한 줄**이 전부.
- drop1/3/4 ↔ ctrl은 지면 분해만 다르다(구멍을 뚫으려면 데크를 쪼개야 한다):
  `deck_left/right/near/far (+hazard)` → `deck` 하나. **윗면 z=0은 동일**.
- **난간 기둥 발을 전부 데크(`z=0`) 위에 세운 것**, **화단벽을 데크 위에 세운 것**이
  이 규약을 지키기 위한 핵심 설계다. 위험 기하에 얹힌 장식은 위험이 사라질 때 같이
  움직여야 해서 트윈이 깨진다.
- 따라서 네 대조군은 전부 **"단서는 있는데 위험은 없는" FA(오경보) 프로브**다.

### gz_drop3 트윈의 특이성 — 읽기 전에 반드시 알아둘 것

gz_drop3는 위험이 **완전히** 가려지므로, 하자드 팔과 대조군 팔은 **렌더 결과가 사실상
픽셀 동일**해야 한다(피트는 보이는 표면에 그림자도 못 던진다). 즉:

- **Δ(트윈 차)는 구성상 0이다.** 이 쌍은 *판별력*이 아니라 **단서만 보고 얼마나 발화하는가**를
  잰다. 08-05 교리("가드 = 낙차 단서")의 직접 시험이다.
- **부수 효과 — 공짜 QA 훅**: 두 프레임이 픽셀 동일하지 **않으면** 가림이 샌 것이다.
  `capture_plan.md` §4에 검사 절차를 넣었다.
- Δ ≠ 0인 쌍을 원하면 `--d3-occ`로 벽을 낮춰 `h0.9_d2`부터 새게 만들면 된다.

## 8. 프리셋별 V/E/H 예측 (계산값 — 실측 아님)

정의(`labeling/labeler.py:383` `tier_of`):

```
int_px == 0 and edge_vis == 0            -> H
int_px >= TAU_INT                        -> V
edge_ratio >= TAU_EDGE                   -> E
else                                     -> H_weak
```

**임계값은 `TAU_INT_DEF = 50`, `TAU_EDGE_DEF = 0.05` (labeler.py:68)이고, `int_px`는
`DS = 4`로 다운샘플한 깊이맵에서 센다 (labeler.py:65). 즉 50 px는 원해상도로 800 px다.**
아래 표의 `int_px /4grid`가 τ=50과 직접 비교되는 값이다.

기하: 눈 `(−d, h)`과 lip을 잇는 시선은 lip 너머 `x`에서 깊이 `x·h/d`. 따라서
- 노출되는 **먼 벽 밴드** = `min(D, F·h/d)` (F = 개구의 X 방향 길이)
- **바닥**이 보이기 시작하는 지점 = `x_vis = D·d/h`
- `int_px_DS = 밴드[m] × 횡폭[m] / (R² · rad_row · rad_col · 16)`, `R = d + F`

### 8.5 E는 왜 좁은 창인가 (정직한 한계)

`τ_int = 50 (/4grid)`은 원해상도 **800 px**에 불과하다. 각 프리셋에서 E를 유지할 수 있는
**개구 최대 면적**을 역산하면:

| view | E를 유지하는 최대 개구 면적 | (X 0.25 m 고정 시) 허용 횡폭 |
|---|---|---|
| `extra_h0.3_d1.2` | 0.002 m² | < 0.01 m |
| `preset_h0.3_d2` | 0.009 m² | < 0.03 m |
| `preset_h0.3_d5` | 0.117 m² | < 0.47 m |
| `preset_h0.3_d10` | 0.889 m² | < 3.55 m |
| `preset_h0.9_d2` | 0.003 m² | < 0.01 m |
| `preset_h0.9_d5` | 0.039 m² | < 0.16 m |
| `preset_h0.9_d10` | 0.296 m² | < 1.18 m |

즉 **d ≤ 2 에서는 어떤 실물 낙차도 E가 될 수 없다**(개구가 1~3 cm여야 한다 — 낙차가 아니라 틈새다).
`d = 5`에서 E를 얻으려면 횡폭을 0.47 m 이하로 줄여야 하고, 그러면 "보도를 가로지르는 트렌치"가
아니라 작은 구멍이 된다. 기본값은 조율자 사양대로 **~1 m 폭**을 유지했다.
E를 3개로 늘리고 싶으면:

```bash
python3 ../make_worlds.py --d4-lat 0.45     # preset_h0.3_d5 까지 E (횡폭 0.45 m)
```

이 결과는 캠페인이 §6.9 한계 세트에 이미 적어 둔 **"E 연약"**을 독립적으로 뒷받침한다 —
E는 라벨러 임계값 아래 좁은 기하 창에서만 성립하는 티어다.
