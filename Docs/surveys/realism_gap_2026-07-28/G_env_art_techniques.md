## 2. CG 티의 정본 체크리스트

### 2.1 베벨 — 단일 최대 요인 [확인]
모든 볼록 모서리에 실척 1~2 mm 베벨. 수학적으로 날카로운 모서리는 두 면 사이 어떤
방향으로도 표면적이 0이라 **스페큘러 하이라이트를 물리적으로 만들 수 없다**. 실제 모서리는
가공·주조·마모·도장 두께로 항상 미세 반경을 갖고, 그것이 만드는 가는 밝은 선을 눈이
"물리적 사물"로 읽는다. PBR에서 베벨은 **빛을 받는 면 방향의 수를 늘려** 그레이징 각
프레넬 응답을 추가한다. (Radiator Blog, tripo3d, novedge)
- AAA 우회법: Insomniac "ultimate trim"(GDC 2015) — 베벨 두께 변주를 트림 아틀라스에 베이크.
- **Isaac 이식**: ①히어로 프림을 베벨 메시로 교체·인스턴싱 ②에지 트림 노멀 스트립
  ③최저비용 = 상단 에지를 따라 45° 회전한 2~4 mm 보조 Cube. **[추정]**
- 우리 우선 적용 대상: **연석 상단 에지, 계단 노징, 난간 튜브 끝** = U-Net이 키로 삼을 실루엣.

### 2.2 텍셀 밀도 일관성 [확인]
| 용도 | 밀도 |
|---|---|
| 3인칭 | 512 px/m |
| 1인칭·히어로 | 1024 px/m |
| 배경 프롭 | ~512 px/m |
| 포트폴리오 상한 | 2048 px/m |

**절대 해상도보다 일관성이 중요** — 옆 바닥보다 4배 선명한 벽은 "장소"가 아니라 "콜라주"로 읽힌다.
**우리 위험**: 트라이플래너 `scale_m` 하나를 0.2 m 연석과 40 m 도로면에 같이 쓰면 200:1 불일치.
→ **오브젝트 월드 크기에서 스케일을 산출**하고 프로젝트 단일 목표치를 잡을 것.
로봇 카메라 1~5 m 스탠드오프면 **512 px/m**, 연석·노징만 1024. **[추정]**

### 2.3 불완전성·비대칭 [확인]
- "창문과 문의 크기·위치를 조금씩 다르게" = 생성된 게 아니라 지어진 것으로 읽히는 조건 (80.lv)
- 산포는 균등하지 말 것: "돌 하나 놓고 복제→축소→회전→약간 이동, 반복" (Level Design Book)
- **Isaac 이식**: 전 인스턴스 프림에 ±2~5% 스케일, ±0.5~2° 회전, ±1~3 cm 이동 지터.

### 2.4 접지부 — 베벨 다음으로 큰 효과 [추정, 단 §7 마스크 규칙은 확인]
지면과 폴리곤으로 깨끗이 만나고 어두워지지 않는 물체는 **붙여넣은 것**으로 읽힌다.
실제 접지부에는 AO 그라디언트 + 퇴적 오염 + 모르타르/보수 자국이 항상 있다.
→ 수직 프림마다 2~8 cm 폭 **오염 링**, 또는 MDL에서 월드 Z 5 cm 이하 base color 암화.

### 2.5 대기 원근 [추정 — 출처 확보 실패]
100 m 건물이 3 m 연석과 같은 국소 대비를 가지면 매트 페인팅으로 읽힌다.
한국 도시 기준 가시거리 500~2000 m 헤이즈, 50 m에서 3~5% 대비 손실만으로도 효과.

## 3. 식생 — 우리 구(球) 수관을 살리는 법

### 3.1 노멀 트랜스퍼 — 핵심 트릭 [확인]
잎 클러스터보다 약간 큰 프록시 **구**를 만들고 그 정점 노멀을 잎 카드에 전사.
(Blender `Data Transfer` → Face Corner Data → Custom Normals / Maya `Transfer Attributes` /
SpeedTree 내장 `Transfer Normals`)

**왜 통하는가**: 잎 카드는 평면이라 자기 노멀로 라이팅하면 딱딱하고 평평한 패싯 =
판지로 읽힌다. 눈은 수관이 **하나의 부드러운 볼록 볼륨**으로 음영지길 기대한다.
구 노멀을 전사하면 수백 장의 카드가 단일 형태로 음영져 개별 평면이 사라진다.
보고된 효과: "그림자 아티팩트 없고 더 폭신해 보인다". **결정적으로 공짜다 —
노멀만 바꿨지 지오메트리는 그대로다.**

계층형 고급판: 가지를 따라 icosphere 인스턴싱 → 각 구에 잎 카드 인스턴싱 →
구 노멀을 per-point 어트리뷰트로 저장 → 잎 셰이더 Normal 입력에 연결.
= 실제 수관처럼 **클러스터 단위 뭉침**.

**Isaac 이식 [추정]**: MDL에서 셰이딩 노멀을 `normalize(P - cluster_center)`로 치환.
구 전사의 해석적 등가물이며 지오메트리 저작이 전혀 필요 없다.
**우리가 할 수 있는 최고가치 식생 변경일 가능성이 높다** — 지금 구 수관을 유지한 채로도
음영이 즉시 자연스러워진다.

### 3.2 알파 밉맵 — 두 번째로 큰 식생 결함 [확인]
표준 밉맵 생성은 알파를 박스필터한다 → 알파 **분산이 평균으로 붕괴** →
거친 밉에서 `alpha < 0.5` 통과 텍셀이 줄어 **잎이 얇아지다 사라진다**.
예: 60/60/20/20% → 평균 40% → 0.5 컷오프 실패 → 불투명 커버리지 50% → 0%.
측정 사례: 꽃 줄기가 밉3에서 "형체 없는 덩어리", 밉5에서 완전 소실. (lisyarus)

Wyman & McGuire (IEEE TVCG 2017) 3원인 분해:
알파 분산 감소 / 이산 가시성(5픽셀 철망 → 1픽셀 → 소멸) / 거친 래스터 격자.

**해법 (실용 순)**:
1. **커버리지 보존 밉(Castaño/The Witness)** — 밉마다 base 커버리지를 재현하는 컷오프를
   이진탐색 후 `pixel.a *= (0.5f / cutoff)`. 소실 방지 보장. 부작용은 형상 약간 축소.
2. `mix(alpha, maxAlpha, 0.75)` 로 다운샘플 — 순수 평균보다 형상 보존.
3. alpha-to-coverage + MSAA.
4. Hashed alpha testing — 고정 0.5 대신 해시 임계값. TAA 필요.

**우리 함의 [추정]**: 잎 텍스처를 도입하면서 밉을 순진하게 만들면 **원경 나무가 성겨진다.
그런데 원경 수관 밀도는 우리 낙차 태스크의 깊이·스케일 단서다.** 잎 아틀라스는
커버리지 보존 밉을 오프라인(numpy 30줄)으로 생성해 명시적으로 실어야 한다.

### 3.3 양면 투과(역광 잎) [확인]
UE `Two Sided Foliage` 셰이딩 모델이 존재하는 이유: 일반 SSS는 "피부나 두꺼운 표면엔
맞지만 잎 같은 얇은 표면엔 부정확". `Subsurface Color`가 **투과량**을 정의하고
줄기·잎맥 마스킹 지점도 겸한다(잎몸보다 훨씬 덜 투과).
설정: Blend Mode = Masked, Shading Model = Two Sided Foliage, Two Sided = on.

**왜 결정적인가 [추정]**: 잎은 0.1~0.3 mm 반투명 조직이다. 태양이 뒤에 있으면
**하늘광 받는 면보다 밝고** 강하게 황록으로 시프트한다. 불투명 조명 잎은 역광면이
균일하게 어둡다 — CG 나무가 플라스틱으로 읽히는 1순위 원인.

**Isaac 이식 [추정]**: OmniPBR에 양면 투과 없음 → 잎 카드는 **OmniSurface**(투과/SSS 보유)
또는 `df::diffuse_transmission_bsdf` 를 확산 반사와 믹스한 커스텀 MDL.
시작값: 투과 틴트 ≈ (0.35, 0.55, 0.15) sRGB, 투과 가중 0.3~0.5, 잎맥·줄기 ~0.05.

### 3.4 근경 5 m vs 원경 50 m [추정]
- **5 m**: 수피 릴리프(~1 mm 스케일 노멀/시차) + **실루엣의 하늘 투과 구멍** + 투과 + 잎 방향 다양성.
  5 m에서 불투명 덩어리인 수관은 즉시 가짜.
- **50 m**: 전체 실루엣 형태 + 하늘 대비 명도 + 대기 원근. 텍스처 디테일은 무관.
  대신 §3.2 알파 밉 침식이 지배적.
- → **LOD 체인 하나가 아니라 두 종류의 나무 처리**가 필요할 수 있다.

## 4. 잔디

### 4.1 Ghost of Tsushima 레퍼런스 구현 [확인]
| 지표 | 값 |
|---|---|
| 동시 화면 블레이드 | **~83,000** |
| 프레임 비용 | **~2.5 ms** |
| 블레이드 표현 | **3차 베지어 4제어점 — 카드가 아니라 매 프레임 GPU 생성** |
| 근경 LOD | 15 정점/블레이드 |
| 원경 LOD | 7 정점/블레이드 |
| 짧은 잔디 최적화 | 남은 8정점으로 **옆에 두 번째 블레이드** 생성 |
| 드로우콜 | 83,000 → **1** (GPU 인스턴싱) |
| 뭉침 | **보로노이** 영역 — 클러스터 내 높이·방향·색 공유 |
| 원경 타일 | 2배 크되 **블레이드 수 동일**(밀도 감쇠) |
| 근→원 전이 | **4개 중 3개 드롭**, 점진 블렌드로 파핑 방지 |
| 컬링 | 거리 → 프러스텀 → 오클루전 → 종류/높이 |

**핵심**: 알파 카드 대신 절차적 지오메트리를 택한 이유가 **투명 픽셀 오버드로 제거**.

### 4.2 "초록 펠트" 회피 규칙
1. **산포하지 말고 뭉칠 것** — 보로노이/포아송 디스크, 클러스터 내 높이·방향·색 상관 [확인]
2. **아래 지면을 같은 톤으로** — 원경에서 잔디가 성겨지며 밝은 회색이 드러나면 "대머리 링"
3. **블레이드 밑동 AO** — 하단 10~20%를 중간부의 40~50%로 암화
4. **마른 블레이드 10~25%** 섞기 + 광엽 잡초 + 꽃 몇 송이. 단일종은 잔디밭도 아니다
5. **높이 분산 ±30~50%**, 클러스터 단위 상관
6. **길·연석·벽 근처는 성기고 밟힘** — 연석 접합부는 (a)성기고 (b)예초기가 못 닿아 바로 그 이음매에서 더 크고 (c)**이음매에서 자라 나온다**. → **잔디-연석 계면 자체가 강한 낙차 단서**
7. **매크로 틴트맵** — 10~50 m 스케일 노이즈로 색조 변조(균일 염색 방지)
(1은 [확인], 나머지 [추정])

### 4.3 기타 지피 [추정]
낙엽·자갈·잔가지·부스러기는 **모서리와 수직면에 쌓인다**(바람·통행이 가장자리로 민다).
공짜 비대칭 생성기이며 **지면이 끝나는 위치를 강화**한다.

## 5. 지면·포장

### 5.1 미세 기복 [추정]
- 노멀맵만(현 상태): 그레이징에서 절대 안 맞음. 지평선 실루엣이 완벽한 직선으로 남는다
- POM: 중간. 자기폐색 정확, 실루엣에서 깨짐
- 테셀레이션+변위: 정확, 비쌈
- **분할 지면 메시 정점 변위 ±5~20 mm, 파장 0.3~3 m** ← 지상 로봇 카메라에 필요한 건 이것.
  거의 공짜이고 **동시에 자연스러운 웅덩이 분지를 만든다**(§5.4).

### 5.2 타일링 파괴 — 4중 적층
**(a) 매크로 변주 [확인]**: 저주파 변주 텍스처를 **서로 다른 UV 배율로 3회 샘플 후 곱함**,
알베도에 약하게 오버레이(대비는 절반으로). 단일 그레이 채널 사용(RGB 아님). UE `T_Default_MacroVariation`.

**(b) 거리 타일링 [확인]**: 같은 텍스처를 근경 = 작은 타일, 원경 = 큰 타일로 샘플 후
Camera Depth Fade 크로스페이드. **fade offset 0이면 경계선이 생기고, 200(=2 m)이면 2 m에 걸쳐 블렌드.**
Sampler Source = Shared: Wrap 필수(16샘플러 한계).

**(c) 확률적 헥스 타일링 [확인] — §5에서 가장 이식가치 높음**
Heitz & Neyret (HPG 2018): 정삼각 격자(각 정점 = 헥스 타일 중심) + 타일별 무작위 오프셋 +
가장 가까운 **3개** 타일을 무게중심 가중 블렌드 + 히스토그램 보존. 절차노이즈 대비 **>20배 빠름**.
Mikkelsen, *Practical Real-Time Hex-Tiling* (JCGT 11(2), 2022, Unity): 히스토그램 전처리를 없애
**원본 텍스처를 셰이더 안에서 직접** 샘플. 논문 제시 파라미터:
**3 샘플/픽셀, 지수 블렌드 가중 γ = 7, 블렌드 확산 β = 0.6, Perlin S커브 대비 r ∈ [0.65, 0.75]**.
히스토그램 보존을 끄면 **타일별 무작위 회전**이 가능해져 "같은 자갈이 항상 같은 각도" 아티팩트가 사라진다.
노멀맵은 노멀이 아니라 **편미분을 블렌드**하고, 타일 오프셋 때문에 `SampleGrad()` 필요.
→ **MDL 약 40줄. β=0.6, γ=7, r=0.7, 회전 랜덤 on 권장.**

**(d) 디테일 노멀 [확인]**: 0.1~0.3 m 타일링 고주파 마이크로 노멀을 매크로 노멀 위에 블렌드
— 카메라가 다가가도 표면이 매끈해지지 않게.

### 5.3 재질 전이대 — 하드 폴리곤 에지가 결정적 티
**높이 블렌딩 [확인]**: 선형 블렌드가 아니라 `HeightLerp` — 레이어마다 높이 마스크를 갖고
픽셀마다 **더 높은 표면**을 택한다 → 자갈 알갱이가 잔디 경계로 **삐져나온다**(녹아들지 않고).
알려진 실패: 여러 레이어 높이가 동시에 0이면 **검은 점** 발생 → 높이 마스크를 0에서 띄울 것.

**경사 기반 블렌딩 [확인]**: 노멀 Z로 블렌드 → 급사면은 노출토/자갈, 평탄면은 잔디.
**이게 정확히 낙차 단서이며 공짜로 얻어진다.**

**Z높이 블렌딩 [확인]**: `Absolute World Position → Z` + 전이폭 파라미터.
전이 0 = 면도날 수평선, 40 = 흐림. `Saturate` 클램프.

**우리 씬용 전이 규칙 [추정]**:
- 자갈→잔디: 15~40 cm 블렌드대, 개별 자갈이 잔디 쪽으로 20~50 cm 침입, 잔디는 경계 20 cm 전부터 성겨짐
- **연석→아스팔트**: 절대 깨끗한 선이 아님 — (a)1~3 cm 실런트 줄눈 (b)연석면에 3~8 cm 흑색 그릿·타이어 고무 퇴적 (c)흔히 5~15 cm 밖에 평행 균열
- 연석→보도: 5~20 mm 침하 단차, 모르타르 비드, 줄눈 잡초
- 잔디→포장: 잔디가 포장 가장자리를 2~5 cm 덮음, 잔디 쪽 토양면이 포장보다 1~3 cm 높음

### 5.4 젖음·웅덩이 — 완전 출처 확보 [확인] (Lagarde, *Water drop 3a/3b*)
| 항목 | 값 |
|---|---|
| 알베도 암화 계수 범위(실측) | **0.2 ~ 1.0** |
| 마모 아스팔트 예 | 건조 0.12 → 젖음 0.08 (계수 0.68) |
| 알베도 < **0.039** | 젖으면 오히려 **밝아짐** |
| 물 F0 | 0.02 · 물 IOR 1.33 · 일반 유전체 IOR 1.5 |
| 다공성→확산 | `factor = lerp(1, 0.2, Porosity)`; `Diffuse *= lerp(1, factor, WetLevel)` |
| 금속 제외 | `factor = lerp(1, 0.2, (1-Metalness)*Porosity)` |
| 젖음 광택 | 1.0 쪽으로 블렌드 · 스페큘러 부스트 0.5 × WetLevel |
| 건조 곡선 | **시그모이드** — 스페큘러가 확산 암화보다 훨씬 빨리 사라짐 |

추가 [확인]: 암화는 **채널 의존·비선형** — 젖으면 더 어두울 뿐 아니라 **채도가 올라간다**.
효과는 **저알베도·거칠고·다공성**(아스팔트·벽돌·콘크리트)에서 최대, 매끈 비다공성에서 최소.
**젖음 마스크 레시피 = 높이맵 반전 + 대비 증가** (물은 낮은 곳에 고인다)
→ §5.1 정점 변위가 두 배로 값어치를 하는 이유.
얇은 수막은 교란된 표면 노멀 유지, 두꺼운 웅덩이는 평면 정점 노멀(거울 반사).
Unity 프로덕션 샘플: 웅덩이는 **평탄·상향면에만** 생성, 투수성이 흐름 속도를 결정.

**Isaac 이식 [확인 권고]**: base color를 **제곱**하는 것이 회색 상수 곱보다 나은 암화 근사.
```
albedo_wet    = lerp(albedo, albedo*albedo, wetness*porosity)
roughness_wet = lerp(roughness, 0.05, wetness*puddle_mask)
```

| 볼륨 국소 효과 | **Position** | 3D Distance = 구형 볼륨 마스크 |

Mask Builder 파라미터 범위 [확인]: Convex/Concave Range −1…1, Contrast 0…1,
Smoothness 0…16, Noisiness 0…1 / AO −1…1, AO Range·Contrast 0…1 /
Top-Down Gradient −1…1 / WSN 0…1 with **6방향 독립 강도(Top/Bottom/Front/Back/Right/Left)** /
Grunge 0…1, Grunge Scale 0…10, Scratches −1…1, Scatter −1…1.
**AO(HBAO) 필터 노드는 높이맵에서 AO를 절차 생성** — 베이크 불필요 [확인].

### 8.2 MDL 구현 (베이크 없이) [추정 — 단 위 규칙은 확인]
```
up          = state::normal().z                        // 상향면, [-1,1]
world_z     = state::position().z                      // 지면 위 높이
dust_mask   = smoothstep(0.6, 1.0, up)                 // 수평면 먼지/눈
verticality = 1.0 - abs(up)                            // 줄무늬는 수직면에만
splash_mask = 1.0 - smoothstep(0.30, 0.50, world_z)    // 30~50 cm 스플래시존
rain_streak = verticality * stretched_noise(x, y, z*0.15)  // Z로 6:1 신장
contact_ao  = 1.0 - smoothstep(0.0, 0.08, world_z)     // 하단 8 cm 암화
edge_wear   = 1.0 - smoothstep(0.0, 0.02, edge_distance)   // 2 cm 마모 밴드
```
**베이크 없는 curvature [추정]**: Box/Cylinder 프림은 모서리를 해석적으로 안다.
오브젝트 공간에서 최근접 모서리까지 거리로 `edge_wear` 산출 —
베이크한 curvature 맵과 같은 것을 공짜로 얻고, **§2.1 가짜 베벨의 마스크로도 겸용**된다.

### 8.3 방향 규칙 — 방향이 틀리면 오히려 이상해진다 [추정]
| 규칙 | 구현 |
|---|---|
| 줄무늬는 **항상 아래로** | 노이즈를 −Z로 4~10배 신장. 등방성 금지 |
| 줄무늬는 **발원점이 있다** | 턱·창대·볼트·용접·줄눈·물방울점. 위에 원인 없는 줄무늬는 틀리게 읽힌다 |
| 수평 돌출부 아래가 강함 | 창대·코니스·笠石·난간 베이스플레이트 — 물을 흘리므로 |
| 벽 밑동 스플래시존 | **30~50 cm**. 지면 반사 빗물이 진흙을 튀김. 더 어둡고 갈색이고 거칢 |
| 먼지는 상향면에 | `normal.z > 0.6`. 수평 턱·벽 상단·트레드 안쪽 모서리에 최강 |
| 하향면은 깨끗하되 어둡다 | 소핏·노징 밑면·난간 밑 — 비 세척도 먼지 퇴적도 없음, AO 높음 |
| **세척 구역** | 강한 낙수선 아래는 주변보다 **더 깨끗하다**. 웨더링은 단조증가가 아니다 |
| 노출량에 비례 | 남/서면은 UV로 빨리 바램, 북면은 축축하게 유지 |

### 8.4 이끼·잡초 배치 [추정 — 사진 검증 필요]
노이즈가 아니라 **물과 그늘을 따른다**:
1. **줄눈과 균열 먼저** — 보도블록 사이, 연석/아스팔트 이음매, 계단 라이저-트레드 모서리, 신축줄눈
2. **벽 밑동** 스플래시존과 같은 0~30 cm 대(지속 습윤)
3. **북향면**(북반구) — 볕이 적고 축축
4. **물체 아래·뒤** — 계단 돌출부 아래, 난간 뒤, 볼라드 그늘
5. **물이 흐르거나 고이는 곳** — 홈통 아래, 배수선, 경사 저지대
6. **통행면에는 절대 없음** — 트레드 중앙과 보행선은 이끼가 없다.
   **이 비대칭(가장자리 이끼·중앙 청결) 자체가 매우 강한 사실성 단서이며 낙차 기하를 인코딩한다.**
```
moss = joint_mask * (splash_mask + shade_mask) * (1 - traffic_mask) * noise
```

## 9. 렌즈·센서 — Isaac Sim 네이티브 기능 [확인]

(출처: Isaac Sim *Camera Sensors* 공식 문서)

**렌즈 왜곡**: `OmniLensDistortionOpenCvPinholeAPI` / `OmniLensDistortionOpenCvFisheyeAPI` 스키마를
`RtxCamera`에 `schemas` 파라미터로 적용, 계수는 `attributes`로 설정.
(범용 `OmniLensDistortionLutAPI`와 구 fisheye-polynomial 모델은 deprecated/비작동)

**카메라 프림 광학 파라미터**: `focalLength`, `fStop`, `horizontalAperture`, `verticalAperture`,
`focusDistance`, near/far 클리핑. `fStop`이 "거리 흐림 제어, 낮을수록 초점 범위 감소" = **DoF 제어**.

**완전한 ISP 시뮬레이션이 `omni.sensors.nv.camera` 확장에 존재**:
블랙레벨 차감 / 화이트밸런스 게인 / 컬러보정행렬 / 센서응답 스케일링 /
**설정 가능한 패턴의 Bayer CFA 인코딩** / **가우시안 및 샷 노이즈** /
톤커브 컴팬딩 / 디모자이크 / 디노이즈 / 톤매핑 / 컬러그레이딩.
**단서: 샘플 ISP는 Linux x86_64 전용** (← 우리 환경과 일치).

해당 문서에 독립 파라미터로 없는 것: 비네팅, 모션블러, 노출 제어.
모션블러는 Isaac Lab 카메라 설정의 `MotionBlurCfg` / 노출시간으로 가능 [확인].

> **권고**: 물리적으로 구조화된 ISP가 이미 있으므로 임기응변 후처리보다 이것을 쓸 것.
> 다만 **비네팅과 JPEG/압축은 별도 후처리로 추가** — ISP가 안 덮는다.

### 9.1 물리적으로 타당한 파이프라인 순서 [추정]
각 단계가 비선형이라 순서가 결과를 바꾼다.
```
장면 라디언스 (선형 HDR)
 → 렌즈: 왜곡 → 비네팅(cos⁴) → 색수차 → 디포커스(DoF) → 베일링 글레어/블룸
 → 셔터: 모션블러(노출시간) → 롤링셔터(행별 시간 오프셋)
 → 센서: 노출 게인 → 광자 샷노이즈(포아송, 신호의존) → 리드노이즈(가우시안, 신호무관) → 양자화
 → ISP: 블랙레벨 → WB → 디모자이크 → CCM → 디노이즈 → 톤맵 → 샤픈 → 감마
 → 코덱: JPEG/H.264 양자화 아티팩트
```
**순서를 뒤집으면(예: 톤매핑 후 가우시안 노이즈) 어떤 실제 카메라와도 안 맞는 노이즈 통계가 나온다**
— 노이즈는 톤커브 **이전 선형 공간**에 주입해야 하고 샷노이즈는 √신호로 스케일해야 한다.

### 9.2 랜덤화 범위 제안 [추정 — 효과별 ablation 표는 문헌에 부재]
1 m/s 지상 로봇 + 일반 롤링셔터 RGB 기준
| 효과 | 범위 |
|---|---|
| 비네팅 | 코너 10~35% 감쇠 (cos⁴) |
| 색수차 | 이미지 가장자리 0.5~2.5 px 측방 |
| 방사왜곡 k1 | −0.35 … +0.05 (실카메라 캘리브레이션에 맞출 것) |
| 모션블러 | 노출 **8~33 ms**; 1 m/s면 8~33 mm 이동. **회전(요) 블러가 병진보다 중요** |
| 롤링셔터 | 상→하 판독 15~30 ms |
| DoF | f/2.0~f/8.0, 초점 2~10 m |
| 샷노이즈 | 포아송, 신호 비례. **선형 공간·톤맵 이전 필수** |
| 리드노이즈 | 8bit 기준 σ 0.5~5 DN |
| 노출 | ±2 EV + 자동노출 지연/헌팅 시뮬 |
| AWB | 색온도 3000~8000 K 지터 (한국 씬은 주광·나트륨·LED 혼재) |
| 톤매핑 | ACES/Filmic, 대비 ±15% |
| JPEG | 품질 60~95 |
| 블룸·베일링 글레어 | 미묘하되 **햇빛 씬엔 필수** — 실제 렌즈는 밝은 하늘 주변에 베일을 만든다 |

**우리 셋업 최우선 3개 [추정]**: ①**노이즈 + JPEG** — Geirhos가 보인 CNN이 물고 늘어지는
고주파 통계를 바꾼다 ②**모션블러** — 지상 로봇 영상은 사실상 절대 선명하지 않다
③**노출/AWB 변주** — 고정된 완벽 노출이 렌더 데이터셋의 가장 명백한 합성 속성이다.
