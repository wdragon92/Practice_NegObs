## 0. 결론 — W2 가 먼저 알아야 할 8가지 (v1.1: 5 → 8)

1. **★ 차단 항목이 하나 있고, W1 이 낸 수치가 틀렸다.** `_ground_skin`(룩 레이어)이 flush 지면
   요소를 묻는다는 진단은 맞다. 그러나 특수조가 계산한 스킨 최고점 **+21.5 mm 는 과대**다 —
   변위 노이즈가 `rng.random()−0.5` 라 진폭이 `±0.5·amp_m` 이고, 옥타브 필터(`_wl_min =
   spacing×2.5 = 0.30 m`)가 0.19·0.07 m 옥타브를 전부 잘라 **1옥타브만 남는다**.
   실제 최고점 = `0.0115 + 0.5×0.010` = **+16.5 mm** `[실측 — scene_common.py:820-841]`.
2. **그래서 `GROUND_PROUD_FLOOR = 22.5 mm` 로 전 요소를 띄우는 처방(특수조 A안)을 채택하지
   않는다.** 그 안에서는 **음각 요소(줄눈·균열·세굴 홈)를 원리적으로 만들 수 없고**,
   양각 22.5 mm 짜리 줄눈은 d=2 m 에서 세로면이 **15 px** 로 서서 "포장 위 융기 격자"로 읽힌다
   `[계산 — 0.0225×f/2, f=1662.77]`. 채택안은 **P-A: 대상 슬래브의 스킨을 끈다**(§1).
3. **채워야 할 곳은 카메라 앞 0.56~2.00 m 띠 하나다** — h0.3 프레임 세로의 **53.9 %**
   `[계산 — §2.2, 3개 조사 독립 수렴]`. 요소를 x ≥ 0(위험 기하 주변)에 두면 프레임 상위 8 %
   에만 걸린다. `sceneN2` 가 요소 9종을 갖고도 σ_LF 1.36 인 정확한 기전이다 `[실측]`.
4. **ground_kit 은 "새 요소 라이브러리"가 아니라 "씬 유형 프로파일 → 기존 빌더 배치
   오케스트레이터 + 신규 소빌더"다.** `infra_kit` 의 6빌더는 이미 구현·문서화돼 있는데
   33씬 중 `sceneN4` 1건만 쓴다 `[실측 — grep]`. 재구현 금지, `import infra_kit` 로 흡수한다.
5. **W1 좌표를 그대로 옮기면 안 되는 것이 3건 발견됐다** — 낙차 에지 앞 0.8 m 금지대 위반
   (01·02·15), scene13 램프 노면 요소의 프레임 진입 오판(d2 만 유효), scene10 이 3개 근경
   조사 어디에도 없음. §5 매트릭스에서 전부 교정했다.
6. **★(v1.1) 위 5항의 교정 자체가 틀렸다** — 트렌치를 `x=−0.95` 로 옮긴 것은 GT-E1(0.80 m
   금지대)만 보고 GT-E2(전폭 횡단선 행 이격)를 보지 않은 것이다. d10 에서 Δ=**5.34행**
   `[계산 — row(9.05)=303.31 vs row(10.0)=297.97]` 으로 자기 게이트 B7 을 위반한다.
   **트렌치 중심 x = −2.55**(근단 에지 −2.40, Δ=16.05행)로 재이설하고, 계단머리의 배수 기능은
   **전폭 선이 아닌 점형 빗물받이 2기**로 대체한다(§5.0 C-1′).
7. **★(v1.1) 점자블록은 이제 "기본 OFF" 가 아니다** — 사용자 07-29 결정으로 **조사 기반
   선별 설치**로 바뀌었다. `build_tactile_pair` 호출 금지 하드코드를 폐기하고 **씬×지점
   등록부**(§12)로 대체한다. 법정 위치(계단 첫 단 0.3 m 전 전폭)는 돌기 6 mm 기준
   GT-E1′ 이격 0.24 m 를 넘으므로 **기하학적으로 안전**하다 `[계산]`.
8. **★(v1.1) scene10 은 `deck_timber`(P10)가 아니다** — h0.3 3컷 실측 결과 **d2 만 목재
   데크, d5·d10 은 공원 흙길+잔디**다(§13). 잠정 배정을 폐기하고 **P18 `deck_trail_hybrid`**
   를 신설한다.

## 1. ★ 차단 항목 — 스킨 간섭 해소 (W2 0번 작업)

### 1.1 스킨 기하 재실측 `[실측 — 코드 정독 + CPU 재계산]`

`scene_common.add_box()` 는 `LOOK_V1 and _skin_wanted(...)` 이면 슬래브 위에 변위 메시를 덮는다
(`:735`). `_skin_wanted` 통과 조건은 `sx,sy ≥ 4.0` · `sz ≤ 0.8` · 재질 클래스 ∈
`{paving, concrete, asphalt, soil, gravel, stone}` · 경로/재질명에 `_SKIN_DENY` 토큰 없음 (`:749`).

`_ground_skin` 상면 계산 (`:778-841`):

| 항 | 코드 | 값 |
|---|---|---|
| 기저 리프트 | `ztop = 슬래브상면 + max(0.0015, amp_m·1.15)` | **+11.5 mm** |
| 옥타브 필터 | `_wl_min = spacing·2.5 = 0.12·2.5 = 0.30` → `(0.55, 0.19, 0.07)` 중 **0.55 만 통과** | 1옥타브 |
| 변위 진폭 | `v ∈ [−0.5, +0.5]` (`g = rng.random(...) − 0.5` 의 이중선형 보간) → `v·amp_m·0.6⁰` | **±5.0 mm** |
| **스킨 표면 범위** | | **+6.5 ~ +16.5 mm** |
| 경계 테이퍼 | 슬래브 경계에서 변위 → 0, 안쪽 `edge=0.05 m` 들여깜 | 경계에선 정확히 +11.5 mm |

→ **특수조 §2.1 의 "+1.5 ~ +21.5 mm" 는 진폭을 2배로 본 값이다.** 결론(맨홀 매몰)은 동일하게
성립하지만 처방 수치가 바뀐다.

현행 flush 요소 proud 는 전부 이 아래다 — `sceneN5` 실측: 줄눈 0.6 mm · 맨홀 틀 1.2 / 뚜껑 2.0 /
보스 3.0 mm · 차도 파선 2.6 mm `[실측 — sceneN5_flush_grating.py:79-102]`.
A/B 렌더 근거(특수조 §2.1): 룩 ON 에서 맨홀 2개 암부 화소 5.88 % → **0.02 %**, |∇| p99 −82 %.

### 1.2 채택안 — **P-A: 대상 슬래브 스킨 OFF**

| 안 | 내용 | 판정 |
|---|---|---|
| **P-A ★채택** | ground_kit 이 장식하는 지면 슬래브를 `_skin_wanted` 에서 **명시 제외**. flush 요소는 물리적으로 옳은 proud/recess(0.6~3.0 mm, 음각 포함) 로 되돌린다 | **채택** — 음각 구현이 가능한 유일 안. 스킨이 하던 "평면감 파괴"는 ground_kit 요소 + T1 디테일 노멀이 대체한다 |
| P-B 폴백 | 스킨 유지 + `GROUND_PROUD_FLOOR = 0.018`(=16.5+1.5) 로 전 요소 양각 | 뚜껑·패치·도색만 산다. **줄눈·균열·홈파기는 포기**. P-A 가 회귀를 내면 이쪽 |
| P-C | `_ground_skin(amp_m)` 0.010 → 0.003 | **비권장** — 33씬 전 지면 픽셀 변화 + Phase1 E9 "정점 변위가 최대 시각 기여" 상쇄 |

**P-A 구현(코드 4줄, `scene_common.py`)**

```python
SKIN_EXCLUDE = set()          # 모듈 전역. 씬이 ground_kit 적용 전에 등록한다.

def skin_exclude(*paths):     # 공개 API — ground_kit 은 이 함수를 '주입'받는다
    SKIN_EXCLUDE.update(str(p) for p in paths)

# _skin_wanted() 첫 줄에 추가
    if str(path) in SKIN_EXCLUDE or any(str(path).startswith(p) for p in SKIN_EXCLUDE):
        return False
```

**`_SKIN_DENY` 에 토큰 1개 추가** — `"gkit"`. ground_kit 이 만드는 프림은 전부
`{ROOT}/GKit/...` 아래 두므로, ground_kit 산출물 자신이 **2차 스킨을 뒤집어쓰는 사고**를
구조적으로 막는다(도막·마모 띠처럼 4 m 이상 대면적을 만드는 빌더가 있다).

**ground_kit 쪽 규약**: `apply_ground(..., skin_exclude=None)` 로 콜백을 주입받는다
(scene_common 미의존 원칙 유지). 씬 코드는 `gk.apply_ground(..., skin_exclude=sc.skin_exclude)`.

## 3. 모듈 구조

### 3.1 규약 (`infra_kit` 승계, 예외 없음)

- **Z-up · m · 진행축 +X.**
- **`scene_common` 미import.** 프리미티브는 `Kit` 주입. `import infra_kit as ik` 는 **허용**
  (역참조 없음 — 순환 안 생긴다). `Kit`·`det_seed`·`det_rng`·`_bay_joints`·`kit_from_scene_common`
  는 **재구현 금지, 재수출**.
- **RNG 100 % 결정적** — `hash()` 금지, `zlib.crc32 → random.Random` 만.
- **모든 프림은 `{prefix}` 아래**, `prefix` 는 `{ROOT}/GKit` 고정(§1.2 스킨 방어).
- 각 함수 docstring 에 **`GT:` 줄** + **개당/미터당 프림 수** 명시.
- 치수는 **`GROUND_DIMENSIONS` 원장에만** 둔다. 원장에 없는 수치를 기본값으로 넣는 것 금지.
- **알베도 하드클램프 `≤ 0.30`** — 순백 대면적 금지 규약을 코드가 강제한다. 0.30 초과 요청은
  `ValueError`.
- **금지 API**: `lid=False` 계열(무개구) · 볼라드 **신규 배치**(기존 볼라드의 돔캡·기초
  플랜지 추가는 C5 소관, ground_kit 범위 밖) · 사람/차량 오브젝트 · 계절 특정 산포
  (단, 04·07 갈변 낙엽·C1 눈·C2 낙엽은 씬 정체성으로 예외).
- **(v1.1 변경) `build_tactile_pair` 는 금지 API 가 아니다.** 사용자 07-29 결정으로
  "기본 OFF" 가 폐기되고 **선별 설치**가 됐다. 대신 **호출은 §12 등록부 `TACTILE_SITES`
  에 등재된 (씬, 지점) 조합에 한정**되며, 등재되지 않은 좌표로 호출하면
  `plan_ground` 가 `ValueError` 를 던진다. 프로파일 플래그로는 켤 수 없다(§3.4).

### 4.5 **역방향 계약 — ground_kit → T1 유닛 지터 원장** (v1.1 신설)

`t1_material_layer_spec_v1` v1.1 §1.8·§8.1 이 확정한 계약이다. MDL 유닛 지터
(`unit_cell_m`·`unit_albedo_sigma`)는 **절차적 격자**로 셀을 자르는데, ground_kit 은
**기하 줄눈**으로 같은 면을 자른다. **두 격자의 주기와 원점이 어긋나면 이중 격자가 보인다** —
1 m 급 셀 위에 3 m 급 줄눈이 위상 무관하게 겹치면 근경에서 모아레·오프셋 이음매로 읽힌다.

> **계약**: ground_kit 은 씬·표면별로 **`unit_cell_m`(셀 주기, m)** 과
> **`unit_cell_origin`(격자 원점 오프셋, `(ox, oy)` m — 씬 좌표계)** 을 원장으로 제공한다.
> T1 MDL 은 이 두 값을 그대로 입력받아 자기 해시 격자를 정렬한다.
> **원점 없이 주기만 넘기면 계약 불이행**이다(MDL 기본 원점은 UV 원점이지 씬 원점이 아니다).

**원장 스키마 확장** — `GROUND_DIMENSIONS` 항목에 두 필드를 추가한다:

```python
GROUND_DIMENSIONS = {
    # key: (값, "확인|추정", "출처")                      ← infra_kit 과 동일 3튜플
    "module_granite_slab": (0.600, "확인", "KCS 34 6-5-1 / scene14 실측 600"),
    ...
    # (v1.1) 유닛 지터 계약 — 프로파일별 1행
    "unit_cell": {                    # profile -> (cell_m, (ox, oy), 출처)
        "plaza_granite":  (0.600, (0.0, 0.0), "판석 모듈 600 [규격]"),
        "sidewalk_block": (0.300, (0.0, 0.0), "보도블록 300 그리드 [법령 ZZ §9.3]"),
        "alley_concrete": (3.000, (0.0, 0.0), "시공줄눈 step_x 3.0 [시방]"),
        "street_asphalt": (None,  None,       "무모듈 — 지터 비적용"),
        "bridge_deck":    (None,  None,       "무모듈 — 지간 이음만"),
        "deck_timber":    (0.145, (0.0, 0.0), "판재 폭 0.145 [시방 KCS 34 5-2-1]"),
        "levee_paved":    (0.200, (0.0, 0.0), "인터로킹 200×100 [규격]"),
        "roof_membrane":  (None,  None,       "도막 — 격자 없음(§5.6 줄눈 금지)"),
        ...
    },
}
```

**정합 규칙(코드가 강제)** — `python3 ground_kit.py` 자기검산이 어서션한다:

| # | 규칙 | 근거 |
|---|---|---|
| U1 | `unit_cell_m` 은 **해당 프로파일의 포장 모듈 치수와 동일**해야 한다. 프로파일이 `pave.module` 을 저작했는데 `unit_cell` 값이 다르면 `ValueError` | 두 값의 출처가 같아야 이중 격자가 안 생긴다 |
| U2 | `pave.step_x/step_y`(줄눈 주기)는 `unit_cell_m` 의 **정수배**여야 한다 | 줄눈이 셀 경계 위에 떨어져야 어긋남이 0. 예: 판석 0.600 셀 + 시공줄눈 1.8 m(=3배) ✔ / 1.5 m(=2.5배) ✘ |
| U3 | `unit_cell_origin` 은 **줄눈 격자의 원점과 동일**해야 한다(`build_joint_grid` 가 쓰는 원점) | 주기가 맞아도 위상이 어긋나면 반 칸 오프셋 이음매가 생긴다 |
| U4 | `unit_cell = None` 인 프로파일에서 T1 이 지터를 켜면 **T1 쪽 FAIL** | 무모듈 포장(아스팔트·도막)에 셀 지터는 물리적으로 틀렸다 |

**U2 의 즉시 효과 — §5.1 P1 처방 수정**: v1 은 "신축줄눈 6 m + 시공줄눈 **1.5~2 m**" 였는데
판석 셀 0.600 기준으로 1.5 m 는 2.5배라 U2 위반이다. → **시공줄눈 1.8 m(3배) 또는 2.4 m(4배)**
로 고정한다. 신축 6.0 m 는 10배라 통과 ✔ `[계산]`.

### 6.1 δ — 전 요소 z 상한

> **모든 ground_kit 요소는 `기존 지면 z − GT_DELTA ≤ z ≤ 기존 지면 z + GT_DELTA`,
> `GT_DELTA = 0.020 m`.**

근거: ① 프로젝트 minor-step 임계 **0.10 m** 의 **1/5** `[실측 — infra_kit 규약]`
② P-B 폴백의 `GROUND_PROUD_FLOOR = 0.018` 을 포함 ③ 맨홀 flush ±10 mm `[규격 KS D 4040]` 의 2배 이내.

**명시 예외 4종**(그 외 예외 금지) — **(v1.1) 예외별 에지 안전 이격을 함께 못박는다.**

레드팀 §2.2 반증: 예외 3종은 `EDGE_STANDOFF = 0.80` 의 유도 전제(`z_e = 0.020`)를 **3~6배
초과**한다. 같은 0.80 m 를 쓰면 잡초(h0.12)는 d10 에서 에지를 가린다. **높이별 이격표**로 정합시킨다.

| 예외 | z 상한 | **필요 이격 `\|x_e\| ≥ EDGE_K·z_e` (m)** | 무여유 값(d10) | 사유 |
|---|---|---|---|---|
| 강체 지면 요소(기본) | +0.020 | **0.800** = `EDGE_STANDOFF` | 0.667 | GT_DELTA |

`EDGE_K = 1.20 · d_max / h = 1.20 × 10 / 0.3 = 40.0` `[계산]` — **1.20 은 v1 이 0.667 → 0.80 으로

| `\|x_e\|` [m] | 0.30 | 0.80 | 1.5 | 2.4 | 3.0 | 4.8 이상 |
|---|---|---|---|---|---|---|
| 허용 상면 z [m] | 0.0075 | 0.020 | 0.0375 | 0.060 | 0.075 | 0.12 (잡초 상한) |

`apply_ground` 는 `gt_delta_max` 를 반환하고, `> GT_DELTA`(예외 미등록 요소)면 **생성 전에**
예외를 던진다. 예외 등록 요소는 **GT-E5 램프**로 검사한다.

### 6.2 낙차 에지 인접 대역 — 금지대와 GRAZE 정합

**(a) 하드 금지대 — 기하학적으로 유도** `[계산]`

프리셋 eye `(−d, gy, h)`, 낙차 에지 상단을 `(0, y, 0)` 이라 하면 에지를 향한 시선의 지면 위
높이는 `z_ray(x) = −h·x/d` (x<0). 높이 `z_e` 인 요소가 `x_e` 에 있으면
`z_e > h·(−x_e)/d` 일 때 **에지를 가린다**. `z_e = GT_DELTA = 0.020`, `h=0.3`, 최악 `d=10`:

```
−x_e > z_e·d/h = 0.020×10/0.3 = 0.667 m     →  안전여유(×1.20) 포함 EDGE_STANDOFF = 0.80 m
```

> **규칙 GT-E1′ (v1.1 개정 — z 조건부)**: 낙차 에지 전방 요소는
> **`|x_e| ≥ EDGE_K · z_e`** (`EDGE_K = 1.20·d_max/h = 40.0`) 를 만족해야 한다.
> `z_e = GT_DELTA = 0.020` 이면 0.80 m 로 **v1 의 하드 금지대를 정확히 재현**하고,
> **더 낮은 요소는 더 가까이 올 수 있다**(점자블록 돌기 6 mm → 0.24 m, 오염 데칼
> 0.6 mm → 0.024 m). 음각 요소(줄눈·균열·판재 틈)는 `z_e ≤ 0` 이라 **무제한 허용**하되
> **에지와 평행한 전폭 횡단선은 GT-E2 로 따로 판정**한다.
>
> **v1 대비 무엇이 바뀌었나**: v1 의 "x ∈ [−0.80, 0] proud>0 금지"는 **모든 높이에 같은
> 이격**을 매겨, ① 6 mm 점자블록의 법정 위치(0.30 m)를 원천 봉쇄하고 ② 잡초(0.12 m)를
> 0.80 m 에서 허용해 **d10 에서 에지를 실제로 가리는** 이중 오류를 냈다 `[레드팀 §2.2]`.

**(b) GRAZE v2 와의 정합** `[실측 — regression_check.py:180-200]`

GRAZE v2 의 E 대역은 지면거리 `[0.7d, 2.2d]`, 즉 씬 좌표 `x ∈ [−0.3d, +1.2d]`.
d=2/5/10 을 합치면 `x ∈ [−3, +12]` — **근경 충전 영역과 거의 전부 겹친다.**
v2 는 등방 클러터(낙엽·자갈·오염)를 열 평균으로 상쇄하므로 안전하지만,
**화면을 가로지르는 새 직선**은 상쇄되지 않는다. 따라서:

> **규칙 GT-E2 (v1.1 개정 — 12행 → 16행)**: 각 h0.3 프리셋의 E 대역 안에 들어가는
> **신규 전폭 횡단 직선 ≤ 1본**, 그 **경계선**(폭 있는 띠는 근단·원단 각각)의 투영 행이
> 에지 투영 행에서 **`Δ ≥ GRAZE_ROW_SEP = 16행`** 이격.
>
> **v1 의 "12행" 은 산술 오류였다** `[레드팀 §2.3]`. 괄호 근거
> "`GRAZE_HW 3 + SMOOTH 3 + SLACK 2` 의 2배"는 **16**이지 12가 아니다. 필터 footprint 가
> ±8행이므로 **두 신호가 완전 분리되려면 16행**이 필요하다. B7 은 하드 게이트이므로
> 값-근거 불일치를 남기지 않는다. **값을 근거에 맞춰 올린다.**
>
> **판정은 요소의 풋프린트가 아니라 그 경계선에 건다** — 폭 0.6 m 띠는 근단·원단 두 선
> 각각이 16행 조건을 만족해야 한다.

> **규칙 GT-E2-x (v1.1 신설 — 등재 예외, 법정 필수 요소 한정)**
>
> `Δ < 16행` 을 **법정 필수 요소에 한해** 허용한다. 현재 대상은 **§12 점자블록 하나뿐**이다
> (계단 첫 단 0.3 m 전 — 법이 위치를 못 박으므로 이설이 불가능하다). 조건 3개를 **전부**
> 만족해야 하고, `TACTILE_SITES` 등재가 곧 예외 등재다:
>
> 1. **GT-E3 만족** — 휘도 단차가 낙차 에지 단차의 50 % 이하.
> 2. **`EXPECTED_FP` 등재** — 이 요소가 **hazard-off 쌍둥이에서 GRAZE 오탐을 낼 것**을
>    씬·컷·행 단위로 **사전 등록**하고, 라운드 판정에서 **신규 오탐으로 세지 않는다**.
> 3. **씬당 1본** — 등재 예외선도 GT-E2 의 "전폭 횡단선 ≤ 1본" 한도를 소비한다.
>
> **왜 이 예외가 정당한가**: 평탄지의 노란 점형 띠가 강한 수평선을 만드는 것은 **현실 그대로**
> 이고, 그것이 바로 데이터셋이 요구하는 **`cue+ / label−` 사분면**(목표 ≥ 20 %)이다
> `[cue_arrangement_survey §2.5]`. 네트워크는 "노란 띠 ≠ 낙차" 를 배워야 한다.
>
> **왜 트렌치·줄눈에는 안 주는가**: 이들은 **선택적 장식**이다. 등재 예외를 열어 주면
> `Δ<16` 인 모든 선이 "융합되니 괜찮다" 로 통과하는데, **hazard-off 쌍둥이에서는 융합할
> 에지가 없어 그 선 자체가 단독 에지 신호**가 된다 — GT-E4 가 잡으려는 바로 그 실패다.
> 그래서 C-1′ 은 트렌치를 **이설**한다(레드팀 권고 ⓐ 채택). **레드팀이 "비권장" 으로
> 판정한 선택지 ⓒ("근경 쪽 방향 완화")를 채택한 것이 아니다** — ⓒ 는 무조건 완화이고,
> GT-E2-x 는 **법정 강제 + 오탐 사전 등재**를 요구하는 폐쇄 목록이다.

> **규칙 GT-E3**: 신규 횡단선의 휘도 단차는 낙차 에지 단차의 **50 % 이하**.
> `frame_budget` 이 요소 알베도 비로 근사 검산한다. **GT-E2-x 등재 요소에는 강제 적용**한다 —
> 근접 배치는 에지 신호를 **증폭**하므로 증폭량을 50 % 이하로 묶는다.
>
> **규칙 GT-E4 (라운드 규칙)**: ground_kit 최초 적용 라운드는 **GRAZE before/after 비교를
> 유보하고 after 를 새 baseline 으로 삼는다.** 대신 **동일 라운드 hazard-off 쌍둥이**(승인 완료)
> 와 비교해 "낙차가 없는데 에지 신호가 생겼는가"를 본다 — 이것이 진짜 검사다.
> 선례: 낙엽 전역화가 FRAME·OCCL 을 같은 사유로 re-baseline `[실측 — leaf_globalization_budget_v2]`.
>

### 12.6 조건부 확률 정합 — **씬 수준으로는 달성 불가** `[계산]`

목표 `[cue_arrangement_survey §2.5]`: `P(낙차|점형) = 0.20~0.35` · `P(점형|낙차) = 0.30~0.45`.

33씬 구성은 **낙차 28 / 무낙차 5**(N1~N5)다. 점형블록을 낙차 씬 `K_h` 개, 무낙차 씬 `K_n` 개에
두면(hazard-off 쌍둥이 포함, 총 조건 28×2+5 = 61):

```
P(점형|낙차) = K_h / 28              → 0.30~0.45 이려면  K_h = 9 ~ 12
P(낙차|점형) = K_h / (2·K_h + K_n)   → K_n ≤ 5 이므로 K_h=9 일 때 최소 9/23 = 0.391
```

**`K_n` 의 상한이 5 라서 `P(낙차|점형)` 이 0.35 아래로 내려갈 수 없다.**
본 등록부는 `K_h = 9`, `K_n = 4` → `P(점형|낙차) = 0.321` ✔ · `P(낙차|점형) = 0.409` ✘(초과).

**해결 경로는 변주 렌더뿐이다** — `cue_tactile` 은 이미 **전 씬 토글**이므로, 무낙차 씬
5개에 대해 **점자블록 ON 컷을 낙차 씬보다 많이 렌더**하면 씬 수와 무관하게 비율을 맞출 수 있다.
필요 배수: `P(낙차|점형) = 0.30` 을 만들려면 무낙차·점형 컷이 낙차·점형 컷의 **2.33배**.
→ **결재 안건 M10** 으로 올린다(본 스펙은 렌더 예산을 임의로 늘리지 않는다).

**4분면 강제 채우기**(각 칸 ≥ 15 %) 관점의 본 등록부 기여:
`cue+/label−` 칸은 **16(주출입구 전면) + N1·N2·N4·N5(볼라드 전면)** = 5건으로 확보되고,
`cue−/label+` 칸은 미설치 19씬 중 낙차 씬 전부로 압도적이다. **17·05·09·10·12 를 OFF 로
둔 것이 이 칸을 채운다** — "점자블록 없는 옹벽 상단·데크 끝" 이 정확히 목표 사례다.
