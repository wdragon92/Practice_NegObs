### 1.3 The mechanism

`veg_wrapper_rel(usd_rel, names, kind)` returns an `add_vegetation`-ready path to a thin
layer under `assets/veg_bare/` that carries the `over ... (active = false)`; the layer
composes normally (it is not an instance), the scene references *it*, and every instance
then shares one prototype that never had the sub-prim. `_veg_wrapper_write` authors a
missing wrapper as text — deliberately not via `Usd.Stage.CreateNew`, because this module
is imported by the CPU-only harness where `pxr` is a stub. Every failure path returns
`None` and the caller falls back, because **a missing wrapper must never cost a scene its
vegetation**. `BARE_NATIVE` supplies the bare `zmax` so the canopy-top cue survives.

scene04's three wrappers were **not touched**; `Rhododendron_noflower.usda` is the one
new file, pre-authored and committed so the runtime author path is a no-op on a clean

### 5.2 NF-2 — the true annular sector

The box convention overshoots the a0/a1 rays at the inner radius by
`(margin·r_out − r_in)·sin(Δθ/2)`, a ratio of `margin·r_out/r_in` that **does not contain
Δθ** — which is why §10.5's box fallback ("cap Δθ so the r_in overwidth ≤ 1.05×") is
unreachable at any `seg`. `_annular_sector_mesh` + `mesh=` on `build_arc_steps` /
`build_helix_steps`. Measured on T3's landing case (r_in 0.48 · r_out 3.30 · 0–180° ·
seg 24), usd-core 26.8:

| | box | mesh |
|---|---|---|
| overshoot past a0 / a1 | **+190.4 mm** | **0.0 mm** |
| r_min / r_max | 0.5290 / 3.3075 | **0.4800 / 3.3000** |
| top-face z | 4.998000 | **4.998000** |

190.4 mm reproduces T3's union-extent figure exactly. Radii and top-face z are held, which
is the GT-invariance GT-6 asks for. One limit recorded: `UsdGeom.Mesh` points are float32,
so the mesh path quantises to **≤ 0.24 µm** at r 3.3 m — four orders below the 0.020 m GT
tolerance, but it is a real difference from the Cube path's double xformOps.

### 5.3 NF-1 — and a correction to T3's prescription

`build_helix_ramp` places the box **centre** and then tilts about it, so the top face is
displaced. T3 §3 prescribes compensating `cz` by `(t/2)(1/cosθ − 1)` **and** the
tangential origin by `(t/2)·sinθ`. **Applied together those double-count**: the tangential
move slides the sloped plane, changing its height at the placement azimuth by `−tanθ·ds`.
Measured on the fascia ring (t 0.78, tilt −14.05°): raw defect **+12.03 mm**, and T3's
pair over-corrects to **−23.7 mm**. Solving both conditions simultaneously —

```
z(u) = cz + (t/2)/cosθ + (u − s)·tanθ ,  s = (t/2)·sinθ ,  z(0) = z_top
  =>  cz = z_top − (t/2)/cosθ + s·tanθ = z_top − (t/2)·cosθ
```

so the z term is **`+(t/2)(1 − cosθ)`**, not `−(t/2)(1/cosθ − 1)`. Verified: lift
**+12.028 mm → 0.000**, tangential offset **+94.68 mm → 0.000**.

### 5.4 Why both are default OFF, and the GT-6 split proof

GT-6's acceptance test is a prim-hash / GT-delta diff that must be **empty except the
enumerated +2 mm landing-top rows**. Those rows come from a **scene06 parameter**
(`top_z` 4.998 → 5.000), not from the library — `scene_common` cannot author them. And a
default-ON Cube→Mesh conversion necessarily rewrites the inventory, which would make
GT-6's own proof impossible to run. So the correct diff for *this* commit is the empty
one, and 05 / 06 / 19 flip the levers inside their own pilots where the split proof is
judged. This is exactly the K4M precedent (mechanism lands, default OFF, identity proof).
