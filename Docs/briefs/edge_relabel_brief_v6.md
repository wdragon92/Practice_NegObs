**v4 → v5 개정 사유 (대화 회귀 감사 — 이 대화에서 실제로 났던 사고의 재발 차단):**
⑳ '지시 대기 공회전' 재발 방지 — 개시 규칙 명문화 ㉑ '의도를 결정으로 오독'한 전례 차단 — YOLO 논문의 최종 역할(비교 baseline vs 파이프라인 단)은 **미정**임을 §7에 명시, 실험은 역할 결정과 독립 ㉒ 폐기·보류 목록에 '트윈'이 이중 등재로 읽힘 — 폐기는 구(舊) 설계, 재도입 여부는 보류임을 구분 ㉓ 탐지율 교차 격자 {0.25~0.90}가 P1 위반으로 오독될 여지 — 보고용 [방법] 상수임을 주석.

**v5 → v6 개정 사유 (원 논문 확보 + 승용 결정):**
㉔ '창고'가 어느 논문의 환경인지 문서 단독으로 결속되지 않았다 → §1.2에 원 논문 서지·환경 계보 명기 ㉕ 원 논문 확보로 사양 승격 — **클래스 1개(논문 Table 2)** · YOLOv8n · COCO 사전학습 · 100 epochs · batch 16 · 사다리꼴 ROI 전처리를 **논문 레시피 [문헌]**으로 채택, 논문 자체 보고(일관 탐지 0.3–0.8 m · 원거리에서 구멍이 세로 스트립에 묻힘)와 이미지 수준 split(우리 월드 분할이 더 엄격)을 한계·서사 재료로 등재 ㉖ **가림축 실험 신설 [승용]** — H_cand 프레임을 가림 비율 축으로 실측(경계 채택엔 불사용), 가림 유도 포즈를 렌더 계획에 포함(씬 수정 없음).

## §0. 승용 요약 (5문장)

1. 연구의 북극성: **"E 상황(낙차의 edge 라인만 보이는 상황)에서 negative obstacle의 edge를 정밀하게 인식하고, 낙차의 존재를 판정할 수 있는가"** — 폴라그리드·구 티어 규칙·구 라벨은 전부 폐기다.
2. 이 문서의 일은 셋: 새 V/E/H 정의로 **전량 재라벨**(모집단은 P0 센서스로 확정), 라벨 품질의 **전수 실측**, V/E 경계를 정하기 위한 **YOLO 탐지 한계 실험 — 베이스라인 논문의 Gazebo 창고 씬을 그대로 렌더해서 잰다** [승용: A트랙].
3. 최상위 원칙: **기준(문턱·허용오차)은 우리가 정하지 않는다** — 실측 분포와 문헌 관례로 보고하고, 채택은 승용 결재다(§3-P1).
4. 진행은 게이트식: 센서스 → G0 → 4씬 파일럿(오버레이 검수) → G1 → 전량 → G2 → 창고 렌더 계획 G3a → 실험 → G3에서 V/E 경계 채택.
5. V/E는 지금 가르지 않고 원시 수치로 저장한다(store raw, bin later); H는 "외부 가림물이 있으면 H"를 원칙으로 하되 표시(H_cand)만 하고 최종 판정은 승용 큐로 보낸다.

## §1. 최소 배경 — 무엇이 바뀌었나 (처음 보는 독자용)

이 저장소의 기존 실험(폴라그리드 출력, 단서 기반 U-Net, 트윈 설계, 아모달 보조)은 설계 비판과 판정 불가로 종료됐고, 연구는 새 세션으로 재시작한다. 과거 문서·코드를 읽는 것은 자유이나 **그 규칙·상수·라벨을 이식하지 않는다.**

- 북극성 [승용]: 1단계 = **존재 판정 + edge 라인 정밀 인식.** 영역 칠하기·기하 추정은 2단계로, 1단계가 되면 넘어간다.
- 폐기 [승용]: 폴라그리드 전 버전 · 구 티어 규칙(int_px / edge_ratio / any_pos / H_weak / none_in_fov) · 구 티어 라벨 전량 · 트윈 전제 구(舊) 설계(도구로서의 트윈 재도입 여부는 아래 '보류' 항목) · 코덱스가 만든 edge 산출물.
- 보류 [승용]: H 심화(가림물 라벨링) · 아모달 · sceneH3형(완전 은닉) · 음성 세트(닮은 가짜 선) · 트윈.
- 유지: 계단 씬 자산 · Isaac Sim depth·지오메트리 정답 · 낙차 위험 문턱 **0.3 m** [문헌·기존 확정] · 문서 관행(승용 요약 선두 · 출처 태그 · 결재란 · **모든 산출 문서는 한국어**).
- 일정 관리는 이 작업의 범위 밖이다 [승용]. 마감·프리즈를 이유로 절차를 줄이지 않는다.

## §2. 새 V/E/H 정의 — 이 절을 오해하면 전부 무너진다

티어를 가르는 질문은 하나다: **"사람 눈에 낙차의 어떤 증거가 보이는가, 그리고 안 보이는 부분은 '왜' 안 보이는가?"**
티어는 위험 지오메트리가 화면에 몇 픽셀 기여했는지 세는 문제가 **아니다.**

**공통 규칙(가장 중요):** VE_raw로 판정된 프레임은 **티어와 무관하게 원시 2층을 모두 기록한다** — ① edge 폴리라인 ② 보이는 '속' 마스크(비어 있어도 됨). 라벨층이 티어에 따라 달라지는 것이 아니다. **라벨은 지금 저장하는 '원시'고, V/E는 나중에 계산되는 '해석'이다.**

| 티어 | 정의 [승용] | G3 확정 후의 의미 |
|---|---|---|
| **V** | 낙차의 '속'이 보인다 — 다음 계단 칸(내려간 면)이 보이거나, 구멍 내부가 기존 YOLO류 탐지기가 잡을 크기로 보인다. "그 크기"는 §7 실험으로 정하며 **이 문서 시점엔 미정** | 원시 속 수치가 채택 경계 이상인 프레임 |
| **E** | edge 라인(땅이 끊기는 선, depression 라인)은 보이지만 그 너머 속은 **시야각 때문에** 안 보인다 | 경계 미만·edge 가시 프레임 |
| **H** | 가드레일·수풀 같은 **외부 가림물** 때문에 안 보인다. 낙차 종류와 무관하게, 가리는 것이 있으면 H. **틈새로 속이 일부 비쳐도 H** | H_cand 중 승용이 스탬프 |
| **NEG** | 낙차가 화면에 안 보인다 = 낙차 없는 장면 | 음성 |

**판정 순서 — 프레임마다, 계산 가능한 형태로:**

1. 씬 기하에서 **edge 인스턴스 후보**를 계산한다: 보행면이 진행거리 `R_run` 안에서 **0.3 m** [문헌·기존 확정] 이상 꺼지는 턱 선. `R_run`은 상수 대장 **필수 등재** — 구 코드의 STEP_RUN 값을 [기존값]으로 이월하되 다른 1값과 민감도 비교를 병기한다. 높이장 격자 해상도도 같은 급의 필수 등재 상수다[기존값 이월 허용]. 각 후보를 프레임에 투영하고 가림 검사로 가시 구간을 구한다.
2. **NEG** = 가시 edge 구간의 총길이 0 **그리고** 보이는 속 픽셀 총합 0.
3. **H_cand** = 시선 검사에서 edge·속의 어느 점이든 **지면·계단·위험 기하가 아닌 프림**(가드레일, 수풀, 집기 등 외부 물체)에 먼저 막히는 경우. 표시 + 가림 프림 경로 기록 + 승용 큐. **보이는 범위의 edge·속 원시 기록은 다른 프레임과 동일하게 남긴다**(그 기록의 라벨 사용 여부는 승용 결재 몫). 명백한 완전 가림도 H_cand로만 적는다 — H의 최종 스탬프는 승용이 찍는다 [승용: H 판정 위임].
   ⚠ **자기가림 함정**: 낙차 바로 앞의 지면(브링크)이 속을 가리는 것은 가림물이 **아니다** — 그것이 E의 정의(시야각)다. 시선을 막은 것이 지면·계단 기하 자신이면 가림으로 세지 않는다. 이걸 틀리면 E 전부가 H_cand로 쏟아진다.
4. 나머지 전부 **VE_raw** — 원시 2층 + §5 수치 기록. V/E 확정은 G3 결재 뒤 CPU 재계산으로 스탬프.

**구 규칙이 왜 죽었나 (경고 — 같은 실수 방지용):**
구 라벨러는 위험 지오메트리의 픽셀 기여를 쟀다: 내부 픽셀 50개 이상 → V, '입술 표본점' 가시율 5% 이상 → E, 둘 다 0 → H. 50과 5%는 실험 근거 없는 상수였고, '입술 표본점'은 사람이 보는 '땅이 끊기는 선'과 다른 물체였다. 결과: **H로 분류된 프레임에 사람 눈으로는 E인 것들이 대량으로 섞였다.** 새 규칙의 "왜 안 보이는가" 질문이 이 실수의 해독제다. 구 규칙의 어떤 상수도 판정에 재사용하지 않는다.

**자기 검산 7문항 — Phase 0 산출물에 자답을 포함하라:**

- Q1. 가드레일 틈으로 구멍이 조금 보인다 → ? (답: H_cand)
- Q2. 선만 보이고 다음 칸은 안 보인다 → ? (답: VE_raw로 원시 기록. 문턱 채택 뒤 E로 확정될 가능성이 높다)
- Q3. 낙차가 프레임 밖에 있다 → ? (답: NEG)
- Q4. edge 라인의 절반만 수풀에 가려졌다 → ? (답: 보이는 구간은 원시 기록 + H_cand 표시. 최종 티어는 §9-❓1 승용 결재)
- Q5. V/E 경계 픽셀 수를 네가 정해도 되는가 → ? (답: 아니오. §3-P1)
- Q6. 계단 앞 지면(브링크)에 가려 다음 칸이 안 보인다 — 가림물인가 → ? (답: 아니오. 자기가림 = E의 정의. H_cand 아님)
- Q7. 창고 렌더 프레임을 계단 corpus(E 라벨 본대)에 넣어도 되는가 → ? (답: 아니오. §7 전용, 별도 manifest — §9-❓6)

## §7. V 문턱 실험 세부 — 창고 A트랙 [승용 결정]

목적: **"기존 YOLO류 탐지기가 잡는 크기"를 베이스라인 논문의 홈그라운드 씬에서 실측**해 V/E 경계의 후보를 만든다. 이 실험은 수치를 '보고'하는 실험이지 '정하는' 실험이 아니다.
이 논문의 최종 역할(비교 baseline vs 파이프라인의 한 단)은 **미정**이다 [승용] — 본 실험은 어느 역할로 가든 필요한 '탐지 한계 실측'이므로 역할 결정과 독립이다.
범위 울타리: **논문 시스템 전체(depth 스트립 검증·LiDAR 융합·회피)는 재현하지 않는다.** YOLO 단의 탐지 한계만 잰다.

**3-1. 환경·씬 실측** (G1 이후 병행 가능)
- `OxyBloom/negativeobstacleavoidandance` 클론. ROS 2 Humble + Gazebo Classic + `realsense_gazebo_plugin` 구동(설치 방식 — 직설치/도커 — 은 자유, 보고서에 기록).
- `large_holed_floor` STL에서 **구멍 개수·치수·깊이 실측** → 상수 대장·§6-8 표.
- RGB+depth 카메라 파이프 검증. **depth 플러그인의 노이즈 설정 확인·기록**(무노이즈/노이즈 모델 — 이탈 통계 해석에 필요). 시점 밴드는 계단과 동일 [기존 확정]: **높이 0.3–2.0 m · 피치 −15°~+5°**.

**3-2. 렌더 계획 → 게이트 G3a ❓**
- `VTH_RENDER_PLAN.md` 상신: 월드 2종(eworld2 · expandedworld) × 구멍별 접근선 **거리 스윕(가까이 '속 보임' → 멀리 '선만 남음' 전이를 덮도록)** × 포즈 수 × **가림 유도 포즈 집합(자연·유도 가림 예상 건수 포함)** × 예상 렌더 비용. 결재 후 렌더.
- 렌더 프레임에 §5 스키마 라벨(`vth_manifest_v1`, domain=warehouse). edge 대조 실측은 계단과 동일하되 (a′) = 바닥 STL의 바닥 높이 단면에서 구멍 경계 윤곽 추출 → 투영 / (b) = depth 불연속.

**3-3. 학습·평가** (G2 이후)
- 모델·레시피: **논문 그대로 [문헌]** — YOLOv8n · COCO 사전학습 · 100 epochs · batch 16 · 증강 사용 · **클래스 1개**(논문 Table 2. 코드의 4개 클래스 명단은 매핑 테이블일 뿐, 학습은 1클래스다) · 전처리는 논문의 **사다리꼴 ROI + 리사이즈** 포함. 논문과 다르게 가는 항목(음성 프레임 포함 여부 등)만 별도로 상수 대장에 기록.
- 학습 라벨: 속 마스크의 최소 외접 박스 — 모집단은 **tier_now=VE_raw이면서 int_area_px > 0**인 프레임(H_cand 제외).
- 분할: **월드 단위** — 학습 eworld2 / 평가 expandedworld (또는 역). ⚠ 월드가 2개뿐이고 바닥·에셋 계열이 같다는 **한계를 보고서에 정직 표기**하고 방향은 §9-❓4로 결재. 참고: 논문 자신의 분할은 한 환경 안 이미지 무작위 70/20/10이므로, 월드 분할은 논문보다 엄격한 쪽이다 [문헌].
- **암기 진단**: 두 월드의 구멍 인스턴스가 기하적으로 동일한지 STL 대조로 인쇄 — 동일하면 "평가 월드의 구멍을 학습에서 이미 봤다"는 한계를 명기하고, 평가 곡선 옆에 **학습 월드 곡선을 병기**해 gap을 인쇄한다(판정 불사용).
- 곡선 모집단: 평가 월드의 **tier_now=VE_raw이면서 int_area_px > 0**인 프레임 전수 (H_cand는 곡선 밖 — 건수·발화 별도 행이며, 아래 **가림축 실험**의 모집단이 된다). 매치 판정 박스 IoU 0.5 [문헌: PASCAL/COCO 관례]. confidence는 도구 기본값 포함 2~3값 병렬 [도구기본값].
- 보고: 탐지율 대 크기 곡선을 **세 축(int_area_px / int_h_px / int_w_px) 각각** + dist_m 병기 + **구멍 물리 치수별 층화 병기**(크기-거리 교락 진단) 인쇄. 탐지율 {0.25, 0.50, 0.75, 0.90} 교차 크기 표(교차 격자는 보고용 — 채택 아님, 상수 대장 [방법]). **int=0 프레임(선만 남은 E 영역)은 GT 박스가 없어 곡선 밖** — 그 프레임들에서의 발화 건수만 별도 행으로 인쇄.
- **참고 병기 (판정 불사용)**: 학습된 가중으로 계단 corpus의 VE_raw 프레임에 추론만 돌려 같은 곡선을 인쇄 — 창고→계단 전이가 어디서 깨지는지 정직 표기 [클로드 제안].
- **가림축 실험 [승용]**: H_cand 프레임에서 **가림 비율(occl_frac — 그 낙차의 edge·속 총량 대비 외부 프림에 막힌 비율)**을 실측하고, 크기 구간을 통제한 상태에서 **탐지율 대 가림 비율** 곡선·표를 인쇄한다. **V/E 경계 채택에는 사용하지 않는다** — 채택 축은 무가림 크기 축 그대로이고, 이 곡선은 "기존 방식이 가림에서 어떻게 무너지는가"의 실측 재료다. 가림 사례는 씬 수정 없이 **가림 유도 포즈**(선반·집기가 카메라와 구멍 사이에 오는 시점)로 확보한다.
- 경계 후보는 **근거를 붙여 제안만** 하고 채택하지 않는다. 원자료 csv 동봉. → G3.

## 부록 A. 용어 최소 사전 (처음 보는 독자용)

- **negative obstacle(낙차)**: 지면보다 꺼진 위험 — 내리막 계단, 구덩이, 도랑. 튀어나온 장애물의 반대.
- **edge 라인**: 땅이 끊기는 선. depression 라인·브레이크 라인과 같은 뜻 — 이후 "edge 라인"으로 통일.
- **grazing angle**: 낮은 시점에서 지면을 스치듯 보는 각. 낙차의 속은 화면에서 세로로 짓눌려 보이고, 멀수록 심하다.
- **브링크(자기가림)**: 낙차 바로 앞 지면 턱. 이것이 속을 가리는 건 시야각 문제(E)지 가림물(H)이 아니다.
- **store raw, bin later**: 원시 수치를 저장하고 구간 판정(V/E 경계)은 나중에 계산으로 스탬프. 기존 확정 원칙.
- **상수 대장(CONST_LEDGER)**: 실행에 쓰인 모든 상수의 값·출처·민감도 기록부. P1의 실무 형태.
- **Gazebo Classic**: ROS 2 Humble 세대의 구형 Gazebo. 창고 트랙이 쓰는 시뮬레이터로, Isaac Sim과 별개 환경.
