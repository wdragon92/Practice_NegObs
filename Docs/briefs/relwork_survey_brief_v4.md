## §0. 승용 요약 (4문장)

1. 조사 질문: **"낙차·계단의 edge 라인만 보이는 상황(E 상황)에서 monocular RGB로 존재를 판정하고 edge를 정밀 인식하는 연구가 있는가 — 있으면 무엇이고, 없으면 가장 가까운 계보는 무엇인가."**
2. 축은 넷: A 계단 검출 / B negative obstacle·drop-off / C 경계(선) 평가 관례 — 채점 허용오차의 문헌 근거 확보 겸용 / D 유사선 혼동·존재 판정 선행.
3. 분담: 공개 원문 수집·비교표 조립은 클로드 코드 — 접근이 막히는 최신·유료 벽 자료는 서지만 남겨 승용에게 이관하고, 승용이 수집해 채팅 클로드에 전달한다 [승용].
4. 산출은 셋: 비교표 · 갭 진술 초안 · 허용오차 후보 기준 목록 — 비교표의 핵심 열은 **"그 논문이 가정한 가시 상태(V형/E형)"**다.

## §1. 배경과 용어 (자립형)

북극성 [승용]: E 상황에서 negative obstacle의 edge 정밀 인식 + 존재 판정 (1단계). 이 조사의 용도 셋 — (a) 신규성 위협 탐지, (b) 평가 허용오차의 문헌 관례 확보(연구 하드라인 P1: 기준은 임의로 정하지 않는다 — 실측·문헌·결재로만), (c) 논문 related work 절의 재료 수집.

**용어 상자 (이 문서만으로 읽히도록):**

- **negative obstacle(낙차)** = 지면보다 꺼진 위험(내리막 계단·구덩이·도랑).
- **edge 라인** = 땅이 끊기는 선(depression 라인).
- **V형 가정** = 낙차·계단의 '속'(내부 면, 디딤판들)이 화면에 보이는 상태를 전제한 연구.
- **E형 가정** = 속은 안 보이고 **edge 라인만 보이는** 상태를 전제하거나 그 상황을 명시적으로 다룬 연구. 우리의 표적.

## §2. 조사 축, 질문, 시드, 검색어

### 축 A — 계단 검출
질문: 각 연구가 **어느 가시 상태(V형/E형)**를 가정하고 무엇을 출력하는가? 내리막 접근(디딤판 비가시, 선만 보임)을 명시적으로 다룬 것이 있는가? 평가 지표와 허용오차 정의는?
시드 [문헌·2026-08-27 채팅 검색에서 실물 확인]:
- StairNet — 단안 RGB 계단 라인 end-to-end 검출 (Sci Rep 2022, s41598-022-20667-w)
- RGB-D 계단 검출 + 기하 파라미터 추정 (Sensors 2023, DOI 10.3390/s23042175 — 내리막에서 오차 증가 보고)
- StairNetV3 — depth-aware (arXiv 2308.06715)
- 구세대: YOLO/RCNN으로 계단 영역을 잡고 고전 기법으로 선 추출하는 2단계 계열 · 이미지 수준 "계단 있음/오르막·내리막" 분류(픽셀 위치 없음)
검색어 시드: `stair detection deep learning` · `stair line detection` · `descending stair detection` · `stair edge detection RGB` · `stair detection visually impaired`

### 축 B — negative obstacle·drop-off
질문: RGB 단독으로 **edge 자체를 출력**하는 것이 있는가? drop-off의 존재를 어느 증거로 판정하는가?
시드: Heckman et al. 2007 계보(기하 — 기존 지도의 직계) · Esuga-Mopah 2026 [베이스라인] · OccluRoads [위협 후보] · Singhani 2019 — 단안 RGB freespace segmentation, drop-off·내리막 계단 포함 (arXiv 1902.00842) · chaytonmin 서베이 표(§1.2) · 청소로봇/휠체어/시각장애 보조의 drop-off 감지 관행(주로 하향 센서 — 대비용).
검색어 시드: `negative obstacle detection` · `drop-off detection robot` · `negative obstacle RGB camera` · `ditch detection autonomous` · `cliff sensor vision`

### 축 C — 경계(선) 평가 관례
질문: 선형 예측의 채점에서 허용오차를 **어떻게 정의하고 얼마로 두는가?** (원문 정의·수치 그대로 확보 — 채점 허용오차의 채택은 **모델 단계 차기 브리프** 소관이며, 이 목록은 그때의 인용 근거다)
시드: 경계 검출 벤치마크의 boundary F-measure 계열 — 허용오차를 이미지 크기 비율로 두는 관례로 알려져 있으나 **정확한 정의·수치는 원문 확인 필수** · 차선 검출 등 선형 구조 평가 관례.
검색어 시드: `boundary detection evaluation F-measure` · `BSDS500 boundary benchmark` · `edge detection evaluation tolerance` · `lane detection evaluation metric`

### 축 D — 유사선 혼동·존재 판정 선행
질문: "선은 보이는데 그 선이 무엇인지 / 그 너머가 무엇인지"를 가른 선행이 있는가?
시드: 계단 선 vs 횡단보도 줄무늬 구분 선행 — depth 특징 사용, StairNetV3(arXiv 2308.06715) 서론의 해당 인용(원문 표기 [27][28])에서 출발해 추적.
검색어 시드: `stair crosswalk confusion detection` · `pedestrian crossing stair classification`
주의: 음성 세트 구축은 현재 **보류** [승용] — 여기서는 문헌만 적재하고 설계로 넘어가지 않는다.

## §4. 포함·제외 기준과 기록 스키마

**선적재 규칙**: 기존 조사분(§1.2의 문헌 지도·chaytonmin 표)을 먼저 비교표에 적재하고 `기존` 태그를 단다. **이미 조사된 논문의 재조사 금지** — 신규 조사는 그 위에 쌓는다.
**기억-작성 금지**: 비교표의 내용 열(가시 상태·출력·지표·수치)은 **실제로 연 원문·초록에서만** 채운다. 열지 못한 논문은 서지·링크·`승용 이관` 태그만 남기고 내용 열은 공란으로 둔다.

포함: 계단/낙차/drop-off의 시각 인식 · 경계(선) 평가 관례를 정의한 벤치마크 · edge-only 존재 판정 인접 문제.
제외: 순수 제어·기구학 · 인식 주장 없는 지도 작성 전용 · 접촉/초음파 단독 센서.

비교표(`RELWORK_TABLE.md`) 열:
논문 · 연도 · 입력(RGB/RGB-D/기타) · **가정한 가시 상태 {V형 / E형 / 무관}** (§1 용어 상자 기준) · 출력 형태(박스/선/영역/분류) · 평가 지표와 허용오차(원문 수치) · 데이터(실사/합성) · 내리막 명시 여부 · 우리와의 관계 {위협 / 베이스라인 후보 / 평가 관례 / 배경} · 출처 링크 · 수집 경로 태그 {기존 / 코드 / 승용}.
