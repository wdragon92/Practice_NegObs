## §2. 렌더 중에 새로 잡은 결함 3건

### 2.1 D팔 프림 하한 — W0의 빈-스테이지 가드가 D팔에 맞지 않는다 (스모크가 막았다)

W0 러너의 가드는 `n_prims >= 50`이었다(C1-probe의 빈 SdfPath 사고 대비). W0의 최저치가
sceneN2/`Bdress` 60이었기 때문인데, 그건 **위험 + 단서 1개만** 끈 팔이다. D팔은 위험과 6키를
동시에 끄므로 정상 씬도 훨씬 작아진다.

씬당 1컷 스모크가 **scene02(28) · scene08(49)** 를 "빈 스테이지"로 오격리했다. 실측 확인:
scene02는 높이맵 **103,041/103,041 finite** · RGB std 27.9 · 고유색 27,317 — **정상 렌더**다.

⇒ 가드를 `n_prims < 5 ∨ n_finite < 1000 ∨ RGB std < 1.0`으로 재교정했다. 빈 스테이지의
서명은 "프림이 적다"가 아니라 **"프림이 거의 0 ∧ 측정된 지면이 없음 ∧ 이미지가 평평함"** 이다.
재교정 후 **스모크 22/22 통과**. 이 22컷이 아니었다면 두 씬을 잘못 격리한 채 배치를 돌렸다.

### 2.3 계기(instrument) — 융합 높이맵이 D팔에도 필요하다

`labeler.load_heightmap`은 `heightmap_fused.npy`가 있으면 **그것이 이긴다**. 정본 코퍼스는
토글이 프림을 **지우지 않고 보이지 않게만** 만드는 씬의 off팔에 이 사이드카를 얹어 두었다
(`fuse_heightmap.py` 헤더: *"the AABB ray … reads … a prim that the toggle only made INVISIBLE
rather than deleted … the actual reason scene07/08 differenced to zero"*).
해당 씬 = **scene02 · 07 · 08 · 12 · 16**.

**D팔도 off팔이라 같은 병에 걸린다.** 스모크 1컷으로 이미 드러났다:

```
scene08   z_A [-4.501, 0.300]  ·  z_D(AABB) [-4.501, 0.006]   →  fp(z_off = D)     =      0
          z_구off(fused) [-0.001, 0.006]                       →  fp(z_off = 구off) = 66,547
```

이 상태로 재판정하면 A와 Bx가 **둘 다 `cells_raw = 0`** 이 되어 Δ = 0 → **전부 "장식"** 이라는
거짓 판정이 나온다. **계기를 맞추는 것이 판정보다 먼저다.**

**채택 규칙(기계·`w1d_fuse.py`)**: *정본 구off팔이 그 씬에서 융합을 쓰면 D도 융합을 쓴다.*
D는 구off를 대체하는 z_off이므로 계기를 코퍼스와 맞춘다 — `fuse_heightmap.py`의 scene12 교훈이

원칙**대로 base 밴드 융합본을 복사한다(복사 전 AABB sha256 동일 확인 = "지오메트리 동일" 실증).

## §4. VG-02 — D팔은 전 칸 음성인가

### 4.1 왜 두 갈래로 재는가 (측정 설계)

라벨러 발자국은 `fp = {z_off − z_on ≥ 0.3}`이다. D팔의 정직한 z_off는 "D의 단서 구성(=없음) +
낙차만 있는 면", 즉 **B팔**이고 B는 아직 없다. 그래서:

- **(ㄱ) 구조적 진술 = 계획의 VG-02 문면.** 생산 짝 (B,D)에서 D는 off팔이므로 `polar_gt`는
  **구성상** 올-제로이고 `tier = "off"`다(`labeler.label_scene`의 `arm=="off"` 분기).
  실측으로도 확인했다 — `w1d_base.json`의 off팔 528프레임 **양성 0/528**. 이건 측정이 아니라 구성이다.
- **(ㄴ) 실질 결함 사냥 = 본 보고서의 판정.** 남는 질문은 "위험 토글이 실제로 낙차를 지웠는가"뿐이다.

**초안이 틀렸던 자리를 적어 둔다.** 처음에는 `resid = fp_corpus ∩ {z_구off − z_D ≥ 0.3}`으로 재려
했다. scene04에서 288셀이 걸렸는데 그 셀들의 값은 `z_D = 0.000`(평평한 메운 지면) ·
`z_구off ∈ [0.722, 0.971]` · `z_A ∈ [−0.700, 0.426]`이었다 — **구off에만 서 있는 자유결속 소품**이
낙차처럼 보인 것이다. 소품은 밑 지면에 재앵커되므로 **낙차 발자국 안에도 설 수 있다**(초안이
"단서는 발자국 밖에서만 움직인다"고 가정한 바로 그 자리). 구off를 참조로 쓰는 한 이 오염은
제거되지 않는다.

**D팔에는 단서가 하나도 없다.** 그러므로 D의 높이맵은 그 자체가 맨 지형이고, 질문이 D 안에서 닫힌다:

```
ring   = dilate(fp_corpus, 1.0 m) − fp_corpus     (코퍼스 발자국 둘레 = D의 보행면)
walk_z = median(z_D[ring])
resid  = fp_corpus ∩ {walk_z − z_D ≥ 0.3}          (D 안의 함몰)
```

단서가 없으니 **단서 오염이 원리적으로 불가능**하다.

### 4.2 판정 — **통과**

| 지표 | 값 |
|---|---|
| 씬×밴드 | **38 / 38 통과** |
| 코퍼스 낙차 발자국 합 | 1,658,351 셀 |
| **D 안 함몰 잔차** | **0 셀** |
| 프레임 단위(정본 `polar_cells`로 resid를 D 각 컷에 투영, 스텝게이트 없이 = 보수적) | **양성 프레임 0 / 912** |

**어떤 칸도 양성이 아니다 ⇒ D팔은 전 칸 음성이고 씬 결함으로 격리할 대상이 없다.**

### 4.3 구off 참조 스캔(`w1d_base.json`) — 오염이 어디서 나는지 실측

D팔을 **on팔로 두고 구off를 z_off로** 라벨링한 스캔(계획이 요구한 "라벨러 파이프라인" 산출):

- sceneN4의 raw `cells_raw` = **1,376** — W0 §3이 지목한 지문(**Δ풋프린트 = Δ높이맵 셀 수 정확 일치**,
  W0 표의 sceneN4 V: +1,376 = 1,376)과 **같은 수**다. 즉 드레싱 제거가 만든 인공물이며 낙차가 아니다.

- 나머지 21씬은 raw `cells_raw`가 크더라도(scene02 9,240 · sceneC4 8,475 · sceneC1 4,613 …)
  라벨러의 **D10 스텝게이트가 전부 걷어낸다** — `cells_kept_max = 0`. 걸어 들어갈 보행 경계가

⇒ **밴드 라운드(h·e·e2)에는 이 스캔을 돌리지 않았다.** 그 밴드의 정본 구off가
"평 라운드 + g7fixM 결함 씬 3개"의 하이브리드라 완전한 트리가 없고, 평 라운드만 쓰면

**① 레버 0인 3씬** — `scene03`(72컷) · `scene04`(72컷) · `scene10`(24컷) = **168컷**.

같은 시드로 찍으면 **바이트 동일한 168컷**을 새로 만드는 셈이다. 셋 중 하나를 렌더 전에 정해야 한다:
(a) A팔 프레임을 그 씬의 B팔로 **재활용**하고 대장에 "cue 대비 0"으로 등재(168컷 · ≈0.27 GPU-h 절약),
(b) 계획대로 찍고 중복을 회계에 남긴다.
**권고: (a).** `w0_rimpact.py`의 `removable()`은 이미 이 씬들을 "B팔에서도 단서 있음(x=1)"으로
계산하므로 §7의 r 값은 **어느 쪽을 택해도 불변**이다.
