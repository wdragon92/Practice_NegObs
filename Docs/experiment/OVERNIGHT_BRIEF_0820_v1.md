## 0. 너의 역할과 프로젝트 4줄

- 너는 **실행 에이전트**다. 설계 변경·재해석 금지. 모호하면 본 브리프의 기본값을 따르고 `DECISIONS.md`에 기록한다. 설계 논의는 주간의 Claude AI, **결정권자는 승용**이다.
- 프로젝트: 단안 RGB 한 장으로, **낙차(negative obstacle) 픽셀이 화면에 전혀 없어도(H 티어)** 전방 낙차 위험을 폴라 그리드로 예측할 수 있음을 보이는 논문 (제36회 AISP).
- 격자 `PROVISIONAL-GRID-V1`: 5섹터 × 4밴드 [0,2)/[2,5)/[5,8)/[8,12) m = **20칸**. 위험 정의 = 깊이 ≥0.3 m 낙차.
- 티어(프레임 속성): V = 낙차 내부면 픽셀 가시 / E = 림(개구 경계)만 가시 / **H = 낙차 기여 픽셀 0, 맥락 단서만**. 지표: 프레임 recall(정답 칸이 하나라도 켜지면 검출) · FA(낙차-OFF 프레임 발화율) · 트윈 Δ. τ_op = 0.5(YOLO 행만 0.25). 시드 {42, 43, 44}.

### P1 — CPU 트랙 (GPU 대기와 **병행**, 지금 즉시 시작)

**B1. Depth 하락 가설 검증** (DAYRUN ⑤(4)·⑥-4) — 기존 metrics/예측 산출물로 **밴드별 recall** 재집계.
- 수용: Depth의 band2 vs 3a vs 3b recall + RGB 동일 분해 + "확장 H셋의 원거리성 때문" 가설의 지지/기각 판정 한 단락.

**B2. 진단 3종의 v2판** — v1 진단(`narrative/diag_v1/DIAG_V1.md`)과 **같은 축·같은 양식**으로 나란히 비교 가능하게.
- (i) 셀별 train 사전확률 vs off-FA **Spearman ρ** — 모델×시드별. v1의 ρ = +0.963 대비, bias 초기화 + 8 m 분할이 결합을 끊었는지가 발전 서사 그림의 핵심이다.
- (ii) 밴드별 트윈 Δ 분해. (iii) 오경보의 씬 기여 분해(C2 재점검 포함).
- 수용: `DIAG_V2.md` + 그림.

**B3. recall–FA 시드 산점도 + τ 곡선** (DAYRUN ⑤(1) 제안 실행)
- 3모델 × 3시드 점(H recall vs FA). 저장된 확률 덤프가 있으면 τ ∈ [0.05, 0.95] 티어별 recall/FA 곡선 추가 — τ_op 확정 결재의 근거 자료.
- 폴백: 덤프가 없으면 GPU 큐 뒤에 test 추론 1패스를 붙여 확보(시드당 수 분). 그것도 안 되면 산점도만.

**B4. 걸침·점유 진단** (승용 제기 사항의 수치화)
- (i) 위험 인스턴스별 양성 칸 집합이 **섹터 경계/밴드 경계(8 m 신설 경계 포함)에 걸치는 비율** — DAYRUN ②ⓒ의 band3 62.7%를 전 경계로 일반화.
- (ii) RGB v2 시드별 **miss 프레임 × 걸침 여부 교차표** — "걸친 케이스를 모델이 더 놓치는가"에 대한 직접 답.
- (iii) 양성 칸 내 **위험 점유 면적비 분포**(하이트맵 차분 기반)와 그 여집합 **과차단율**(칸은 켜졌지만 실제로는 통행 가능한 면적 비율, 밴드별) — hole 타입 논의·통행성 비용·한계 절의 기초 통계.
- 수용: `STRADDLE_REPORT.md` (표 3개 + 해석 각 한 단락).

**B5. 트윈 층화 검산 (중요)** — D20 페어링 허용오차(0.15 m)로 살린 쌍은 **입력 자체가 미세하게 다르다**(ground_z 이동). H 티어 트윈 Δ가 이 쌍들 때문에 부풀 가능성 검산.
- 절차: 트윈 Δ를 "카메라·ground_z **완전 동일** 쌍"과 "허용오차 내 이동 쌍"으로 층화해 모델·시드별 재산출(CPU, 기존 예측 재사용).
- 수용: 층화 표 + **완전 동일 쌍만의 H Δ와 CI**. 헤드라인 인과 주장("낙차 픽셀이 어느 팔에도 없는데 반응이 떨어진다")의 방어선이므로 결과가 어느 쪽이든 그대로 기록한다.

**B6. 잔가지** — 최종 val(scene08·20·D3)에서 "1A칸 양성 0" 플래그 재확인(DAYRUN ⑤(8)ⓐ) / `infer_photo.py` 사용 3줄을 dayrun README에 링크.

### P2 — 스위치 트랙

**C1. hole 타입 제로샷 프로브** (RUN_HOLE_PROBE = YES일 때)
- 목적: 낙차 유형 일반화의 첫 데이터. **훈련 편입 절대 금지 — 평가 전용.**
- 절차: Isaac 프리미티브로 hole 씬 2–3개 자작(개구 사방이 지면으로 둘러싸인 국소 함몰, 깊이 ≥0.3 m, 개구 크기 0.5–1.5 m급). 구도: ① 근거리 노출 hole(V/E — band1이 최약 밴드이므로 근거리 1구도 필수) ② 중거리 hole — **경로 한쪽에 치우쳐 인접 섹터가 비도록 배치(통로 보존 구도)**: 정답 섹터 발화와 함께 **인접 빈 섹터의 오발화율**을 별도 보고 ③ **가림막 뒤 hole(H 성립 구도) ≥1**. 트윈 규약 엄수(hazard on/off, seed·카메라 포즈 바이트 동일). 조명 3 × 캠 8 → 96–144프레임 → v2 라벨러로 라벨 + 티어 분류 → **frozen v2 체크포인트 9개(3모델 × 3시드) zero-shot 평가** + 트윈 Δ.
- 격리: `experiments/probe_holes_0820/` 전용. 본 코퍼스·본 표 불가침.
- 수용: 티어 분포표 + zero-shot recall/FA/Δ 표 + 대표 패널 4장. 렌더까지만 되고 평가가 실패해도, 산출물과 원인이 기록되면 Tier3 성립.
- 폴백: 씬 제작 스모크(1프레임)가 45분 넘게 막히면 중단·기록.

**C2. 외관보존 off팔 대조군** (RUN_DRESSING_CONTROL = YES — ④-7 승인 완료 상태로 실행)
- 목적: "장식 반응" 캐비앗(N3 Δ 0.252 · C2 환각)의 최소 실증 대조군.
- 절차: sceneC2·N3의 off팔을 **낙차만 제거·장식(낙엽 둔덕·난간 등) 유지**로 재렌더 — 별도 디렉토리, 기존 팔 무수정. FA·트윈 Δ를 "구 off / 신 off" **병기**. 평가는 **RGB v2 3시드 필수**, 여력 시 Depth·B2까지 확장.
- 게이트: on팔 해시 불변 + 카메라 포즈 바이트 동일 확인 통과 후에만 평가.
- 수용: 병기 표 + 해석 한 단락.
- 폴백: 씬 토글 수정·게이트 통과가 60분을 넘기면 중단·원인 기록 후 다음 주간 사이클로 이월.

## 5. 우선순위 · 시간표

- 병렬 원칙: CPU 트랙(B1–B6)은 **즉시** 시작, GPU 트랙은 해제 후 **A1 → A2 → C2 → C1** 순차. C2를 C1보다 앞에 두는 이유: 비용이 작고(씬당 ~15분) 헤드라인 인과 주장 방어라는 정보 가치가 커서, 시간이 모자라면 탐색 트랙(C1)이 자연히 잘리게 하는 배치다.
