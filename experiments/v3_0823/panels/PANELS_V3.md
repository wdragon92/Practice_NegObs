## 4. `fusion_headroom.png` — 융합 여유 · 무중첩 (216 KB · 1789×1022)

**GT 표기**: **교정 GT**(`logs/fa_census_tables_v2corr.json` → `t4_overlap`).
**OFF층 4개 항목은 구 GT(`logs/fa_census_tables.json`)와 완전 동일**함을 드라이버가 실행 시점에 대조합니다
(`same_off == True`). 즉 이 패널의 좌·우 수치는 **어느 GT를 쓰든 같습니다.**

**무엇이 보이나** — 집합 단위 = **시드-다수결 (frame, cell)**(3시드 중 ≥2 발화):

| 항목 | 값 |
|---|---|
| \|rgb\| · \|depth\| · \|b2\| | 269 · 42 · 93칸 |
| **rgb ∩ depth** | **0칸** (Jaccard 0.000) |
| rgb ∩ b2 · depth ∩ b2 | 40 · 2칸 |
| **3모델 동시** | **0칸** |
| 합집합 362칸의 구성 | 정확히 1모델만 **320 (88.4 %)** · 정확히 2모델 42 (11.6 %) · 3모델 **0 (0.0 %)** |

**읽는 법**: 3모델 `AND`(합의) 게이팅을 걸면 **off팔 FA가 원리적으로 전멸**하고,
2모델로 완화해도 **42칸(11.6 %)만 잔존**합니다.

> **⚠ 이것은 FA 상한이지 성능 보장이 아닙니다.** 같은 비중첩이 recall에도 적용되면 합의 게이팅은
> **검출도 함께 죽입니다.** 센서스가 확정한 것은 **분자(FA) 쪽 여유가 실측으로 매우 크다**는 것까지이며,
> 실제 이득은 **recall 쪽 중첩을 같은 방식으로 재야** 확정됩니다
> (`weekend_0823/fusion/` 의 `fused_or`/`fused_max` 런이 이미 있으므로 동일 코드로 가능 — 다음 저비용 작업).
> 이 경고문은 패널 상단에 붉은 글씨로 **인쇄되어 있습니다.**

**모식도 고지**: 세 원의 **면적은 칸 수에 비례**(반지름 ∝ √n)하지만, **겹침 면적은 비례하지 않습니다.**
`rgb∩depth = 0` 과 `rgb∩b2 = 40` 을 동시에 면적 정확히 그리는 벤 다이어그램은 존재하지 않으므로,
교집합 수치는 **전부 숫자로 병기**했고 제목에 "모식도"를 명시했습니다.

**참고(패널 좌하단)**: ON_NEG층은 겹칩니다 — 3모델 동시 **37/707칸 (5.2 %)**,
구 GT **50/863 (5.8 %)** 에서 방향 유지. 즉 **무중첩은 OFF층 고유 현상**입니다.
