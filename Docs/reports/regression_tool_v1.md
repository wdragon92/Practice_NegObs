## 0. 왜 만들었나

같은 회귀가 4번 재발했다.

> scene19 d5 암흑 · scene17 성토 매몰 · scene05 화단 매몰 · scene19 skyline 접선 차폐

자체를 오진한다. v5·v6 두 라운드의 재조준 주석은 손계산으로 "통과"를 선언했지만

남겼다. 이 도구가 그 처방의 자동 집행자다.

## 1. 설계의 단 하나의 전제 — 전역 톤 정규화

곧 오는 라운드는 **재질 교체·정점 변위·모서리 베벨·건물 층간 띠**가 전 씬에 걸린다.
즉 **모든 픽셀이 정당하게 바뀐다.** 픽셀을 그냥 빼면 33씬 400여 컷이 전부 경보가
되고, 그 순간 도구는 버려진다.

그래서 구조 비교는 전부 **백분위 매칭으로 전역 톤을 제거한 뒤**에 한다
(신규 이미지의 휘도 분포를 이전 이미지 분포에 33분위로 사상).

실측 검증 — 렌더 모드를 통째로 바꾼 페어(scene07 `v8_rt` → `v8_pt`):

| | 정규화 전 | 정규화 후 |
|---|---|---|
| 8 LSB 넘게 바뀐 픽셀 | 3.8 ~ 55.6 % | — |
| 16×9 블록 이동률 | — | **0.0 % (전 14컷)** |
| 최종 판정 | — | **FAIL 0 · WARN 0** |

RT→PT 라는 최대 규모의 룩 변화를 전량 흡수했다. 이 정규화가 없으면 아래 어떤
임계값도 의미가 없다.

같은 이유로 grazing 지표는 지면대를 **박스 블러로 거시화한 뒤** 잰다. 원본
그래디언트를 그대로 쓰면 정점 변위·디테일 노멀이 만드는 미세 텍스처만으로
지표가 **×8.72** 튄다(scene07 `v8_pt`→`final_pt`, h0.3_d5). 거시화하면 같은 컷이
**×0.88** 로 잠잠해진다 — 낙차 노출은 수십 픽셀 규모의 거시 구조지 그레인이 아니다.

## 2. 검사 8종 — 판정 기준과 근거

임계값은 전부 스크립트 상단 상수 블록에 근거 주석과 함께 모아 두었다.
근거는 세 갈래다.

- **(a) 감독 판정문 실측** — `judge_v7_rt_A.md`, `judge_v8_rt.md` 는 프리셋 9컷을
  `mean / dark<25 / 255 클리핑` 으로 전수 측광했다. 본 도구는 **같은 정의**를 쓴다.
- **(b) 대조군 실측** — 회귀가 없어야 정상인 페어들의 잡음 상한.

### 이월 결함은 강등한다

DARK·BLOWN·WHITE 가 **이전 라운드에도 같은 정도로 있었으면 회귀가 아니다.**
그대로 두면 원래 어두운 씬(scene06 나선 내부 mean 2.7 · scene13 지하 21.4 ·
scene15 좁은 골목 18.9 · sceneD4 터널 12.9~22.7 — 전부 합격 33씬 안이다)이
매 라운드 같은 경보를 쏟아내 표를 못 읽게 만든다.

→ 이월 + 변화 없음 = **INFO 로 강등**, 총평 하단에 `이월 결함` 요약으로 따로 집계.
악화된 경우만 등급을 유지한다.

## 3. GRAZE — 무엇을 근거로 "의심"하는가

h0.3 로봇 시점은 판정 1순위다. 여기서 낙차는 **보이면 안 된다**. 완전 자동
판정은 불가하므로 다음 **근사**만 쓴다.

> 숨어 있던 낙차가 드러나면 지면대에 **거시 구조가 늘고**, 반대로 신설 기하가
> 낙차를 덮어 버리면 **줄어든다.**

지면대 = 프레임 하단 55 %. 세 지표 전부 **전역 톤 정규화 후** 측정한다.

| 지표 | 정의 | 대조군 밴드 | WARN | 강 |
|---|---|---|---|---|
| ① 거시 구조량 | 지면대를 9×25 박스 블러로 거시화한 뒤 세로 그래디언트 평균의 **비율** | 0.94 ~ 1.05 (미세 텍스처만 크게 바뀐 라운드도 0.88~1.17) | 밖 [0.72, 1.40] | 밖 [0.50, 2.00] |
| ② 수평 단차 행 | 행평균 휘도의 단차 > 4 인 행의 비율(= 단코·낙차선 밀도) | \|Δ\| ≤ 1.7 pp | \|Δ\| > 5 pp | > 15 pp |
| ③ 최강 단차 위치 | 최대 단차가 나는 행의 상대 위치 | \|Δ\| ≤ 0.01 (거의 완전 고정) | \|Δ\| > 0.12 | — |

**2개 이상 이탈해야 플래그를 올린다.** 방향까지 알려 준다 —
증가면 "숨어 있어야 할 낙차가 드러났을 가능성", 감소면 "낙차가 과도하게
은폐·매몰됐을 가능성". 판정문에는 항상 **"육안 확인 필요(자동 확정 불가)"** 를 붙인다.

대상 뷰는 이름 규약(`preset_h0.3_*`, `grazing_*`)으로 고른다. manifest 의 eye z 는
**월드 절대 z** 라 지면이 하강하는 씬에서 로봇 눈높이의 지표가 되지 못한다
(scene07 `side_slope` 의 eye z 는 −2.67).

**정직한 한계**: 가용 데이터에 "grazing 은닉이 깨진" 라벨된 양성 사례가 없다.
따라서 검증된 것은 **오탐률뿐**(대조군 84컷에서 0건). 검출력은 미검증이다.

### 4.4 전 33씬 실행 성능

`look_check/scene*` 33씬 478컷을 **23 초**(8 프로세스, GPU 없음)에 처리한다.
전 33씬 PT 라운드 렌더가 약 11 분(`realism_phase1.md` §3.3)이므로 검사 비용은
렌더의 **3.5 %** 다. 매 라운드 무조건 돌려도 된다.

### 4.5 임계값이 실제로 유용한가 — 결론

- **OCCL 은 거의 무조건 믿어도 된다.** 대조군(0.67 %)과 실회귀(8.2 %+) 사이가
  12배라 임계 위치에 둔감하다. 교훈이 지목한 "카메라를 삼키는 회귀" 를
  정확히 겨냥한다.
- **FRAME 은 가장 민감하고 가장 시끄럽다.** 톤 정규화 덕에 룩 변경에는
  안 반응하지만, 기하가 조금만 움직여도 반응한다. 룩 레이어만 거는 이번
  라운드에서는 이게 정확히 원하는 감도다. 반대로 **씬 재설계 라운드에는 쓰지 말 것**
  (v7/v8→final_pt 처럼 씬을 갈아엎은 페어에서는 FRAME 이 186컷을 잡는다 —
  전부 진성이지만 정보가 없다).
- **DARK/BLOWN 절대치는 이월 강등 없이는 못 쓴다.** §2 참조.
- **WHITE 절대치는 신뢰하지 말 것.** §5-3 참조.

## 5. 잡을 수 없는 회귀 — 사람이 계속 봐야 하는 것

1. **알베도·재질 규약 위반** (브리프 §A-1/2: 수관 알베도 대역, 잔디 tint).
   렌더 픽셀은 알베도가 아니다. 정오광+ACES 아래에서 알베도 0.5 콘크리트가
   픽셀 0.85 로 나온다. 재질값 감사는 **USD/코드 쪽**에서 해야 한다.
2. **공동을 지면 평면이 덮었는가** (§A-3). 위에서 덮인 피트는 그냥 "평평한 바닥"
   으로 보이며, 이미지상 아무 이상 신호를 내지 않는다. 기하 자기검증
   (`scene08 _solid_at` / `scene19 _frame_scan` 패턴) 의 영역이다.
3. **Z-파이팅**(§A-8). 서브픽셀 깜빡임이라 정지 프레임 통계로는 안 잡힌다.
4. **지평선 폐쇄 실패**(§A-4). "허공이 보인다" 는 의미론적 판정이다. 하늘 면적
   급증으로 간접 추정은 되지만 오탐이 많아 넣지 않았다.
5. **낙차 은닉의 참값**. GRAZE 는 어디까지나 의심 플래그다. h0.3 에서 낙차가
   실제로 보이는지는 사람이 봐야 한다 — 그래서 판정문에 "육안 확인 필요"를 박아 뒀다.
6. **사실성 자체**. flat%·slope·채도는 본 도구의 관심사가 아니다.
   `scripts/imgstats.py` 를 병행할 것. (`realism_phase1.md` §2.5 의 경고 —
   저수준 통계는 명백한 시각 차이도 못 잡는다 — 는 여전히 유효하다.)
7. **USD 프림명 규약·`sc.*` 첫 인자·subdivisionScheme 미저작**(§A-5/6, §2.6).
   전부 코드 감사 항목이다.

한 줄로: **이 도구는 "깨졌다"를 잡지 "좋다"를 판정하지 않는다.**
그리고 §4.3 이 보여 주듯 **판정문의 육안 A/B 를 대체하지 않고, 봐야 할 컷의
우선순위를 매겨 줄 뿐이다.**

## 6. 사용법

```bash
# 단일 씬 A/B
python scripts/regression_check.py --before look_check/scene07/p2g2_off \
                                   --after  look_check/scene07/p2g2_on

# 전 33씬 (감독 상시 명령 — §7)
python scripts/regression_check.py --scenes 'look_check/scene*' \
    --before-round w2c_g2,w2_pilot,r2b_on,wall,facade,r2_on --after-round <신규라운드> \
    --fail-only --json Docs/reports/regr_<신규라운드>.json

# 씬마다 라운드가 다르면 목록 파일 (씬경로 <TAB> 이전 <TAB> 이후, # 주석 허용)
python scripts/regression_check.py --list rounds.tsv
```

- `--before-round` / `--after-round` 는 **쉼표 폴백**이다. 먼저 존재하는 폴더를 쓴다.
- **[W2-D 정정] 기준선 사슬.** 위 사슬은 `final_pt_r2,final_pt,ctx2_pt,ctx2` 를 대체한다.
  `final_pt`·`final_pt_r2` 는 07-30 `look_check` 정리에서 **삭제**됐고, 남은 사슬은
  배치1에서만 `ctx2_pt,ctx2` 로 풀리고 **본편 21씬에서는 아무 폴더로도 풀리지 않아**
  기준선 없이 비교하는 상태였다(`look_check/README.md` §4). 상시 기준선은
  **`r2_on`** 이며(`graze_recalibration_v1.md` §9), 그 앞에 **이후 판정된 라운드를
  최신 순으로** 붙인 것이 위 사슬이다 — 씬마다 **자기 최신 판정 라운드**로 풀린다:
  `sceneC2 → w2c_g2` · `scene13/15/N5 → w2_pilot` · `sceneC1 → r2b_on` ·
  `sceneN4 → wall` · `scene05 → facade` · 나머지 전부 `→ r2_on`.
  새 라운드가 판정되면 **사슬 머리에 추가**한다(꼬리에 붙이면 안 된다).
- `--only h0.3,graz` — 뷰 이름 부분일치 필터(판정 1순위만 빠르게 볼 때).
- `--fail-only` — FAIL/WARN 컷만 출력.
- `--json out.json` — 전 지표·전 사유가 담긴 기계 판독본. 표에 안 보이는 INFO 도 전량.
- **종료코드**: FAIL 이 하나라도 있으면 1. 배치 스크립트에서 게이트로 걸 수 있다.

출력은 `씬 × 뷰` 표(판정 · mean · dark% · 신규암부 · 덩어리 · 블록이동 · 사유) +
`이월 결함 요약` + `우선순위 목록`(FAIL→WARN) + `씬 우선순위` 순이다.
